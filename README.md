# DPmetaApp

Одно Android-приложение автора — единая среда его экосистемы: проекты и
ход разработки, сайт `dpsmpx.com`, аккаунты и сессии Claude, статистика
и графики. Системы активных репозиториев становятся подсистемами
приложения, а не внешними программами (D-27); до своего переноса о
проекте прав его репозиторий.

**Всё в одном (D-28).** Первая подсистема уже здесь: DP_AI_Orcestrator —
подсистема «AI», каталог [`dpai/`](dpai/README.md), с историей git. Её
ядро (`Outcome`, `Diagnostic`, `Clock`, `Secret`, JSON, журнал событий,
хранилище, одобрения) — ядро всего приложения, а её Android-оболочка —
первая форма приложения. Прежний репозиторий DP_AI_Orcestrator
заморожен: работа идёт только здесь.

## Что приложение умеет сейчас

Сейчас в приложении работает подсистема «AI» — пульт сессий Claude Code
на устройствах автора (подробно — [`dpai/README.md`](dpai/README.md)):

- **Где идёт работа.** Execution targets: Termux на этом же телефоне
  (приложение само запускает его `sshd`), ПК с Linux или Windows по SSH;
  ход Claude может идти на телефоне, а рабочее дерево, Git и проверка —
  на ПК (`DP_AI_Orcestrator:D-50`). Вход в Claude — только через форму
  Claude в слоте аккаунта, ключей API нет (`DP_AI_Orcestrator:D-29`).
- **Задачи.** Создание с приоритетом, классом, моделью, усилием,
  пределом стоимости хода, зависимостями и областью; пауза, продолжение,
  отмена, повтор, ответ заблокированной, ручная проверка, исключение,
  архив. Каждое действие — команда с ключом: повтор нажатия не делает
  второго действия (`DP_AI_Orcestrator:D-42`).
- **Сессии.** Что модель делает сейчас (инструмент, цель, текст хода),
  остановка хода, запрос в ту же сессию с выбором модели и усилия,
  свежая сессия с handoff; итоговые сообщения ходов целиком.
- **Git и проверка.** Рабочее дерево и ветка на задачу, проверка
  результата («готово» модели — не завершение), изменения задачи — что
  принесёт слияние; слияние в ветку интеграции — только по ответу
  человека.
- **Расход и лимиты.** Загрузка окон подписки (5 ч и неделя) и время
  сброса; расход по задаче и по сессии — ходы, токены, стоимость.
- **Запросы человеку.** Уведомление и окно поверх приложений с
  вариантами ответа; опасное — с подтверждением.
- **Команда `dpai`** в Termux или на ПК — те же действия, что на экране,
  через канал на `127.0.0.1` с сопряжением по коду
  (`DP_AI_Orcestrator:D-47`).
- **Журнал и настройки.** Журнал приложения на экране и файлом в
  «Загрузки»; копия настроек в «Загрузки» — сама и по кнопке;
  восстановление после переустановки — одной командой в Termux.

Остальные части D-01 — проекты экосистемы, ход разработки, сайт,
статистика — ещё не начаты: они приходят подсистемами в фазе B
мастер-ТЗ (D-25, D-28). Что из сделанного ещё не проверено на телефоне
и что держит V1 подсистемы — [`dpai/TODO.md`](dpai/TODO.md), раздел «На
устройстве».

## Сборка и проверки

```sh
./gradlew build                     # из корня: ядро, подсистема «AI» и, при Android SDK, приложение
./gradlew :dpai:android:assembleDebug   # отладочный APK: dpai/android/build/outputs/apk/debug/
tools/check/run.sh                  # static: документы, процесс, секреты, ядро — секунды
tools/check/run.sh full             # и самотесты, проверки подсистемы dpai, ./gradlew build из корня; перед вливанием
tools/check/run.sh full --strict    # то же, но без JDK или Android SDK — ошибка; перед выпуском
tools/check/run.sh --write-status   # переписать блок состояния ниже из ROADMAP
cd dpai && tools/verify/run.sh full # подсистема «AI»: сборка, все тесты, при SDK — lint и API Android 30
```

Нужны Python ≥ 3.11 и git; для сборки — JDK 21 (Gradle — через
wrapper); для приложения — Android SDK (`ANDROID_HOME` или
`local.properties`), без него собирается всё, кроме оболочки Android.
Релизную сборку подписывает только автор своим ключом (ТЗ, §12.4);
APK нигде не публикуется (D-24). GitHub Actions не используются.
