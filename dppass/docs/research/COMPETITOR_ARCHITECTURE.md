Дата: **4 октября 2026**. Только для фактического сравнения
(`CLAUDE.md`, «Оригинальность»): «так сделано у X» — не довод для
DPpass; довод — свойство, которое нужно пользователю. Код этих
проектов в DPpass не копируется (лицензии — ниже и в
`docs/legal/THIRD_PARTY_MATRIX.md`).

## 2. Уроки для DPpass

1. **Связь UI/модели с JSON ядра дорого обходится.** Клиенты, где
   модель — это поля конфигурации конкретного ядра, переживают каждое
   ломающее изменение схемы ядра (у Xray — регулярно: `finalmask`
   v26.7.28) по всему приложению. DPpass: собственный IR и компилятор
   под закреплённую версию (D-05, D-18).
2. **Второе ядро у зрелых клиентов появляется** (Happ desktop: Xray +
   sing-box; Amnezia: несколько протоколов) — но чаще как отдельный
   исполняемый файл, чем внутри одного процесса. Для DPpass —
   абстракция сейчас, второе ядро — отдельным решением (D-04, D-20).
3. **Мост TUN — отдельный компонент.** v2rayNG держит его отдельной
   нативной библиотекой (hev-socks5-tunnel), SFA — внутри libbox, Xray
   с января 2026 умеет сам. DPpass: граница `TunnelBinding`, выбор —
   экспериментом (`ANDROID_NETWORK_MODEL.md`, §3).
4. **Изоляция процесса сервиса** (v2rayNG `:daemon`) — распространённая
   практика; в DPpass — отложенное решение с готовой границей.
5. **Телеметрия и идентификаторы устройства** (Happ: Sentry, Firebase,
   HWID) — DPpass отказывается от них по умолчанию (D-12); диагностика
   — локальные отчёты с редактированием секретов.
6. **Скрытые и зашифрованные конфигурации** (Happ) — удобство
   поставщика ценой контроля пользователя. DPpass: пользователь
   всегда может увидеть, что и куда отправляет его устройство (D-11).
7. **Лицензии экосистемы в основном копилефт** (GPL у v2rayNG,
   NekoBox, SFA, Amnezia; ещё и с ограничениями у Hiddify). Удобный
   чужой код — не повод его брать (D-20): DPpass пишет свой код и
   использует только компоненты из матрицы.
