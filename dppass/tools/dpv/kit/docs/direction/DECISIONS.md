# Решения

Журнал решений. Это источник истины: если другой документ расходится с
решением, прав журнал, а расходящийся исправляется.

Правила журнала:

- Номер — `D-NN` латиницей; не переиспользуется и не меняется. Новое
  решение — следующий свободный номер.
- Решение не переписывается задним числом. Если оно меняется, старое
  получает статус «заменено D-NN», а новое объясняет, что изменилось и
  почему.
- У каждого решения есть **Проверка.** — проверка DP Verify, команда
  проекта или тест, который ловит отступление от него. Решение без
  проверки — пожелание.

Форма записи: **Решение.**, **Почему.**, **Следствия.**, **Проверка.**,
**Отклонено.**

## Принятые

### D-01 — Проверки — DP Verify, процесс — process-kit

**Решение.** Проверки проекта идут одной командой DP Verify
(`tools/dpv/dpv`, профиль `tools/dpverify.toml`); правила работы —
`CLAUDE.md`, этапы — `ROADMAP/ROADMAP.md`, незаконченное — `TODO.md`.

**Почему.** Один вход, один вывод и одни коды возврата; общие проверки
не пишутся в каждом проекте заново.

**Следствия.** Предметные проверки проекта подключаются командами
профиля `[[command]]`; копия `tools/dpv/` руками не правится.

**Проверка.** `tools/dpv/dpv run full --ci` перед вливанием; итог —
`tools/dpv/dpv report --md` в описании PR.
