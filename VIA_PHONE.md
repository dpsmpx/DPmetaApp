# Garuda через телефон: раздача туннеля DPpass на Android

Как ПК с Garuda выходит в интернет через туннель DPpass на телефоне —
«Раздача туннеля» (`DPpass:D-51`). 21 октября 2026.

**Сначала главное.** Android пускает трафик точки доступа и USB-модема мимо
VPN. Если просто подключить ПК к точке доступа телефона, ПК выйдет в
интернет напрямую через оператора, без туннеля. Через туннель идёт только
то, что ПК отправляет в прокси телефона: SOCKS5 или HTTP с логином и
паролем. Ниже два способа:

- весь ПК через туннель — скрипт `dppass-via-phone` с sing-box (раздел 3);
- только браузер (раздел 4).

DPpass для Linux так пока не умеет: подключения через устройство раздачи
(`DPpass:D-55`) в нём нет (`DPpass:D-74`, этап 6).

## 1. Телефон

1. DPpass → «Подключение» → подключиться.
2. DPpass → «Настройки» → «Раздача туннеля» → «Раздавать туннель».
3. Включить раздачу в Android: строка «Точка доступа и модем» на том же
   экране, или «Настройки» Android → «Сеть и интернет» → «Точка доступа и
   модем» (на Xiaomi — «Подключение и общий доступ»). Там — «Точка доступа
   Wi-Fi» или «USB-модем».
   - Через несколько секунд DPpass переподключится.
   - В разделе «Адрес прокси» появится адрес вида `10.x.y.z:порт` или
     `192.168.x.y:порт` — по
     одному на каждую точку доступа и модем.
4. «Поделиться входом» → отправить ссылку
   `socks5://логин:пароль@адрес:порт#DPpass` себе на ПК: KDE Connect,
   «Избранное» мессенджера или другим способом. Можно и переписать порт,
   логин и пароль из раздела «Вход».

Порт, логин и пароль сохраняются, поэтому после переподключения ПК
перенастраивать не нужно. После «Новые логин, пароль и порт» ссылку нужно
снова передать на ПК.

## 2. Подключить ПК к телефону

- **Wi-Fi.** Значок сети в панели KDE → точка доступа телефона → пароль.
- **USB.** Подключить кабель, на телефоне включить «USB-модем».
  NetworkManager сам поднимет проводное подключение: драйверы RNDIS и NCM
  есть в ядре Garuda.
- **Bluetooth.** Медленнее: единицы Мбит/с. Сначала сопрячь телефон в
  настройках Bluetooth KDE и включить на телефоне «Bluetooth-модем». Затем
  выполнить команды ниже. MAC-адрес телефона — в `bluetoothctl devices`.
  Этот способ не проверен.

  ```sh
  nmcli connection add type bluetooth con-name phone-bt bluetooth.bdaddr AA:BB:CC:DD:EE:FF bluetooth.type panu
  nmcli connection up phone-bt
  ```

После этого интернет на ПК уже есть, но **без туннеля**. Дальше — раздел 3
или 4.

## 3. Весь ПК через туннель: `dppass-via-phone`

Установить один раз. Каталог `dppass-linux` — клон этой ветки из
`README.md`:

```sh
sudo pacman -S sing-box
cd dppass-linux && git pull
sha256sum -c SHA256SUMS
sudo install -m 755 dppass-via-phone /usr/local/bin/
```

Первый запуск — со ссылкой с телефона, в одинарных кавычках:

```sh
dppass-via-phone 'socks5://логин:пароль@10.x.y.z:порт#DPpass'
```

Потом ссылка не нужна: `dppass-via-phone`. Скрипт спросит пароль `sudo`.
Остановить — Ctrl+C в том же окне терминала.

Что делает скрипт:

- **Запоминает порт, логин и пароль** в `~/.config/dppass-via-phone/login`
  с правами 0600, только для вас.
- **Адрес телефона не запоминает:** Android меняет подсеть точки доступа
  при каждом включении. Поэтому скрипт ищет телефон среди шлюзов сетей ПК —
  тот, что отвечает на порту раздачи. Подходит только частный адрес своей
  сети.
- **Запускает sing-box от root.** sing-box поднимает TUN `dppass-phone` и
  отправляет весь трафик ПК в прокси телефона:
  - запросы DNS к любому серверу, в том числе к самому телефону,
    перехватываются и уходят через телефон по TCP к 1.1.1.1 — другой
    сервер задаёт `DPPASS_DNS=…`;
  - IPv6 закрыт;
  - конфигурация sing-box с паролем — временный файл в `/run/user/…`,
    удаляется при выходе.
- **По Ctrl+C** sing-box убирает TUN, маршруты и правила.

Не запускайте скрипт вместе с DPpass для Linux: оба забирают весь трафик.
Пакет sing-box ставит ещё службу `sing-box.service` — она здесь не нужна,
не включайте её.

**Проверка:**

```sh
curl https://ifconfig.me            # адрес сервера VPN, а не оператора
curl -6 -m 5 https://ifconfig.me    # не соединится: IPv6 закрыт
```

Российский сайт может показать адрес оператора. Если на телефоне включён
раздельный маршрут, так и должно быть: маршрутизация и блокировка у ПК те
же, что у телефона.

## 4. Только браузер

FireDragon (браузер Garuda) или Firefox:

1. «Настройки» → «Основные» → «Параметры сети» → «Настроить…».
2. «Ручная настройка прокси»:
   - «HTTP прокси» — адрес телефона;
   - «Порт» — порт раздачи;
   - отметить «Также использовать этот прокси для HTTPS».
3. На первом сайте браузер спросит логин и пароль.

Имена сайтов при этом разрешает телефон. Всё остальное на ПК — обновления,
мессенджеры, терминал — идёт мимо туннеля, напрямую через оператора. Для
одной команды в терминале можно указать прокси явно:
`curl -x socks5h://логин:пароль@адрес:порт https://ifconfig.me`.

## Если не работает

| Что видно | Что делать |
|---|---|
| `телефон не найден` | Проверить три вещи: ПК подключён к точке доступа или USB-модему телефона; DPpass на телефоне подключён; включено «Раздавать туннель». На экране раздачи должен быть адрес. |
| На экране раздачи «Нет точки доступа, USB- или Bluetooth-модема» | Включить раздачу в Android: DPpass заметит это за несколько секунд. |
| «Прокси не открылся на адресе раздачи» | Выключить и включить точку доступа или нажать «Новые логин, пароль и порт». Во втором случае передать на ПК новую ссылку. |
| `socks5: incorrect user name or password` | Вход сменили на телефоне: запустить скрипт с новой ссылкой. |
| ПК сразу в двух сетях, например кабель дома и телефон | Скрипт сам перебирает шлюзы. Если не нашёл — `DPPASS_PHONE=10.x.y.z dppass-via-phone`, адрес — с экрана раздачи. |
| Скрипт работает, а сайты не открываются | Скорее всего, на телефоне отключился туннель: раздача работает только через него. Интернет на ПК при этом пропадает, а не идёт мимо туннеля. |
| sing-box завершился аварийно | Запустить скрипт ещё раз и остановить Ctrl+C: он уберёт оставшиеся правила. Или перезагрузить ПК. |

## Пределы

- **Прокси без шифрования.** Логин, пароль и трафик между ПК и телефоном
  идут открыто. Поэтому — только своя точка доступа с паролем, USB или
  Bluetooth. DPpass открывает прокси только на адресах раздачи, не в
  домашней сети и не в интернете.
- **Открытый порт виден.** Пока раздача включена, порт видят приложения
  телефона и устройства в раздаче: это примета прокси. Выключайте раздачу,
  когда она не нужна.
- **Правила по приложениям** телефона к ПК не относятся.
- **В ссылке — пароль.** Если передавали её через мессенджер, удалите
  сообщение после.

## Как проверено

21 октября 2026, в облаке, стенд `checks/via_phone_stand.py`. Это три
сетевых пространства имён на настоящем ядре Linux:

- «интернет»;
- «телефон» — Xray 26.9.30 со входом раздачи, каким его строит DPpass:
  SOCKS5 с паролем, UDP, распознавание; трафик точки доступа телефон
  пересылает мимо туннеля, как Android;
- «ПК», у которого DNS — шлюз, как от DHCP точки доступа.

Версии sing-box — 1.14.0 (как сейчас в `extra` Arch) и 1.14.3. Что
проверено:

- без скрипта трафик и DNS ПК идут мимо туннеля — стенд это видит;
- со скриптом:
  - трафик по имени и по адресу, UDP и DNS резолвера системы идут через
    «туннель» телефона;
  - DNS телефона (то есть оператора) не спрошен ни разу;
  - мимо туннеля не ушло ни одного пакета;
- при неверном пароле нет ни соединения, ни обхода;
- HTTP-прокси телефона для способа «только браузер» (проверено `curl`): с
  паролем — через «туннель», имя разрешает телефон; без пароля — отказ 407;
- телефон находится среди двух шлюзов;
- второй запуск отклоняется;
- Ctrl+C убирает TUN, правила и файл с паролем;
- после аварийного `kill -9` следующий запуск проходит, а его Ctrl+C всё
  убирает;
- выключенная раздача даёт отказ с причиной.

Не проверено:

- на самой Garuda и с настоящим телефоном;
- Bluetooth;
- настройка прокси в самом браузере;
- правило «IPv6 закрыт» (`strict_route`). В ядре облачной машины нет IPv6,
  поэтому стенд запускал скрипт без этого правила. По коду sing-tun на
  Linux это его единственное действие.
