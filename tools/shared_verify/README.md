# Общая папка DP-Verify

D-89, D-91, D-92. `runtime.py` — контроллер POSIX (Linux, Termux); Python 3.11+ и
Git. Сам DP-Verify сохраняет автономное ядро без сети: сеть и обновление
выполняются этим внешним контроллером. Исходный репозиторий DP-Verify
не встраивается второй независимой копией кода в исходники APK.

Нужна полная Git-копия DP-Verify, ветка main, origin — официальный HTTPS
URL репозитория без учётных данных в адресе. Аутентификацию настраивает
среда отдельно. Папка состояния с логом проверки — вне папки инструментов.

```sh
python3 tools/shared_verify/runtime.py --repo /opt/dp-tools/DP-Verify sync --state /opt/dp-tools/state
python3 tools/shared_verify/runtime.py --repo /opt/dp-tools/DP-Verify session -- claude
```

`session` передаёт `DP_VERIFY_HOME`, `DP_VERIFY_REVISION` и шлюз `dpv`
в PATH. Открытая сессия не держит lease. Шлюз вызывает `run`, который
держит shared lease только во время инструмента. Правки папки — через
`edit` под exclusive lease. Несколько инструментов могут читать одновременно. `sync`
берёт exclusive lease без ожидания: занято — JSON `deferred`, код 75;
планировщик должен повторить позднее. Lock один на git-common-dir,
поэтому symlink и дополнительные worktree не обходят его. Дочерний
процесс наследует дескриптор на случай аварии обёртки.

Синхронизация принимает только линейную историю. Проверяет кандидат
отдельной worktree штатной командой `./dpv run full --ci`, затем
активирует проверенный fast-forward или отправляет проверенный commit
прямо в main обычным push без PR/force. Ошибка проверки, изменение
кандидата или основной папки во время проверки, новая несовместимая
удалённая версия — отказ с сохранением истории и правок. В выводе нет
stderr Git, где мог бы оказаться URL с секретом; подробный вывод самого
проверяющего инструмента — в приватном `validation.log`.

`init` получает первую копию и проверяет её до установки. `watch`
повторяет синхронизацию и откладывает занятые попытки. Локальные правки
автоматически коммитятся только при совместимой удалённой истории и
настроенном авторе Git; каждый публикуемый кандидат проходит full.
Разошедшаяся история сохраняется с отказом, без merge/force.

Адаптер агента dpai подключает папку к Claude/Codex/Gemini по настройке
`dpai tools configure`; выключено по умолчанию. Ещё нужны экран Android,
планировщик приложения, авторизация подключённого GitHub-аккаунта и
Windows-lock. Сейчас CLI использует уже настроенную авторизацию Git.
Ручные обращения в обход шлюза/контроллера не защищены lease.

Проверки — `tests/test_shared_verify.py`: настоящие временные Git-репозитории,
конкурентный процесс, сбои валидатора и гонки, без сети и реальных ключей.
