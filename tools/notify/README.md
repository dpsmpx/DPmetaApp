# Хуки мгновенного канала

`dpmeta_notify.py` шлёт в мгновенный канал DPmetaApp (D-23, D-152; ТЗ,
F-55, F-56) события «Claude закончил ответ», «ждёт разрешения», «ждёт
ввода», «ход прервался» и «сессия закончилась». В событии — только тип,
ключ проекта, ветка, время, id сессии и причина, с подписью HMAC-SHA256
общим ключом; текст ответа и сообщения не уходят.

## Подключение

Репозиторий подключает хуки своим решением. Нужен `python3` (3.8+), сеть до
сервера ntfy и две переменные окружения — из приложения: «Ещё» →
«Уведомления» → «Мгновенный канал»:

- `DPMETA_PUSH_URL` — адрес темы, например `https://ntfy.sh/<тема>`;
- `DPMETA_PUSH_KEY` — «Ключ для хуков» (секрет: только в окружение, не в
  репозиторий);
- `DPMETA_PROJECT` — по желанию, ключ проекта (иначе — имя корня git).

В `.claude/settings.json` репозитория:

```json
{
  "hooks": {
    "Stop": [{"hooks": [{"type": "command", "command": "python3 tools/notify/dpmeta_notify.py"}]}],
    "Notification": [{"hooks": [{"type": "command", "command": "python3 tools/notify/dpmeta_notify.py"}]}],
    "StopFailure": [{"hooks": [{"type": "command", "command": "python3 tools/notify/dpmeta_notify.py"}]}]
  }
}
```

Скрипт копируется в репозиторий как есть (путь в `command` — от его
корня). В облачной среде Claude Code сервер ntfy должен быть в списке
разрешённых адресов среды.

Хук не мешает Claude: нет переменных, сети или ответа — молча выходит с
кодом 0.
