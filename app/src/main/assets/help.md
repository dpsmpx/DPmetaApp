# Справка DP_IDE

DP_IDE — мобильная студия разработки: проекты, IDE и ИИ на одном телефоне; GitHub — по желанию. Ссылки ниже ведут в разделы приложения и в его настройки; адреса сайтов — по двум касаниям: первое копирует, второе открывает.

[Показать окно знакомства снова](app:intro)

## Разделы

Панель открывается кнопкой ≡ слева вверху.

- **Сводка** — числа по всем проектам: что работает, вопросы автору, PR, ошибки источников. [Открыть](app:summary)
- **Проекты** — проекты на устройстве, а с GitHub — ещё репозитории, PR и вопросы; вкладки — в верхней панели. [Открыть](app:projects)
- **IDE** — файлы проекта, редактор, терминал Linux. [Открыть](app:ide)
- **AI** — сессии Claude, Codex и Gemini, задачи, запросы на подтверждение, модели. [Открыть](app:ai)
- **Настройки** — всё одним документом, с поиском: оформление, проекты, хранилище и секреты, управление ИИ, копии, журнал. [Открыть](app:settings)

## Первые шаги

Для разработки с API-моделью откройте [ИИ](app:ai) → «Быстрый старт с ИИ».
Выберите уже клонированный проект и провайдера; ввести нужно только API-ключ,
модель выбирается из списка. Пути и служебное место работы готовятся сами.
У подключённого профиля ключ повторно не нужен. После вашего сообщения модель
может читать, искать и менять файлы выбранного проекта, запускать его проверки
и сборку. «Проект и изменения» открывает Git diff и отмену последней правки.
Обычные чаты, CLI/SSH и расширенная настройка остаются доступны.

На рабочем экране IDE вкладка «Автоматизации» показывает инструменты
основного дерева: команды пульта, профили, проверки задач и окружение.
CHECK/BUILD и диагностика вызываются там же; остальные действия открывают
прежние настройки и подтверждения. Проектный API-чат получает тот же
каталог и проверяет ревизию перед вызовом.

1. Установите Linux в приложении — в нём работают терминал, сборка и ИИ: «AI» → «Настройки AI» → «Linux в приложении». [Настройки → AI](app:settings?q=linux)
2. Создайте проект мастером — C++, Kotlin или Python, локальный Git без GitHub. [Новый проект](app:new-project)
3. Если нужна подписка Claude Code, войдите в слот: вкладка «Targets» → «Терминал» → «Claude в терминале». Для проектного API-чата этот вход не требуется.
4. По желанию — GitHub. Токен fine-grained, только чтение содержимого, PR и метаданных; для issues и CI в карточке — ещё Issues, Checks и Commit statuses на чтение (по желанию): [страница токенов GitHub](https://github.com/settings/personal-access-tokens). Вставьте его в [Настройки → токен](app:settings?q=токен): он хранится под ключом Keystore и открывается PIN или биометрией. Затем «Обновить» на сводке: сначала «Проекты пульта» — отметьте репозитории, которые пульт показывает; потом «Клоны…» — какие из них скопировать в `~/projects/<владелец>/<имя>`. [Настройки → проекты пульта](app:settings?q=проекты)

## Проекты пульта

Пульт показывает ваши репозитории GitHub, которые вы сами отметили, и рабочие проекты на устройстве. «Проекты пульта…» — на вкладке «Проекты» и в настройках: репозитории вашего аккаунта с флажками и поле «владелец/имя» для репозитория не из аккаунта (нужен доступ токена). Снятая отметка убирает проект из пульта; клон на телефоне остаётся — удалить его можно в «Клоны…». Клон — отдельный выбор: без него пульт читает репозиторий с GitHub.

В карточке проекта — «Документы и чек-листы…»: пути от корня репозитория, по одному на строке. Документы появляются чипами рядом с README, касание открывает файл. Чек-листы — файлы Markdown с пунктами `- [ ]` и `- [x]`: после «Обновить» карточка показывает раздел «Чек-листы» — сколько отмечено из всех, долю и первые открытые пункты каждого файла; неверный путь виден как «файла нет».

Карточка показывает и работу на GitHub: открытые issues (метки, кому назначены), последние коммиты основной ветки и CI — у головы основной ветки и у открытых PR (зелёный, красный с упавшими проверками, идёт). Красный CI поднимается в «Внимание». Если токену не дали Issues, Checks и Commit statuses, карточка пишет «нет прав токена» — это не ошибка.

Если проект — рабочий проект IDE, карточка начинается с раздела «Студия»: открытые задачи ИИ, запросы, которые ждут вас, идущие сессии, ходы и расход ИИ, ручные сборки и проверки за сутки. На сводке те же числа — строкой «Студия» по всем рабочим проектам, рядом плитки «PR открыто» и «Красный CI».

«Ждут меня» — вкладка раздела «Проекты» и плитка сводки: запросы ИИ, которые ждут ответа (касание — «AI» на «Запросах»), PR, где у вас запрошено ревью (касание — экран PR), и issues, назначенные вам (касание — issue на GitHub), по всем проектам пульта. Ревью и issues отбираются по логину владельца токена — он запоминается при «Обновить».

Документ открывается в редакторе IDE, если репозиторий — рабочий проект IDE на клоне в `~/projects/<владелец>/<имя>`. Клон есть, а рабочего проекта нет — пульт один раз спросит «Сделать рабочим проектом IDE?»; «Нет» запоминается, и документ открывается для чтения в пульте, а кнопка «В IDE…» там задаёт тот же вопрос снова. Клона нет — документ читается с GitHub, рядом — «Клонировать и открыть в IDE…»: клон делается при «Обновить», затем файл открывается в редакторе.

## Новый проект

Мастер открывается из «Сводки» и «Проектов» («Создать проект…»), из IDE («Новый проект…») и с вкладки «Targets». [Открыть мастер](app:new-project)

- **Шаблоны.** C++ — CMake и тесты ctest. Kotlin — консольный (kotlinc без Gradle, лёгкий для телефона), Gradle JVM (wrapper и JUnit; первая сборка скачивает Gradle) или Android-приложение на Compose (собирается на ПК-target с Android SDK). Python — пакет в `src/` и тесты unittest без загрузок.
- **Место.** По умолчанию — Linux приложения на телефоне, `~/projects/local/<имя>`; можно выбрать ПК по SSH и другую папку от домашней. Папка уже есть и не пуста — мастер ничего не перезаписывает.
- **Инструменты.** Мастер проверяет их на target; в Linux приложения недостающее ставится кнопкой (нужна сеть).
- **Git.** Локальный репозиторий, ветка `main` и первый коммит. Если Git на target не знает автора коммитов, впишите имя и почту в мастере.
- **Дальше.** Проект становится рабочим: в IDE — вкладки «Сборка», «Проверки» и «Запуск», ИИ получает его задачи. Опубликовать проект на GitHub можно позже — кнопкой «На GitHub…» у проекта в карточке «На устройстве» («Сводка», «Проекты»): закрытый репозиторий от имени владельца токена и отправка ветки `main`. Токену для этого нужны права Administration: write и Contents: write.

## Резервная копия и аварийный отзыв

[Настройки → резервная копия](app:settings?q=резервная)

- **Сохранить копию…** — разделы на выбор: пульт, ИИ и проекты, IDE и оформление. Секреты (токены, ключи API) — только с паролем от 12 знаков; пароль приложение не хранит, забытый — копию не прочитать никому. Ключ SSH и ключи подписи APK из Keystore не выходят: на новом телефоне — новый ключ SSH (его строку снова добавьте на ПК), ключи подписи — из ваших `.p12`.
- **Сама** — копия без секретов раз в сутки в «Загрузки/dpmeta-backup» (последние 7).
- **Восстановить…** — файл, пароль (если копия под ним) и разделы. Нынешнее сначала сохранится копией без секретов; секреты пишутся сразу, остальное — после перезапуска приложения.
- **Аварийный отзыв** — все секреты устройства, «Отозвать ↗» ведёт на страницу сервиса. Телефон потерян — отзовите там с другого устройства. «Стереть отмеченные…» удаляет отмеченное с этого телефона после ввода слова «СТЕРЕТЬ». [Настройки → аварийный отзыв](app:settings?q=отзыв)

## Уведомления

Настройки уведомлений пульта: тихие часы, приватность, правила,
проба по загруженной ленте и импорт/экспорт —
[Открыть настройки](app:settings?q=уведомления).

- **Кнопки в уведомлении:** «Отложить» — две, по умолчанию «На час» и «До утра (09:00)»; каждую можно сменить на 15, 30 минут, 1, 2, 3 часа или «до времени». Отложенное приходит снова в срок, в тихие часы — без звука. У событий PR — «Открыть PR».
- **Сводка:** правила «в сводку» копят события и присылают одно уведомление со списком — раз в день (по умолчанию 09:00), утром и вечером или каждые 2, 4, 6, 12 часов. Пустая сводка не приходит.
- **Ответ чата в фоне:** пока Claude отвечает в «Спросить Claude», висит «Claude отвечает…» с «Прервать» — можно уйти из приложения, ответ не оборвётся. Дописан, пока вы не в приложении, — уведомление «Ответ готов» (без текста ответа); касание открывает чат.
- **Маршруты:** запуск маршрута из пульта виден в ленте («Маршрут «…» запущен»), уведомление — только когда до часового предела остаётся меньше 5 запусков. PR, который открыла сессия этого запуска, приходит уведомлением «PR #N от маршрута «…»» с «Открыть PR» — пульт узнаёт его по ссылке на сессию в описании PR.

## Проекты

Пульт показывает выбранные вами репозитории GitHub и рабочие проекты IDE.
Касание открывает карточку проекта; документы из карточки открываются в IDE.
Порядок задаётся вашим списком проектов; рабочие клоны доступны также из IDE.

## Проверка

«AI» → «Настройки AI» → «Проверка» показывает, что не так, почему и что делать; решение — кнопкой, где оно есть. Пока проблемы есть — полоса над вкладками «AI» и «проблем: N» в строке «AI» сводки. Там же — мастер настройки: Linux, Claude Code, вход, токен GitHub, автор коммитов.

Само, без нажатия, приложение делает только безопасное: чинит повреждённые пакеты Linux, пишет помощник входа GitHub для Git (токен он берёт из `GH_TOKEN`, только если вы включили «давать ИИ»), обновляет DNS Linux при смене сети и догоняет клоны без ваших правок и коммитов. Что сделано — списком «Исправлено само» и строкой в журнале. Права, секреты и данные меняются только вашим нажатием. [Открыть «AI»](app:ai)

## Хранилище

Одно хранилище для IDE, терминала и ИИ — домашняя папка Linux приложения:

- `~/projects` — проекты: клоны GitHub — `<владелец>/<имя>`, свои — `local/<имя>`;
- `~/tools` — инструменты: `bin` (он первым в `PATH`), службы IDE (`ide`), модели (`models`);
- `~/ai` — слоты ИИ, `<исполнитель>-<N>`; менеджеру файлов не виден.

Карта `~/STORAGE.md` обновляется сама после установки, загрузки и клона; ИИ узнаёт о ней из своей инструкции.

**Место.** «Предел хранилища, ГБ»: `0` — всё свободное место телефона. Загрузка, установка, новый клон и сборка в Linux приложения не начнутся, если после них на телефоне останется меньше 1 ГБ — это жёсткий запас. [Настройки → хранилище](app:settings?q=хранилище)

## Фоновое обновление

«Ещё» → «Фоновое обновление»: пульт обновляется сам раз в 15, 30 (по умолчанию) или 60 минут — при сети и не низком заряде, и только если телефон недавно разблокировали (токен GitHub открыт лишь после входа). Новые клоны в фоне не создаются — это делает «Обновить». Под выбором — итог последнего фонового запуска.

## О программе

«Ещё» → «О программе»: версии DP_IDE и «AI», коммит, из которого собран APK, отпечаток SHA-256 сертификата подписи установленного APK и «Лицензии компонентов» — строки документов происхождения, которые лежат в самом APK.

## IDE

- **Поиск** — кнопка в списке файлов: «Файлы» ищет по именам и путям, «Код» — по тексту или регулярному выражению, от открытой папки вниз; «Заменить все…» меняет найденное во всех файлах после окна с числами. Касание файла открывает вкладку, касание строки — вкладку на этой строке. Служебные папки (`.git`, `build`, `node_modules`) и файлы больше 1 МБ не просматриваются.
- **Несколько проектов** — Targets → у target с репозиторием ⋮ → «Проект…» добавляет рабочий проект; все работают одновременно, места на target общие. Какой показывать — «Показывать» в «Рабочих проектах» или переключатель над рабочим экраном. Сколько сессий ИИ сразу идёт на target — «Мест для сессий ИИ» в настройках карточки target (1–4).
- **Артефакты и APK** — «Сборка», «Артефакты»: найденные файлы сборки; у APK — «Установить» (сначала окно с пакетом, версией, подписью и SHA-256, ставится показанная там копия; затем подтверждаете в окне Android), «Подписать» своим ключом из Keystore телефона, «В Загрузки». Ключи — «Ключ проекта» и «Глобальный ключ»: «Импортировать…» файл .p12 или «Создать…» (копия .p12 под паролем сохраняется у вас); ключи уходят и в копию приложения под паролем. «Ключ выпуска на ПК…» собирает из ваших полей команду keytool и копирует её (пароль в приложении не хранится). Сборка подписывается сама после успеха — ключом проекта, иначе глобальным; ключа нет — APK остаётся как собран, с предупреждением. Дерево на ПК — «На телефон» скачивает файл по SFTP (на ПК ничего не меняется), дальше — «Установить», «Запустить».
- **История сборки** — внизу «Сборки» и «Проверок»: каждый запуск с исходом, временем, веткой и коммитом; касание раскрывает шаги, ошибки и вывод.
- **Файлы ПК** — у дерева на ПК «Файлы» открывают его по SFTP: просмотр, поиск и правка с сохранением обратно на ПК (файл изменили на ПК — приложение скажет о конфликте).
- **Запуск** — рабочий экран проекта, «Запуск»: команда и папка программы; «▶ Собрать и запустить» открывает её во вкладке терминала, только если сборка прошла. На Windows-ПК команда выполняется в PowerShell по SSH: одна строка до 1500 знаков, после неё — «[Код выхода: N]» и PowerShell в той же папке.
- **Сборка в несколько шагов** — рабочий экран проекта, «Сборка» и «Проверки»: шаги по порядку, следующий — после успешного; «Шаблон» подставляет CMake, Gradle, Make, CTest, Python.
- **Android SDK** — «AI» → «Настройки AI» → «Linux в приложении» → «Android SDK…»: по желанию, с официальных источников Google после вашего согласия с лицензией (около 1,5 ГБ, с NDK — до 4 ГБ). Под arm64 Google не выпускает aapt2 для Gradle и NDK — их можно поставить сборкой сообщества: адрес и SHA-256 вводите вы, сумма проверяется. В профиле сборки — окружение `ANDROID_HOME=/root/android-sdk`.
- **Окружение** — «AI» → «Настройки AI» → «Linux в приложении» → «Окружение: пакеты…»: все пакеты Alpine — версия, сколько занимает, сумма из базы apk, поставлен вами или зависимостью и для кого нужен. Поиск и фильтры «Ваши», «С проблемами», порядок по размеру. Проблемы совместимости (нет зависимости, не та версия, конфликт, повреждённый пакет) видны сразу, а кнопки починки запускают apk без ИИ. «Убрать…» у вашего пакета сначала показывает всё, что уйдёт вместе с ним, и сколько освободится; части системы Alpine не убираются. «Обновить» — один пакет, «Обновить всё» — все. Раздел «Компоненты» — то, что DP_IDE ставит не пакетом Alpine: Android SDK, службы IDE (kotlin-lsp, pyright), Kotlin, окружения проектов, Claude Code, Codex, Gemini, модели. У каждого — версия, версия этой сборки DP_IDE, источник, сумма и кто её сверил, размер; «Убрать…» освобождает место, «Поставить заново» и «Обновить» — тем же установщиком, что на его экране. Раздел «Настройки»: свои переменные окружения (например, `JAVA_OPTS`, `GRADLE_OPTS`, `TZ`) — для терминала, ходов ИИ и шагов профилей; секреты сюда не пишутся, как и переменные самой среды (`PATH`, `LANG`, `GIT_…`). Там же — репозитории Alpine: выпуск или `edge` (и `testing` при нём) с тем же зеркалом; «Записать и применить» показывает новый список и приводит пакеты к выбранной ветке. Раздел «Снимки»: перед каждой командой apk и сменой настроек приложение запоминает ваши пакеты, версии, репозитории и переменные (последние 10). Касание снимка показывает, что вернётся из кеша наверняка, что — только если зеркало ещё даёт ту версию, и что уйдёт; «Откатить» возвращает окружение и в конце говорит, что вернуть не вышло. «Хранить файлы пакетов для отката» держит кеш apk; без него старая версия вернётся, только если она ещё есть в зеркале. Раздел «Проекты»: для каждого проекта в Linux приложения — что ему нужно по файлам корня (CMake, Gradle, npm, Python, Cargo, Go) и шагам ручных профилей, чего нет и каким пакетом это ставится («Поставить: …»); Android SDK — по «Нужно» профиля. «Убрать…» у пакета предупредит, если с ним уйдёт команда, нужная проекту. В конце «Настроек» — «Сбросить Alpine…»: корневая система распаковывается заново, ~/projects и ~/ai сохраняются всегда, весь дом и кеш пакетов — по выбору; подтверждение — вводом «Alpine». Перед сбросом приложение делает снимок: «Откатить» к нему вернёт прежний набор пакетов. «Обновления» в «Настройках»: раз в сутки при Wi-Fi и зарядке приложение само проверяет, что новее в зеркале Alpine и в этой версии DP_IDE, и присылает уведомление, если появилось новое; ставите вы — «Обновить» у пакета или «Обновить всё». «Проверить сейчас» — то же по кнопке.
- **Что нужно профилю** — в профиле «Сборки» или «Проверки» отметьте «Android SDK» или «Android NDK»: перед запуском в Linux приложения проверяется, что они поставлены («Android SDK…»), и `ANDROID_HOME` подставляется сам; чего нет — запуск не начнётся и скажет, что поставить. На ПК используется его SDK.
- **Параметры профиля** — там же. В командах подставляются `${PROJECT}`, `${ROOT}`, `${TREE}`, `${BRANCH}`, `${TARGET}`; свои параметры — строкой `VARIANT | Вариант | debug, release`, их значения выбираются кнопками перед запуском (последний выбор помнится). «Окружение шагов» — строки `ИМЯ=значение`; секреты туда не пишутся (имена вроде `*_TOKEN` отклоняются) — их даёт «давать ИИ».
- **Отладка** — C, C++ и Python в Linux: точка останова — касанием номера строки, «Отладка» над полем файла или на странице «Запуск» проекта; на остановке — строка подсвечена, внизу — шаги, стек, переменные и выражение. Нет отладчика — «Поставить gdb» или «Поставить debugpy». Дерево на ПК — «Отладка» на странице «Запуск»: отладчик работает на самом ПК (Linux — gdb 14+ и debugpy, Windows — только Python с debugpy); ставите его вы, приложение подскажет команду.
- **Logcat** — «Logcat» в списке файлов: журнал Android по беспроводной отладке телефона к самому себе — пакет, уровень, поиск, пауза; строка трассировки открывает файл на строке. У APK в «Артефактах» — «Запустить» и сразу его logcat. Права adb — права shell, ими пользуются и терминал, и ИИ.
- **ИИ-дополнение** — «ИИ: дописать» у файла проекта: модель дописывает код в месте курсора, ответ вставляется по «Вставить». Источник проекта — «Вид / команды» → «ИИ-дополнение…»: выключено (по умолчанию), локальная модель или облачная с согласием на отправку кода. Уходит только окно открытого файла, ключи вырезаются.
- **Предпросмотр Compose** — «Предпросмотр» у файла Kotlin с @Preview: функция открывается в самом приложении на телефоне (его debug-сборка с ui-tooling) через adb, снимок экрана — в панель. У разметки XML — «Показать разметку» из установленного APK (свои виды — рамками). Файл в дереве на ПК — ещё «Нарисовать на ПК»: Robolectric рисует функции и разметку в самом проекте на ПК (там нужны JDK и Android SDK), картинки — в панель.
- **Отладка своего APK** — «Отладка» у установленного APK (сборка debug) в «Артефактах»: приложение перезапустится и подождёт отладчика; точки — касанием номера строки в файлах .kt и .java, на остановке — стек, переменные, шаги. «Остановить» отключает отладчик, приложение работает дальше.
- **В ИИ** — над полем файла проекта: выделение (или строка курсора), замечания, символ, импорты и использования — в сессию задачи, новой задачей или во вкладку ИИ терминала; направление запоминается для проекта. У предела ИИ — предложение другого подключённого ИИ; автоматически — только если включено в «Контуре».
- **Ошибки сборки** — после ▶ в строке терминала «Ошибки: …», на рабочем экране — под выводом проверки и сборки. Касание строки открывает файл на месте ошибки.
- **Редактор** — «Править» у файла: подсветка, вкладки, поиск и замена в файле, отмена; файл меняет только «Сохранить».
- **Семантика** C++, Python и Kotlin включается кнопкой над полем редактора; языковая служба ставится тоже кнопкой, сама ничего не скачивает.

## Секреты

Все секреты приложения — одним списком, без значений. «Давать ИИ» можно токену GitHub, ключам API-профилей и токену Hugging Face; Admin-ключи, токены маршрутов и облачной копии — только в списке. [Настройки → секреты](app:settings?q=секреты)

- Выданное попадает в окружение Linux приложения — ходам ИИ и терминалу; на ПК-target не уходит и на диск не пишется.
- Ключ, который у слота перекрыл бы вход по подписке, слот видит под именем `DPMETA_<имя>` — например, `DPMETA_ANTHROPIC_API_KEY`: подписка не переключается на оплату по API.
- Токен GitHub для ИИ открывается входом раз за запуск и отзывается при остановке службы.
- **Свой секрет** — «Добавить свой секрет»: имя вроде `MY_SERVICE_TOKEN` станет переменной окружения. Имена приложения (`GH_TOKEN`, ключи провайдеров) и системные (`PATH`, `LD_…`) не принимаются.

Ключи: [Anthropic Console](https://console.anthropic.com/settings/keys), [Hugging Face](https://huggingface.co/settings/tokens).

## Оформление

Тема, акцент, размер текста, плотность и шрифт редактора — сразу во всём приложении. «Обои телефона» — цвета обоев на Android 12 и новее. [Настройки → оформление](app:settings?q=тема)

## Частые вопросы

**Загрузка или установка не начинается.** Не хватает места: после неё осталось бы меньше 1 ГБ или приложение вышло бы за предел. Освободите место или поднимите предел. [Настройки → место](app:settings?q=место)

**Терминал не находит программу, поставленную IDE.** Откройте новую вкладку терминала: `~/tools/bin` попадает в `PATH` при входе в оболочку.

**Где клоны, которые раньше были в `/root/repos`?** В `~/projects`; на старом месте — ссылка.

**Claude в слоте ведёт себя как при оплате по API.** Проверьте, что в слоте нет `ANTHROPIC_API_KEY`: приложение его не выдаёт, ключ доступен как `DPMETA_ANTHROPIC_API_KEY`.
