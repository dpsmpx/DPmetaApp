# Сборки для устройств автора

D-104 разрешает ручную выкладку APK в GitHub Releases закрытого
`dpsmpx/DPmetaApp` по явному поручению автора. D-24 сохраняет личное
назначение; видимость репозитория, сайт и магазины не меняются.
Ветка apk_debug по D-33 остаётся отдельным каналом. GitHub Actions нет.
Вливание в main — только отдельным поручением (D-79).

## Перед выкладкой

1. Проверить, что репозиторий закрыт, версия/tag не заняты другой сборкой,
   рабочее дерево чистое, исходный коммит зафиксирован в описании.
2. Выполнить `tools/check/run.sh full --strict` с JDK 21 и Android SDK.
3. Взять объединённый shell-debug.apk из debug-вывода модуля shell,
   проверить applicationId, versionName/versionCode, minSdk/targetSdk,
   `apksigner verify --verbose --print-certs` и SHA-256.
4. Подготовить русское описание изменений, ограничений, результатов
   проверок и путь к новым функциям; рядом с APK — SHA256SUMS.txt.
5. Создать draft release на точном исходном коммите, загрузить файлы,
   проверить имена/размеры/суммы и только после этого опубликовать dev
   как prerelease. Существующие assets не перезаписывать молча.
6. После публикации сверить tag/commit, prerelease, assets и их SHA-256
   через API или контрольное скачивание. Сохранить ссылку в описании PR.

## Ключ выпуска (D-158)

Ключ — только у автора; сессия его не видит и не создаёт (ТЗ, §12.4). Три пути:

1. **В приложении.** «Ключи подписи» → «Глобальный ключ» → «Создать…» (копия .p12
   под паролем — в выбранный файл) или «Импортировать…». Ключ подписывает только
   после входа и уходит в копию приложения под паролем (D-157).
2. **В Termux или на ПК.** «Ключи подписи» → «Ключ выпуска в Termux или на ПК…»:
   имя, страна, файл и пароль — в готовую команду `keytool` в буфер обмена. Для
   Termux (bash, zsh) пароль — через окружение, а строка убирает себя из истории
   (D-160; в zsh с `share_history` или `inc_append_history` без `hist_ignore_space`
   — вставлять в bash). В
   PowerShell пароль в команду не встраивается — PowerShell сохраняет историю
   строк, — его спросит `keytool`. «Скопировать и открыть
   Termux» сразу открывает Termux (нужен JDK: `pkg install openjdk-21`). Приложение
   поля не хранит. Получившийся .p12 можно потом «Импортировать…» в приложение.
3. **Сборка release на ПК своим ключом.** В `~/.gradle/gradle.properties` (файл —
   только для своего пользователя): `dpai.release.storeFile`, `dpai.release.storePassword`,
   `dpai.release.keyAlias`, `dpai.release.keyPassword`; затем
   `./gradlew :shell:assembleRelease` (R8, D-156). Без этих свойств release
   подписывается отладочным ключом — только для замеров, не для раздачи.

Готовый APK можно подписать и отдельно — `sh tools/release/sign_apk.sh <apk> <ключ.p12>`
(пароль спрашивается без эха). Перед выкладкой —
`python3 tools/release/check_apk.py <apk> --cert <SHA-256 сертификата>`: подпись v2+,
не отладочный ключ, отпечаток совпадает, не `debuggable`, пакет и версия.

## Подпись

Тестовый APK явно помечается debug. Он не выдаётся за подписанный ключом
выпуска автора. Ключ выпуска остаётся у автора (D-12); сессия не получает
его и не генерирует замену. Несовпадение сертификатов установленного и
нового APK не устраняется удалением данных пользователя или переподписью.
Отпечаток сертификата публикуется с суммой APK для проверки.
