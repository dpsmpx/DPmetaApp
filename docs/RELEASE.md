# Сборки для устройств автора

D-104 разрешает ручную выкладку APK в GitHub Releases закрытого
`dpsmpx/DPmetaApp` по явному поручению автора. D-24 сохраняет личное
назначение; видимость репозитория, сайт и магазины не меняются.
Ветка apk_debug по D-33 остаётся отдельным каналом. GitHub Actions нет.
Вливание в main — только отдельным поручением (D-79).

## Перед выкладкой

1. Проверить, что репозиторий закрыт, версия/tag не заняты другой сборкой,
   рабочее дерево чистое, исходный коммит зафиксирован в описании.
2. Выполнить `tools/check/run.sh full --strict` с JDK 21 и Android SDK.
3. Взять объединённый APK `shell/build/outputs/apk/debug/shell-debug.apk`,
   проверить applicationId, versionName/versionCode, minSdk/targetSdk,
   `apksigner verify --verbose --print-certs` и SHA-256.
4. Подготовить русское описание изменений, ограничений, результатов
   проверок и путь к новым функциям; рядом с APK — SHA256SUMS.txt.
5. Создать draft release на точном исходном коммите, загрузить файлы,
   проверить имена/размеры/суммы и только после этого опубликовать dev
   как prerelease. Существующие assets не перезаписывать молча.
6. После публикации сверить tag/commit, prerelease, assets и их SHA-256
   через API или контрольное скачивание. Сохранить ссылку в описании PR.

## Подпись

Тестовый APK явно помечается debug. Он не выдаётся за подписанный ключом
выпуска автора. Ключ выпуска остаётся у автора (D-12); сессия не получает
его и не генерирует замену. Несовпадение сертификатов установленного и
нового APK не устраняется удалением данных пользователя или переподписью.
Отпечаток сертификата публикуется с суммой APK для проверки.
