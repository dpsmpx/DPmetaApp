# Современные актуальные подходы к оформлению сайтов (ноябрь 2026)

Документ-руководство для аудита и развития сайта экосистемы (dpsmpx.com и связанные страницы).
Составлен 6 ноября 2026 на основе анализа реальных сайтов, Core Web Vitals, WCAG 2.2, отраслевых обзоров и практики 2025–2026.

Цель — не «следить за трендами», а иметь устойчивый набор принципов, по которым можно оценивать и улучшать оформление.

---

## 1. Фундамент 2026: три обязательных столпа

Любой современный сайт начинается не с красивой сетки, а с трёх вещей, которые влияют на каждого посетителя и на ранжирование.

### 1.1. Performance-first (скорость — часть дизайна)

- **Core Web Vitals** (полевые метрики, 75-й процентиль):
  - LCP ≤ 2,5 с
  - INP ≤ 200 мс
  - CLS ≤ 0,1
- Дизайн-решения, которые бьют по метрикам (тяжёлые шрифты без `font-display`, изображения без размеров, layout shift от анимаций, длинные JS-задачи) — плохие решения, даже если выглядят «премиально».
- Практики:
  - Бюджеты на вес страницы и критический CSS/JS.
  - Изображения: AVIF/WebP, явные `width`/`height`, `loading="lazy"` (кроме LCP-элемента).
  - Переменные шрифты или системный стек + один display-шрифт.
  - Микро-анимации только на GPU (transform/opacity), с `prefers-reduced-motion`.

### 1.2. Accessibility-first (WCAG 2.2 AA — базовый уровень)

В 2026 accessibility перестала быть «позже». Европейский Accessibility Act уже действует, WebAIM фиксирует регресс (95,9 % топ-миллиона страниц имеют ошибки).

Семь опорных столпов, которые нужно закладывать в токены и компоненты:

1. **Контраст** — минимум 4,5:1 для обычного текста, 3:1 для крупного. Токены светлой и тёмной темы проверяются парами.
2. **Типографика** — масштабируемость (до 200 %), достаточный line-height, читаемые размеры.
3. **Фокус и клавиатура** — видимый focus-ring, логичный порядок, sticky-элементы не перекрывают фокус (WCAG 2.4.11).
4. **Движение** — уважение `prefers-reduced-motion`, отсутствие параллакса и scroll-jacking, который мешает.
5. **Ввод** — крупные зоны нажатия (≥ 44×44 px), поддержка разных способов ввода.
6. **Контент** — понятные заголовки, alt-тексты, понятные ошибки форм.
7. **Формы** — связанные label, понятные сообщения об ошибках, автозаполнение.

Оверлеи-«виджеты доступности» не считаются решением и часто вредят.

### 1.3. Mobile-first + адаптивность

Большая часть трафика — мобильный. Дизайн начинается с узкого экрана, потом расширяется. Bento-сетки и сложные layouts на мобиле схлопываются в одну колонку с чёткой иерархией.

## 2. Визуальные и layout-подходы, которые реально используют

По данным анализа ~1200 качественных сайтов (save.design, ноябрь 2026) и отраслевых обзоров:

### 2.1. Bento-сетки (модульные асимметричные блоки)

- Стали дефолтом для feature-секций, портфолио, дашбордов.
- Дают естественную визуальную иерархию (размер ячейки = важность).
- Реализация: CSS Grid (`grid-template-areas` или dense auto-flow), единые gaps 12–24 px.
- Ограничение: не больше ~8 ячеек в секции, на мобиле — одна колонка.

### 2.2. Типографика

- Один сильный display-шрифт + один текстовый (Inter по-прежнему самый частый, но растут независимые и variable-шрифты).
- Fluid type scale (clamp).
- Кинетическая типографика — дозированно, только если усиливает смысл, а не отвлекает.
- Читаемость важнее «вау».

### 2.3. Цвет и темы

- Тёмная тема — first-class citizen (параллельные токены с самого начала).
- Насыщенные «дофаминовые» акценты работают только на контрасте с нейтральной базой. Всё яркое = ничего не выделяется.
- Mesh-градиенты и мягкое свечение — в умеренных дозах.

### 2.4. Микро-взаимодействия и motion

- 150–300 мс, ease-out / spring.
- Только то, что помогает понять состояние (hover, press, loading, success/error).
- GSAP и Framer Motion — самые используемые, Three.js растёт для осмысленного 3D.
- Правило: если анимация не ускоряет понимание — убираем.

### 2.5. Остальное

- **Glassmorphism / Liquid Glass** — только на навигации, модалках, отдельных акцентах. Не на всём контенте.
- **3D / WebGL** — только когда показывает продукт или данные лучше, чем 2D. Иначе — лишний вес и accessibility-риск.
- **Органические формы, pixel/8-bit, Y2K** — нишевые, под бренд. Не универсальны.
- **AI-персонализация** — полезна на SaaS/лендингах с чётким намерением, но требует прозрачности и не ломает базовый UX.

## 3. Что сознательно пропускать или применять очень осторожно

| Приём | Почему осторожно |
|-------|------------------|
| Тяжёлый parallax / scroll-jacking | Ломает accessibility и ориентацию |
| Анимации ради анимаций | Ухудшают INP и CLS, отвлекают |
| Полный glassmorphism на карточках | Читаемость и контраст страдают |
| Декоративный 3D без функции | Вес + батарея + motion-sickness |
| Оверлеи accessibility | Не решают проблему, часто вредят |
| Равные по весу ячейки bento без иерархии | Просто сломанная сетка |

## 4. Практический чеклист для сайта экосистемы

Использовать при аудите и при новых страницах:

**Производительность**
- [ ] LCP / INP / CLS в зелёной зоне на реальных устройствах
- [ ] Изображения с размерами и современными форматами
- [ ] Критический CSS, отложенный некритичный JS
- [ ] `prefers-reduced-motion` уважается

**Доступность**
- [ ] Контраст AA на всех текстовых парах (светлая + тёмная)
- [ ] Видимый и неперекрываемый фокус
- [ ] Семантическая разметка + понятные label/alt
- [ ] Клавиатурная навигация без ловушек
- [ ] Крупные зоны нажатия

**Визуал и UX**
- [ ] Чёткая визуальная иерархия (размер, вес, цвет, положение)
- [ ] Единая система отступов (4/8 px)
- [ ] Одна основная CTA на экран/секцию
- [ ] Понятные empty/error/loading состояния
- [ ] Адаптив: мобиль → планшет → десктоп без потери смысла

**Контент и тон**
- [ ] Текст читается, а не «красиво свёрстан»
- [ ] Ссылки и кнопки говорят, что произойдёт
- [ ] Нет лишнего шума, который конкурирует с главным

---

## 5. Как использовать этот документ

1. При аудите сайта — проходить по чеклисту и фиксировать отклонения с приоритетом (HIGH = ломает performance/a11y/ядро UX).
2. При новых страницах — начинать с токенов (цвет, тип, spacing, motion) и компонентов, а не с «красивой картинки».
3. Тренды (bento, kinetic type, glass) применять только если они усиливают понятность и бренд, а не наоборот.

Документ живой: при существенном изменении практик или появлении новых жёстких требований (WCAG 3.0, новые Core Web Vitals) — обновлять.
