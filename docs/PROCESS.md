# Как ведётся DPvisualisation

Зачем каждое правило `CLAUDE.md` и откуда оно взято. Правила — в
`CLAUDE.md`, решения — в `docs/direction/DECISIONS.md`; здесь только
причины и происхождение. Общий способ ведения проектов экосистемы описан в
`DPmeta:docs/PRINCIPLES.md` (E-01…E-13): там собрано, что уже одинаково в
репозиториях автора, — DPvisualisation следует ему, а не изобретает свой.

## 1. Источник истины

| Правило | Зачем | Откуда |
|---|---|---|
| Журнал решений старше остальных документов; решение меняется новым решением со строкой в истории | при расхождении документов есть один ответ, а история показывает, почему ответ менялся | `DPmeta:docs/PRINCIPLES.md`, E-01 |
| О проекте прав его репозиторий, о связях — DPmeta | модель — производное знание; если бы она «знала лучше», стала бы ещё одним устаревающим источником | `DPmeta:M-02`, D-01 |
| `README.md` — не источник истины; блок состояния пишет скрипт | состояние в README отстаёт молча, если его пишут руками | E-13; `tools/check/run.sh --write-status` |
| Запрос автора сверяется с решениями до работы | автор решает, но молча исполненный запрос, противоречащий решению, ломает остальное | E-02 |

## 2. Работа сессии

| Правило | Зачем | Откуда |
|---|---|---|
| Проверить, нужна ли правка; готово — остановиться | не писать второе рядом с первым и не брать следующий этап без поручения | E-03 |
| Сбой инструмента — не сбой кода; красное до правки — не своё | упавшая команда без git, Node или клона — окружение, а не находка; чужая поломка в своей задаче не чинится | E-04 |
| Коммит и пуш после каждого куска, `WIP:` для незаконченного, PR по шаблону | сессия может кончиться в любой момент; следующая продолжает с ветки, а не начинает заново | E-08; хук `.claude/hooks/session-start.sh` |
| `TODO.md` — только незаконченное | список дел, где перемешано сделанное и нет, не читают | E-05 |
| В корне — только точки входа | всё остальное находится по каталогам; проверка `repo.layout` | E-06 |
| Тексты по-русски, идентификаторы латиницей | так во всей экосистеме; латинские номера не путаются с кириллическими | E-10, D-10 |

## 3. Проверки

`tools/check/run.sh` — одна команда для сессии и для автора (D-09):

- `static` (секунды) — после любой правки: журнал решений, ROADMAP и
  версия, свои номера и пути в документах, модель и её сборка, срез,
  публичная выжимка, раскладка репозитория, зависимости, секреты, команды
  выгрузки;
- `full` — перед вливанием: ещё тесты Python и просмотрщика, сборка и дым
  в Chromium (все узлы и потоки нарисованы, страница не шире окна при
  1366 и 390 px). Кроме зелёного `full`, ветка перед вливанием проходит
  независимую проверку без подтверждённых находок (D-21, ответ автора
  10 октября 2026).

Код возврата 3 — проверка не запускалась (нет Node.js, Python): это сбой
окружения, о нём говорится в PR, а не «зелёный» итог. GitHub Actions не
используются (E-07): проверку запускает сессия, итог — в описании PR.
Новое правило — вместе с образцом, который оно ловит, и чистым образцом
(`tests/test_check.py`): правило без образца может молча ничего не ловить.

## 4. Другие репозитории

Клоны других репозиториев только читаются (`DPmeta:M-04`): над ними
параллельно работают их сессии. Находка — в PR и `TODO.md` здесь; правку
делает сессия того репозитория по его правилам. Их код и внутренние
документы сюда не копируются (`DPmeta:C-05`) — модель ссылается на них
путём и номером.

## 5. Приватность и публичное

Модель раскрывает устройство закрытой экосистемы, поэтому полный
просмотрщик и срезы — только у автора (D-08), а на сайт уходит выжимка с
белым списком полей и отказом сборки при закрытом (D-15). Второй слой —
фильтр сайта (`SocialMediaImage:Д39`). Выгрузку на сайт делает только
SocialMediaImage после «да» автора (`SocialMediaImage:Д35`); здесь нет ни
команд выгрузки, ни ключей (D-14, проверка `security.commands`).
