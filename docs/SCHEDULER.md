# Планировщик и задачи

Задачи, их автомат, зависимости, приоритеты и выбор исполнителя. Код —
модуль `tasks` (этап 7); автомат задачи — `core`, `TaskLifecycle`
(этап 1). Планировщик детерминирован (D-22): одинаковые вход и время
дают одинаковое решение.

## 1. Автомат задачи

Состояния доски ТЗ, §41 и цепочка проверки ТЗ, §32 (D-23). Начальное —
`BACKLOG`; конечные — `DONE`, `FAILED`, `CANCELLED`.

| Из | В (обычный переход) |
|---|---|
| `BACKLOG` | `QUEUED`, `CANCELLED` |
| `QUEUED` | `READY`, `BLOCKED`, `BACKLOG`, `CANCELLED` |
| `READY` | `RUNNING`, `QUEUED`, `BLOCKED`, `CANCELLED` |
| `RUNNING` | `WAITING`, `BLOCKED`, `IMPLEMENTED`, `READY`, `FAILED`, `CANCELLED` |
| `WAITING` | `RUNNING`, `BLOCKED`, `READY`, `FAILED`, `CANCELLED` |
| `BLOCKED` | `READY`, `QUEUED`, `FAILED`, `CANCELLED` |
| `IMPLEMENTED` | `VERIFYING`, `COMPLETION_UNVERIFIED`, `CANCELLED` |
| `VERIFYING` | `VERIFIED`, `READY`, `COMPLETION_UNVERIFIED`, `FAILED`, `CANCELLED` |
| `VERIFIED` | `DONE`, `READY` |
| `COMPLETION_UNVERIFIED` | `VERIFYING`, `DONE`, `CANCELLED` |
| `DONE`, `FAILED`, `CANCELLED` | — |

Явные операции (не обычный переход, D-11):

| Операция | Переход |
|---|---|
| повтор упавшей задачи | `FAILED` → `QUEUED` |
| возобновление отменённой | `CANCELLED` → `BACKLOG` |
| переоткрытие выполненной | `DONE` → `BACKLOG` |

Смысл:

- `QUEUED` — принята в очередь, зависимости ещё не выполнены или нет
  ресурсов; `READY` — может быть назначена прямо сейчас;
- `RUNNING` → `READY` — сессия закончила ход без результата (предел,
  handoff): задача ждёт следующего исполнителя (ТЗ, §28);
- `IMPLEMENTED` — исполнитель сообщил о завершении; это заявление, не
  результат (D-23);
- `VERIFYING` → `READY` — проверка не прошла, нужна работа;
- `COMPLETION_UNVERIFIED` — проверку не удалось выполнить; `DONE` из
  него — только с записанным исключением политики (инвариант
  `docs/DATA_MODEL.md`, §5; запись исключения — этап 10).

## 2. Зависимости

Граф задач — DAG (ТЗ, §17, §42). Задача становится `READY`, только
когда все её зависимости в `DONE`. Цикл — `DEPENDENCY_CYCLE` с перечнем
задач цикла (ТЗ, §120); задачи цикла не планируются. Отношения: «зависит
от», «блокирует», «связана с» (не влияет на порядок).

## 3. Приоритет

Базовые уровни: `CRITICAL`, `HIGH`, `NORMAL`, `LOW`, `BACKGROUND` (ТЗ,
§18). Вычисленный ключ упорядочивания — кортеж, сравниваемый
лексикографически:

1. ручной приоритет пользователя, если политика его разрешает;
2. базовый уровень с поправкой на старение (ожидание дольше порога
   поднимает уровень, ТЗ, §84);
3. влияние на блокировку: сколько задач ждут эту;
4. приоритет проекта;
5. время постановки в очередь (раньше — выше);
6. `TaskId` — устойчивая развязка равенства.

Число в формулах не прячется за плавающей точкой: только целые и явные
пороги, чтобы порядок был воспроизводим.

## 4. Выбор исполнителя

Для задачи в `READY` планировщик выбирает аккаунт и target (ТЗ, §50,
§51, §85):

- только совместимые возможности (`requiredCapabilities`);
- аккаунт в `AVAILABLE`, без cooldown и rate limit; лимиты не обходятся
  (D-04);
- при равенстве — меньшая текущая нагрузка, затем меньше недавних
  ошибок, затем устойчивый ключ;
- давление ресурсов (память, CPU, батарея) откладывает задачи ниже
  порогового приоритета (ТЗ, §47);
- внутренние пределы: параллельные сессии, запуски в минуту, повторы на
  задачу, переподключения (ТЗ, §82).

## 5. Повтор и петли

Повтор — по классу причины в диагностике (D-05; ТЗ, §21):

| Класс | Действие |
|---|---|
| `RETRYABLE` (сеть, временная недоступность, rate limit) | повтор с паузой по политике, не больше `maxRetries` |
| `NON_RETRYABLE` (ошибка компиляции того же кода, неверный ввод) | без слепого повтора; `BLOCKED` или задача-исправление |
| `UNKNOWN` | один повтор, затем `BLOCKED` |
| аутентификация | запрос входа; аккаунт → `AUTH_REQUIRED` |
| конфликт слияния | `BLOCKED` до вмешательства или задачи-зависимости |
| испорченный worktree | процедура восстановления (`docs/RECOVERY.md`) |

Защита от петель (ТЗ, §22, §121): ключ «задача + хеш промпта + хеш
состояния + код отказа»; N повторов одного ключа — `LOOP_DETECTED`,
ресурсы дальше не тратятся. Так же ловятся: нет изменений файлов, нет
новых событий, повтор одной ошибки, повторные откаты, повторная смена
аккаунта.

## 6. Бюджет задачи

Для каждой задачи: максимальная длительность, повторы, продолжения и
(где провайдер поддерживает) расход — `--max-budget-usd` у Claude Code
CLI (ТЗ, §86; `docs/research/CLAUDE_CODE_CLI.md`).
