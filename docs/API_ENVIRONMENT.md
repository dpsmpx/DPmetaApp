# Окружение проекта в API-чате

D-183, DP_AI_Orcestrator:D-216. Можно попросить модель: «Проверь и настрой
окружение выбранного проекта, затем запусти его проверки». Модель готовит
план, человек подтверждает его в чате, результат возвращается в тот же ход.
Вводить команды или пакеты руками не требуется.

## Диагностика

`environment.inspect` читает базу Alpine и объявления проекта.
`declaredNeedsSatisfied=true` означает только наличие объявленных пакетов/путей. Поля `runtimeStatus=UNKNOWN`, `jvmStatus=NOT_PROBED`, `commandsProbed=false` и `projectBuildVerified=false` прямо показывают отсутствие запуска, не готовность JVM или сборки.

`environment.probe` запускает настоящие пробы: `project`, `java`, `jdk`,
`java_debug`, `memory`, `python3`, `c++`, `android_sdk` и другие варианты
из описания. Результат содержит реальные коды, stdout/stderr, хеш
захваченного вывода и отметку сокращения. Неизвестный код не заменяется нулём.
Пробы компиляции используют отдельные временные каталоги.

Успешная проба не подтверждает требования всех зависимостей проекта.
`projectBuildVerified=false` сохраняется до отдельной сборки и тестов.

## Исправления

Через `list_automations` / `describe_automation` / `run_automation`:

- `environment.apk.add`, `.fix`, `.repair`, `.upgrade_some`: прежние команды
  Alpine, снимок и живые пробы установленных основных инструментов. Если
  пакет поставлен, а JVM не стартует, план не считается проверенным.
  Восстановление повреждённых пакетов показывается в том же плане.
- `environment.android_sdk`: закреплённые commandline-tools, нужный API и
  build-tools проекта. Лицензию принимает человек отдельным флажком.
  Проверяются JVM, android.jar именно запрошенного API, нужная версия
  build-tools, запуск aapt2 и, при запросе NDK, clang. SDK обнаруживается процессами
  автоматически; явный путь человека сильнее. Официальные Linux aapt2/NDK
  не становятся совместимыми с arm64 от одной загрузки: требуется проверенная
  сборка для host или другой target.
- `environment.command`: JSON-массив argv, предел ожидания 1…3600 секунд.
  Для shell его надо назвать явно, например `["/bin/sh","-c","..."]`.
  `apk` запускается отдельным argv/инструментом: его обход Android требует
  proot без `/proc`. Общая команда требует опасного подтверждения с именем
  проекта. Proot не песочница; область доступа указана до подтверждения.

Для восстановления при нечитаемой базе общая команда может запросить
`snapshot=skip`. Человек видит это до опасного подтверждения. Обычные
установки не продолжаются при отказе записи снимка. Снимок пакетов не
является полной копией файлов произвольной команды.

Модель не принимает лицензию и не подтверждает действие сама. Одобрение
одноразовое, на точный план/контекст, с ограниченным сроком. Отклонённый
план не спрашивается повторно в том же ходе. По умолчанию подтверждения
обязательны; исключение — включённый человеком «Полный доступ» чата.

Изменения выполняет прежний worker, с долговечной паузой, проверкой
занятости/черновиков и историей. Bootstrap не требует исправных Git и Java.
Перезапуск не повторяет команду; отмена останавливает только свой процесс.
Выборы сохранённых профилей пользователя не перезаписываются.

## Режим «Полный доступ» проектного API-чата

По DPmetaApp:D-184 и DP_AI_Orcestrator:D-218 человек может включить
режим только в конкретном проектном API-чате: нажать кнопку, прочитать
красное предупреждение, ввести точное имя проекта и пройти системную
проверку PIN/биометрии. После этого прежний брокер выдаёт одобрение
каждого точного Proposal без нового окна. Это не самоодобрение модели:
API-инструмента для включения режима нет.

Режим сохраняется после перезапуска до ручного отключения, но только для
того же чата, проекта, корня и конфигурации target. При отзыве
отменяется текущий ход; уже выполненные действия не откатываются.
Удаление чата или профиля снимает доступ. Отдельное принятие лицензии
Android SDK остаётся обязанностью человека. Правила защиты секретов
Keystore не отменены. Режим не расширяет каталог инструментов,
не повышает привилегии Android и не снимает ограничений SELinux.

## Точная причина отказа CHECK/BUILD

В Linux приложения профиль с явным Gradle/JVM-шагом (`gradlew`, `sh gradlew`,
`gradle`, `java`, `javac`, `mvn`) перед `prepare` автоматически запускает
фиксированную пробу `java -Xmx128m -version`. При отказе исполняемой памяти
проводится также проба `memory` (при наличии Python). Если JVM не стартует,
Gradle не запускается, в ответе — `PRECHECK_FAILED` и рекомендация SSH-target.
Проверка не меняет SELinux и не обещает локальную сборку там, где запрещён
`execmem`. Ручные профили для других стеков работают по прежним правилам.

Если проверка перед исполнением не прошла, API возвращает
`phase=PREFLIGHT`, `commandStarted=false` и причину в `note`:
ошибку Git, несовпадение фактической и выбранной ветки, отсутствие HEAD
или конфликты. Это не означает, что JVM или Gradle уже запускались.
`phase=EXECUTION` означает попытку запуска шага, коды и вывод — в
`evidence`.

Если JVM не работает из-за запрета исполняемой памяти в домене Android,
используйте подключённый SSH execution target с работающей JVM и SDK
для сборки APK. Само наличие Termux на телефоне не даёт приложению
доступа к процессам Termux; target меняет человек.

## Ошибка исполняемой памяти Java

`Failed to mark memory page as executable - check if grsecurity/PaX is enabled`
возникает при отказе mprotect на пробной странице, а не после обнаружения
PaX. Сначала нужны `java_debug` и `memory`: errno, размер страницы и
результаты RW→RWX/RX. Без этого смена ядра/paxctl не являются подтверждённым
решением. Источник — [датированная проверка](../dpai/docs/research/2026-11-22-jvm-executable-memory.md).

Хостовые тесты не заменяют Android/proot. Приёмка телефона — в TODO.md.

## Termux как SSH-target для APK

Практическая настройка Termux на том же телефоне, проверка SSH-host-key, хеша
архива агента, нативного AAPT2, SDK/NDK и ограничений Android описана в
[ANDROID_BUILD_TARGETS.md](ANDROID_BUILD_TARGETS.md). Это обычный POSIX SSH-target,
не возобновление удалённого D-202 Termux bridge. Кнопка «APK-среда» проверяет
запуск программ и наличие SDK именно через SSH; полноценная сборка и подпись
подтверждаются отдельно.

## Единое окно чатов и выбор target

Вкладка «Чаты» объединяет API-разговоры и терминальные сессии задач,
сохраняя их прежние хранилища и права. Внутри API-чата кнопка
«Подключить проект / target» выбирает готовую пару или открывает
штатные мастера создания. Передача другому ИИ требует действия
человека, а подробная матрица — в
[CHAT_WORKSPACE.md](CHAT_WORKSPACE.md).
