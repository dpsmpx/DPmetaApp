# Окружение проекта в API-чате

D-183, DP_AI_Orcestrator:D-216. Можно попросить модель: «Проверь и настрой
окружение выбранного проекта, затем запусти его проверки». Модель готовит
план, человек подтверждает его в чате, результат возвращается в тот же ход.
Вводить команды или пакеты руками не требуется.

## Диагностика

`environment.inspect` читает базу Alpine и объявления проекта.
`declaredNeedsSatisfied=true` означает наличие объявленных пакетов/путей,
а не готовность JVM или всей сборки.

`environment.probe` запускает настоящие пробы: `project`, `java`, `jdk`,
`java_debug`, `memory`, `python3`, `c++`, `android_sdk` и другие варианты
из описания. Результат содержит реальные коды, stdout/stderr, хеш
захваченного вывода и отметку сокращения. Неизвестный код не заменяется нулём.
Пробы компиляции используют отдельные временные каталоги.

Успешная проба не подтверждает требования всех зависимостей проекта.
`projectBuildVerified=false` сохраняется до отдельной сборки и тестов.

## Исправления

Через `list_automations` / `describe_automation` / `run_automation`:

- `environment.apk.add`, `.fix`, `.repair`, `.upgrade_some`: прежние команды
  Alpine, снимок и живые пробы установленных основных инструментов. Если
  пакет поставлен, а JVM не стартует, план не считается проверенным.
  Восстановление повреждённых пакетов показывается в том же плане.
- `environment.android_sdk`: закреплённые commandline-tools, нужный API и
  build-tools проекта. Лицензию принимает человек отдельным флажком.
  Проверяются JVM, android.jar именно запрошенного API, нужная версия
  build-tools, запуск aapt2 и, при запросе NDK, clang. SDK обнаруживается процессами
  автоматически; явный путь человека сильнее. Официальные Linux aapt2/NDK
  не становятся совместимыми с arm64 от одной загрузки: требуется проверенная
  сборка для host или другой target.
- `environment.command`: JSON-массив argv, предел ожидания 1…3600 секунд.
  Для shell его надо назвать явно, например `["/bin/sh","-c","..."]`.
  `apk` запускается отдельным argv/инструментом: его обход Android требует
  proot без `/proc`. Общая команда требует опасного подтверждения с именем
  проекта. Proot не песочница; область доступа указана до подтверждения.

Для восстановления при нечитаемой базе общая команда может запросить
`snapshot=skip`. Человек видит это до опасного подтверждения. Обычные
установки не продолжаются при отказе записи снимка. Снимок пакетов не
является полной копией файлов произвольной команды.

Модель не принимает лицензию и не подтверждает действие сама. Одобрение
одноразовое, на точный план/контекст, с ограниченным сроком. Отклонённый
план не спрашивается повторно в том же ходе. Авторежим без подтверждения
не включён.

Изменения выполняет прежний worker, с долговечной паузой, проверкой
занятости/черновиков и историей. Bootstrap не требует исправных Git и Java.
Перезапуск не повторяет команду; отмена останавливает только свой процесс.
Выборы сохранённых профилей пользователя не перезаписываются.

## Ошибка исполняемой памяти Java

`Failed to mark memory page as executable - check if grsecurity/PaX is enabled`
возникает при отказе mprotect на пробной странице, а не после обнаружения
PaX. Сначала нужны `java_debug` и `memory`: errno, размер страницы и
результаты RW→RWX/RX. Без этого смена ядра/paxctl не являются подтверждённым
решением. Источник — [датированная проверка](../dpai/docs/research/2026-11-22-jvm-executable-memory.md).

Хостовые тесты не заменяют Android/proot. Приёмка телефона — в TODO.md.
