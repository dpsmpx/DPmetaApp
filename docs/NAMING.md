## 2. Как писать прежние имена

Рекомендация (M-03) — обобщение того, что уже решено в `Galdhold:Р20` и
`DPlang:Р38` для них самих; в других репозиториях действует, только когда
они примут её своим решением:

1. **Новый текст — нынешним именем.** О другом проекте пишется его
   нынешнее имя и нынешний репозиторий: Galdhold, `dpsmpx/Galdhold`;
   DPlang, `dpsmpx/DPlang`.
2. **Запись о прошлом — как было.** История решений, вехи и
   `CHANGELOG`, аудиты и срезы на дату, факты (DPprofile), архив, записи
   канала-дневника не переписываются ради нового имени.
3. **При первом упоминании можно связать имена:** «Galdhold (прежде
   VoxelRPG)».
4. **Машинные ключи не следуют за именем.** Устойчивый тег или ключ
   (`DPprofile:D-03`, `voxelrpg`) лучше имени, которое меняется; если
   ключ всё же содержит имя, смена — решением владельца ключа (RISK-04).
5. **Ссылки — на нынешний адрес.** GitHub перенаправляет старый адрес
   репозитория, но перенаправление пропадает, если старое имя займут.

Где прежние имена ещё стоят в настоящем времени — `docs/SYNC_QUEUE.md`
(SQ-01, SQ-03, SQ-09) и последний срез `tools/xref.py` в `docs/reports/`.

## 4. Ссылки между репозиториями

Наблюдение: две формы уже приняты и не противоречат друг другу —

- **номер:** `Проект:номер` — обязательна в DPprofile («Решения других
  репозиториев пишутся с префиксом репозитория (`Galdhold:Р12`,
  `DPpass:D-24`)», `DPprofile:docs/direction/DECISIONS.md`);
- **путь:** `Проект:путь` — `DP-Verify:V-17` (`DPpass:docs/PROCESS.md`).

SocialMediaImage и DPlearn пишут имя и номер через пробел («Galdhold
Р18», «V-07 DP Verify») — однозначно, но не единообразно.

Рекомендация (C-06): в новых текстах — `Проект:номер` и `Проект:путь`
с нынешним именем проекта. Такие ссылки сверяет `tools/xref.py`; DP-Verify
сверяет только имя проекта, но не сам путь (`DP-Verify:V-17`).

## 5. Общие слова с разным смыслом

Одно слово в разных репозиториях значит разное. Внутри репозитория
смысл задан им самим; здесь — чтобы не перепутать при переходе.

| слово | где | что значит |
|---|---|---|
| **факт** | DPprofile | атомарное утверждение о прошлом с источником на коммите; не переписывается (`DPprofile:D-04`…`DPprofile:D-06`) |
| | SocialMediaImage | публичное утверждение класса `FACT` с источником, датой и сроком перепроверки (`data/facts/facts.yaml`) |
| | DP_game_market_analytic_system | вычисленный из наблюдений факт о рынке (`docs/ARCHITECTURE.md`, слой «Validated facts») |
| **hostcheck** | Galdhold, DPpass | у каждого своя команда проверок `tools/hostcheck/run.sh` с разными ключами (`--brief`/`--affected` и `--quick`/`--full`) |
| **этап** | все | у каждого свой план и своя нумерация; номера этапов разных репозиториев не сравниваются |
| **проверка** (поле решения) | DPpass, DPprofile, DPlearn, DP-Verify, DPmeta | чем ловится отступление от решения; в журналах Galdhold, DPlang и SocialMediaImage такого обязательного поля нет |
| **полигон** | Galdhold | отдельный потребитель движка для проверки его независимости (`Galdhold:Р5`) |
| | DPlearn | пилотный домен `examples/pilot` (`DPlearn:D-17`) |
| **метки `М`/`С`/`Т`/`К`** | DPlang, DP-Verify, DPlearn | сложность задачи: мелкая, средняя, тяжёлая, капитальная — одинаково во всех трёх |
