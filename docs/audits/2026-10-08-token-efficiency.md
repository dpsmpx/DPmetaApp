# Аудит расхода контекста и токенов — 8 октября 2026

Задача автора: слой экономии контекста и токенов — больше полезной
работы на единицу расхода подписки, без обхода пределов провайдера и без
потери нужной для решения информации. Аудит — по коду `e75e6c5` и
`claude --help` Claude Code 2.1.294; решение — D-40, устройство —
`docs/EFFICIENCY.md`.

## 1. Как устроено

- **Оркестрация.** `Orchestrator.tick` → `launch`: аренда слота
  (`Accounts`), сессия (`Sessions`), рабочее дерево (`GitService`),
  версия контекста (`ContextAssembler`), prompt (`PromptRenderer`) →
  `ClaudeRequest` → `SessionDriver` → `ClaudeCodeCliRunner` → агент
  target → `claude -p --output-format stream-json`. `poll` разбирает поток
  (`ClaudeTurnAssembler`), `react`: завершён — проверка (`CompletionFlow`),
  коммит, `DONE`; прерван — handoff и `--resume` той же сессии провайдера;
  упал — повтор по классу причины (D-05).
- **Контекст и память.** `ContextBundle` (`dpai.context`): источники
  уровней `GLOBAL` … `HANDOFF`, предел 200 000 знаков, порядок уровней —
  и порядок вывода, и порядок отбора; не вошедшее — `CONTEXT_TRUNCATED`.
  Источники даёт `ProjectConfig.sources`, но ни `cli`, ни `android` их не
  задают: на деле контекст хода — цель и handoff. Долгая память — документы
  проекта и `CLAUDE.md`, которые Claude Code читает сам; память задачи —
  версия контекста и handoff в `DocumentStore`; память сессии — сессия
  провайдера (историю сжимает Claude Code); эфемерное — события запуска в
  журнале агента (D-37).
- **Модель.** Claude Code CLI. `ClaudeRequest.model` есть, но оркестратор
  его не задаёт: все задачи — на модели и усилии по умолчанию аккаунта.
- **Инструменты.** Инструменты исполняет Claude Code внутри хода; их
  вывод в prompt оркестратор не кладёт. Свой вывод оркестратора — проверка
  (`Verifier`: 20 последних строк шага), Git, handoff.
- **Кеш.** Кеша результатов нет; кеш prompt — у Claude Code.
- **Учёт.** `ClaudeStreamParser` разбирает `usage.input_tokens`,
  `output_tokens` и `total_cost_usd`, но `SessionDriver` их отбрасывает: в
  журнал не попадает ни одной цифры расхода. `cache_*`, `thinking_tokens`,
  `modelUsage` (модель, окно), `num_turns`, длительности и
  `subagent_stats` не разбираются вовсе.

Уже есть и остаётся: идемпотентные ключи сессии, запуска агента, handoff
и одобрения (повтор и гонка не дают второго хода); повторы по классу
причины и защита от петель (`loopKey`); `--max-budget-usd` из политики
задачи; пределы подписки из `rate_limit_event` — слот у предела не
арендуется (D-30); детерминированный отбор контекста и сжатие истории без
модели (`Compaction`); сегментированный журнал.

## 2. Потери

| # | Потеря | Чем плоха |
|---|---|---|
| W1 | Проверка не прошла → задача снова `READY` → новая сессия провайдера с тем же prompt, без того, что упало | исполнитель заново изучает репозиторий, снова заявляет «готово»; до порога петли — ходы впустую, страдает и качество |
| W2 | Продолжение `--resume` шлёт весь контекст заново | источники уже в истории сессии провайдера |
| W3 | Продолжение всегда `--resume`, как бы ни выросла история | каждый ход перечитывает всю историю: кеш дешевле, но не бесплатен и идёт в пределы подписки |
| W4 | Каждый ход — в своём рабочем дереве | системный prompt Claude Code различается каталогом и `git status`: межсессионный кеш prompt не срабатывает, на каждом старте — запись кеша (9 844 токена в образце `success-structured.jsonl`, запись на час) |
| W5 | Одна модель и одно усилие на всё | простое идёт по цене сложного; эскалации нет |
| W6 | Расход не записывается | нельзя ни измерить, ни сравнить |
| W7 | Доказательство проверки — 20 последних строк | у Gradle это «BUILD FAILED … Run with --stacktrace», а не ошибка |
| W8 | Handoff пуст: изменённые файлы, проверено, упало | всё это известно локально (`git status`, отчёт проверки) |
| W9 | Под давлением предела первым выпадает handoff | уровень `HANDOFF` последний в порядке отбора |
| W10 | Та же цель, поставленная дважды (двойное нажатие, повтор из оболочки) | второй ход с той же работой |
| W11 | Переполнение контекста у провайдера — обычный отказ | повтор того же объёма вместо продолжения с меньшим |

Неприменимо в этой архитектуре: поиск по базе знаний (RAG) — источников
нет, Claude Code ищет сам (`ripgrep`, glob); история диалога — у Claude
Code; субагентов у оркестратора нет — есть параллельные сессии
(ограничены `maxSessions` и пересечением файлов) и субагенты внутри
Claude Code (инструмент `Agent`).
