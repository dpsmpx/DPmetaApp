# Состав DP_IDE: что оставить, что убрать, что оставить частично (16 ноября 2026)

Срез на дату. Основание — слово автора 16 ноября 2026: «Проект планируется как
коммерческий, а не только личный, и в нём должны быть полностью реализованы все
функции разработки, основной упор на разработку с ИИ, но и полноценная
полуавтоматизированная IDE для ручной разработки также предусмотрена как
вторичный функционал после ИИ. На момент окончания полной разработки ничего
лишнего в проекте быть не должно, в том числе того, что не влияет
непосредственно на эффективность разработки и не улучшает процесс. Это больше
не мой личный пульт управления моими проектами. Это конкретно полноценная
мобильная студия разработки».

Критерий каждой строки: **делает ли это разработку (прежде всего с ИИ, затем
ручную) эффективнее для любого пользователя студии**. Привязка к проектам,
репозиториям, устройствам и процессу автора — не критерий пользы.

Здесь ничего не удаляется: это список для решения автора. Код и подсистемы
меняются только после новых решений (CLAUDE.md, «Запросы автора»).

## 2. `dpai/` — что оставить и что убрать

**Оставить** (польза для разработки прямая): `core`, `testkit`, `storage`,
`security`, `execution`, `accounts`, `git`, `contexts`, `tasks`, `sessions`,
`verification`, `monitoring`, `notifications`, `connectors`, `providers`,
`localai`, `lsp`, `orchestrator`, `ui`, `jsch`, `terminal`, `android`,
интеграционные тесты подсистемы; модуль `analytics` (пуст) — наполнить по ТЗ
автоматизации, §11, §18 (стоимость ИИ).

**Частично:**

| Что | Оставить | Убрать |
|---|---|---|
| `files` (`DP_AI_Orcestrator:D-99`) | Файлы проекта и вложения в чат ИИ | Копии произвольных папок телефона с двусторонней синхронизацией — если не нужны как документы для ИИ |
| `sync` (`DP_AI_Orcestrator:D-107`) | Зашифрованная копия состояния студии | Привязку только к приватному репозиторию GitHub — как единственному месту копии (оставить вариантом) |
| Общая папка инструментов на target (`DP_AI_Orcestrator:D-122`, `DP_AI_Orcestrator:D-125`, `DP_AI_Orcestrator:D-175`) | Общий механизм «инструменты на target» | Особое обслуживание DP-Verify (D-89): это инструмент автора; оставить шагом проверки, если пользователь сам его подключил |
| Termux как target (`DP_AI_Orcestrator:D-26`, `DP_AI_Orcestrator:D-46`, `DP_AI_Orcestrator:D-54`) | SSH-target на ПК | Termux-target, запуск `sshd` Termux, восстановление командой в Termux, мост Termux пульта (F-41, F-42) — после проверки, что Linux в приложении закрывает всё; версия Termux в Google Play устарела |
| `cli` подсистемы (`dpai`, `DP_AI_Orcestrator:D-47`) | Если ИИ в госте управляет студией через канал | Если пользы нет — убрать |

**Убрать:**

| Что | Почему |
|---|---|
| `ecosystem` и «Экосистема» (`EcosystemPlan`, `EcosystemRun`, `AutoEcosystem`, `EcosystemPane`, `EcosystemAuto`; `DP_AI_Orcestrator:D-106`, `DP_AI_Orcestrator:D-114`) | Прогон по экосистеме автора из реестра DPmeta |
| `android-app` (отдельная сборка «AI», `DP_AI_Orcestrator:D-103`) | Продукт один, APK один (`shell`) |

## 3. `app/` — пульт

Пульт строился как личный пульт экосистемы автора. Часть его функций —
обычная работа с репозиториями, она нужна студии; часть — про процесс и
проекты автора.

**Перенести в студию** (как раздел «Проекты»/GitHub, без «пульта»):
список PR с фильтрами и карточка, комментарий и слияние по уровням
(D-80), ветки, issues, правка файлов через ветку и PR (F-69), клоны,
«Опубликовать на GitHub», чат «Спросить Claude» (F-21) — о проекте пользователя, а не об экосистеме автора, маршруты Claude
Code (F-22), шаблоны поручений (F-23), отчёты Usage & Cost по
Admin-ключу (F-17…F-19), вход по PIN и отпечатку, резервная копия и
восстановление, уведомления о событиях PR и CI, виджет — по состоянию
студии (задачи, ходы, сборки), а не экосистемы.

**Убрать:**

| Что | Почему |
|---|---|
| «Сводка» с готовностью проектов по флажкам `ROADMAP.md` и метриками экосистемы (`core/metrics`, `Readiness`, `Rules` с `HUMAN_AUTHORS = dpsmpx`) | Процесс автора (ROADMAP, DECISIONS, TODO); у пользователя студии его нет |
| Реестр DPmeta и всё, что из него читается (`core/sync` — читатели реестра, `RegistryFormat`, `DpmetaDocs`) | Карта экосистемы автора |
| Карта проектов `ProjectMap` с ролями проектов автора | Проекты автора |
| Панели проектов `config/projects/*.toml` (DP-Verify, DPmeta, DPpass, SocialMediaImage, аналитика рынка) | Проекты автора |
| Записи реестра команд под проекты автора (`config/commands.toml`) | Механизм остаётся и входит в реестр автоматизаций (D-172); записи — нет |
| Слушатель уведомлений других приложений (F-57) | Не разработка; разрешение на чтение чужих уведомлений — чувствительное в правилах Google Play |
| Мост Termux пульта (F-41, F-42) | См. §2, Termux |
| Мгновенный канал ntfy (F-55, F-56) | Частично: оставить, если нужен push о долгих ходах ИИ; иначе — убрать |

## 5. Дубли: не убирать, а свести в одно

Работа «ничего лишнего» касается и двойных механизмов, которые выросли из
двух проектов (пульта и подсистемы «AI»):

1. Уведомления: `core:notify` и `notifications` подсистемы.
2. Git: `core:git` (клоны пульта) и `git` подсистемы (рабочие деревья).
3. GitHub: `core:github` (REST) и `gh` на target (`DP_AI_Orcestrator:D-108`).
4. Уровни действий: `core:actions` и одобрения `security`.
5. Реестры шагов: реестр команд, ручные профили, профили проверки, команды
   окружения — уже решено свести (D-172).

## 7. Что нужно коммерческой версии кроме удаления

Не убрать, а сделать (каждое — отдельным решением):

1. **Ничего личного в сборке**: имена, владелец `dpsmpx` в правилах, метка
   `from-dpmetaapp`, адреса и проекты автора — в данных пользователя или
   нигде. Сейчас привязка к экосистеме автора есть в 13 файлах `core`, 5 —
   `app`, 9 — `dpai/android`, 3 — `dpai/orchestrator`.
2. **Языки интерфейса** — для магазинов нужен хотя бы английский.
3. **Лицензии поставляемого**: proot — GPL-2.0, статическая сборка в APK
   (`DP_AI_Orcestrator:D-115`) требует открыть исходники этой сборки;
   minirootfs Alpine — пакеты со своими лицензиями; экран «О программе» уже
   перечисляет зависимости (F-50).
4. **Политика конфиденциальности и раздел Data safety** Google Play: что
   хранится на телефоне, что уходит в сеть (провайдеры ИИ, GitHub, зеркало
   Alpine, Hugging Face).
5. **Вход для любого пользователя**: GitHub по устройству, ключи API и входы
   CLI исполнителей — уже общие; проверить, что нигде не ждут учётных
   данных автора.

4. Перестройка пульта в раздел студии (§3), сведение дублей (§5) — вместе с
   этапом 1 ТЗ автоматизации (реестр, D-172).
5. Коммерческие требования (§7).
