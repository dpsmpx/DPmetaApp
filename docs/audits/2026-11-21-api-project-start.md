# Быстрый старт API-разработки: отдельная проверка

21 ноября 2026. PR #229 поверх PR #228 (`a60f518a`). Проверяющий —
сама сессия отдельным проходом, без агента (D-163). Объём — D-182 и
`DP_AI_Orcestrator:D-214`, а не весь план автоматизации студии.

## Настройка и совместимость

Просмотрены пути ApiQuickStartWizard → ApiProjectRuntime → ApiQuickStart,
ModelsStore и прежние экраны профилей/targets. Клоны пульта и свои проекты
обнаруживаются в общей папке `~/projects`: один уровень или владелец/имя.
Ветка берётся из символического HEAD. Ручных полей target/путей в мастере
нет; повторная подготовка сохраняет id и настройки прежнего проекта.
Отсоединённый или повреждённый HEAD не усыновляется автоматически.
Обычные чаты и CLI/SSH остаются прежними путями; API-ключ не требует входа
в CLI и туда не передаётся. Подготовка не запускает платный ход.

Модели берутся из каталога провайдера: явный запрет tools и известные
специализированные модели исключаются. Неизвестная поддержка tools не
выдаётся за доказанную: возможен отказ сервера с диагностикой. Старый
loopback-профиль llama.cpp проверяет готовность своего процесса до отправки
ключа на порт, как обычный чат (T18). Свой совместимый сервер без ключа
остаётся доступен через сохранённый расширенный профиль.

## Файлы, команды и восстановление

Просмотрены ApiProjectFiles, WorkspaceWriteGate, WorkspaceChanges,
WorkspaceChangeStore, DemoModel, Drafts и уведомления CodeService/LSP.
Дерево ограничено выбранным корнем с проверкой предков и ссылок. Служебные
каталоги и известные файлы секретов скрыты; произвольный секрет внутри
исходника этим списком не распознаётся. Пользователь видит согласие на
отправку кода выбранному провайдеру до первого сообщения.

Создание требует отсутствия файла, замена/удаление — суммы прочитанных
байтов. Запись идёт через общий замок, проверяет проект, занятость и
черновики; до изменения сохранены зашифрованные before/after и маркер
паузы. Ошибка чтения не трактуется как отсутствие. Откат не затирает
неизвестный внешний текст; это восстановимая запись, не обещание CAS ОС.
v1-копии читаются с прежним AAD; новые v2 различают отсутствие и пустоту.
Чаты v1 не получают доступ к проекту; v2 хранит явный id.

CHECK/BUILD используют прежний worker и долговечную паузу ручных профилей.
Свежий id завершения отличает результат этого запуска от старого; ранний
отказ подготовки не выдаётся за успех. Нет инструмента произвольного shell.
При отмене/таймауте запрашивается остановка, пауза остаётся до подтверждения.
Перезапуск не повторяет API-ход: чат получает явную отметку прерывания.
Сессия SSH закрывается при любом выходе. Создание/замена/удаление сообщают
языковым службам правильный тип события; перечитывается редактор.

## Протоколы провайдеров

Anthropic сохраняет прежний поток и подписи рассуждений; совместимые API —
Chat Completions, Gemini — Function Calling. Официальный OpenAI использует
Responses: store=false, возврат opaque reasoning, function_call_output по
call_id. В Responses strict=false задан явно для необязательных полей.
Gemini допускает отсутствующие args и возвращает лишь настоящий id сервера.
Весь набор id проверяется до первого эффекта; отказ/обрыв не исполняет
инструменты, отмена проверяется между ними, неизвестный инструмент возвращает
ошибку. Есть предел циклов и размера результата. Неизвестный расход остаётся
неизвестным, ключ не включён в тело HTTP или историю чата.

## Подтверждение и приёмка

Сценарный тест проходит обнаружение клона без targets, автоматическую
привязку, реальные read/write через синтетический HTTP и отмену записи.
Второй сценарий подтверждает отказ записи занятому проекту. Отдельно
проверены создание/удаление/восстановление, старые форматы, протоколы,
отмена и LSP Deleted. Итоги общих прогонов и проверенная голова — в PR #229.

Блокирующих находок в этом проходе после исправлений не осталось.
На телефоне ещё нужны реальный ключ/провайдер, интерфейс, фон, отказ места,
остановка и восстановление. Живых платных API-вызовов в облачной сессии нет.
Приёмка записана в TODO.md. Автоматический SDK/все библиотеки и вся
Automation Engine не входят в эту задачу; прежние настройки доступны.
