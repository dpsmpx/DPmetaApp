## Полномочия

Прямой вызов разрешён явным списком подключённых обработчиков, а не
числом уровня или знанием id. Внешний API не содержит метода одобрения.
Окно связано с конкретным чатом/проектом; ответ проверяет nonce,
для опасной команды — имя проекта, для SDK — отдельное согласие с
лицензией. Одноразовое одобрение core.security связывает канонический
профиль, проект, root, target, ревизию и режим снимка, истекает за пять
минут и потребляется перед подготовкой исполнения. Target и доступ к
дереву проверяются повторно. Авторежим не включён.

Общие команды получают расширенный доступ только через опасное окно:
Proot не является песочницей. Пользователь видит полные argv и границы
снимка. Ключ API не добавлен в окружение дочернего процесса. Обычные
файловые инструменты сохраняют ограничение каталогом проекта.

## Исполнение и отказы

Используются прежние ManualProfiles, AgentClient, LongJobs.GUEST,
черновики, долговечная пауза и история. Bootstrap не требует работающего
Git. Снимок снимается под паузой; ошибка записи останавливает запуск,
кроме явно подтверждённого восстановления snapshot=skip. Параметры
пользовательских профилей не меняются. Скрипты не проходят подстановку
параметров ручного профиля: shell-переменные остаются буквальными.

Отмена/таймаут имеют собственный сигнал; глобальный stop не используется.
Результат принимается только с id собственного подготовленного запуска;
ранний отказ не принимает предыдущий finished. Перезапуск не создаёт
повторного start. Эти свойства проверяются существующими регрессиями и
новыми тестами отмены, одобрения и реального агента.

Обзор выявил ложную готовность SDK при проверке любой платформы вместо
запрошенной. Исправлено: проверяются точные API/build-tools и работающие
нативные инструменты; тест включает другую платформу, несовместимый
aapt2 и отсутствующий NDK. Успех apk с последующим отказом JVM завершает
план ошибкой, что проверено настоящим исполнителем с внешними командами
из тестовых образцов. Наличие пакета не выдаётся за готовую сборку.

Блокирующих находок после исправлений нет. Причина mprotect на телефоне
ещё не установлена: хостовые тесты не воспроизводят Android SELinux.
Приёмка диалога, фона/перезапуска и настоящих пакетов — в TODO.md.
