# Полноценная мобильная IDE

Требования автора — D-101, Python добавлен по D-103. Базовый редактор dev.26 и рабочий экран
с профилями dev.28 — первые части студии, не готовая полноценная IDE.

Основной режим — автономно на телефоне после установки инструментов
и зависимостей. Redmi Note 13 4G, 8 ГБ ОЗУ, бюджет студии 20 ГБ;
ПК дополнительно. Размеры индексов/SDK, память и задержки измеряются на
этом устройстве; 20 ГБ — общий бюджет, не размер обязательного APK.
Python — исходники .py/.pyi/.pyw и контекст выбранного интерпретатора,
виртуального окружения и зависимостей на target.
C++ — сначала Galdhold и его реальная сборочная конфигурация.
Kotlin — JVM, Android/Compose и Multiplatform, с контекстом Gradle,
зависимостей, source sets и платформенных API. Сборка конкретной KMP-цели
выполняется на target с подходящими SDK и инструментами её платформы.

| Этап | Результат и критерий |
|---|---|
| 1. Восстановление работы | Текст, выделение и исходный снимок переживают перезапуск; исходные файлы сохраняются явно, внешнее изменение даёт конфликт |
| 2. Поле редактора | Подсветка C++/Kotlin/Python, большие файлы, номера строк, отступы/скобки, несколько файлов и мобильная/аппаратная клавиатура без заметных задержек |
| 3. C++ | Семантическое дополнение по реальным флагам сборки, диагностика, параметры, определения/использования, переименование, исправления и форматирование; проверка на Galdhold |
| 4. Kotlin | Те же функции с корректными Gradle-зависимостями и контекстом JVM/Android/KMP; проверка на проекте приложения |
| 4а. Python | Семантическое дополнение, диагностика, параметры, определения/использования, переименование и форматирование с учётом выбранного интерпретатора, окружения и зависимостей |
| 5. Рабочий цикл | Многошаговые сборка/проверка/run, ошибки с переходом в код, артефакты/APK, logcat и отладка по профилю |
| 6. Интерфейсы | Предпросмотр Compose/XML и затем визуальный конструктор с согласованными правками кода |
| 7. Опциональное ИИ-дополнение | Отдельная настройка, по умолчанию выключено; выбор источника через dpai, облачный контекст разрешается для каждого проекта; понятное влияние на лимиты |

Этапы принимаются отдельно. Выбор движка редактора и языковых служб —
после проверки совместимости с Android/arm64, лицензий, реальных C++/
Gradle-проектов и измерения ресурсов. Подсказка по словам файла не
подменяет семантическое дополнение. Базовая IDE работает без облачного ИИ.

Этап 1 реализован в dev.29 и проверен на хосте; приёмка на телефоне
остаётся в TODO.md. Поле этапа 2 реализовано в dev.30 (D-102): нативный
Sora, локальные TextMate-грамматики, вкладки и команды редактирования.
Полные хост-проверки DPmetaApp 26/26 и dpai PASS. Плавность ввода, жесты
и ресурсные бюджеты требуют замера на Redmi.
Инструкция — docs/EDITOR.md. Текущее состояние языковых служб и
следующих этапов описано ниже. Ограничение
ручной проверки/сборки D-99/D-100 сохраняется: сначала сохранить или
отменить правки, запуск только на свободном контуре.

Этап 3 начат (D-105, DP_AI_Orcestrator:D-137): в ядре есть клиент
языковых служб и запуск clangd процессом-собеседником; на хосте он
проверен на настоящем clangd 18 — флаги `compile_commands.json`,
диагностика, дополнение, подсказка, подпись, определение, использования,
переименование, форматирование, исправление. В редактор приложения
выведены включение службы и установка clangd кнопкой, подчёркивание
замечаний и их список с исправлениями, полоска дополнения, подпись
параметров, сведения, переход к определению (в другой файл — вкладкой),
использования, переименование символа своего файла и форматирование
(`docs/EDITOR.md`, «Семантика C и C++»); на телефоне это ещё не
проверено. Осталось проверить на телефоне, измерить память на Redmi и
принять на Galdhold. D-135 добавляет ручной индекс C++ с
compile_commands.json, выключенный по умолчанию. Реальный clangd на
хосте проверен с закрытым файлом проекта; размеры/память/задержки на
Redmi ещё неизвестны. Применение переименования сразу к нескольким
файлам пока не включено. D-143 сохраняет языковые сеансы открытых
вкладок при переключении и подключает новый файл к уже работающей
службе того же проекта; новый проект сам службу не запускает.

Этапы 4 и 4а начаты (D-110, DP_AI_Orcestrator:D-142): тем же клиентом и
экраном Python получает лёгкую службу pylsp+ruff или pyright+ruff по
кнопке, Kotlin — kotlin-lsp JetBrains на JDK 25 Alpine с обновлением
истекающих сборок EAP кнопкой и платформой Android SDK после принятия
лицензии. На хосте проверены настоящие pylsp, ruff, pyright и kotlin-lsp
(Gradle-импорт, диагностика, переходы, переименование), kotlin-lsp и
установка pyright — в Alpine (musl). Осталось: приёмка на Redmi, проект
приложения для Kotlin/Android, KMP — когда его поддержит служба,
переименование через файлы и исправления-команды. D-136 уточняет
обновление kotlin-lsp: версия и SHA-256 закреплены в APK, новый EAP
приходит с обновлением приложения, а не со страницы последнего выпуска.

Этап 5 начат (D-118, DP_AI_Orcestrator:D-153): вывод запуска из
редактора и ручной проверки/сборки разбирается в места кода — C/C++,
Kotlin/Gradle, Java, Python, MSVC, CMake, Rust; список «Ошибки» в
терминале запуска и под выводом сборки, касание открывает файл вкладкой
на строке. Ручные профили — до 20 шагов с шаблонами CMake, Gradle, Make,
CTest, Python (D-119, DP_AI_Orcestrator:D-154). «Запуск» открывает
программу во вкладке терминала, при «Сначала собрать» — после успешной
сборки (D-120, DP_AI_Orcestrator:D-155); история результатов — до 30
запусков с исходом, коммитом и выводом (D-121, DP_AI_Orcestrator:D-156).
Артефакты по шаблонам, установка APK и подпись ключом автора из Keystore
(D-122, DP_AI_Orcestrator:D-157). Отладчик C/C++ (gdb по DAP) и Python
(debugpy) в Linux приложения: точки касанием номера строки, панель шагов,
стек, переменные, выражение (D-124, DP_AI_Orcestrator:D-159). Logcat и
запуск APK — adb к самому телефону через беспроводную отладку: logcat с
фильтрами и переходом по трассировке, «Запустить» у APK (D-125,
DP_AI_Orcestrator:D-160). Отладка своих Kotlin/Java APK — свой клиент
JDWP через adb к самому телефону: точки в `.kt`/`.java`, стек,
переменные, шаги, исключения (D-126, DP_AI_Orcestrator:D-161).
Артефакты ПК-target — по SFTP только для чтения: «На телефон», затем
установка, запуск и logcat (D-127, DP_AI_Orcestrator:D-162). Запуск на
Windows-target — PowerShell по SSH с PTY (D-128, DP_AI_Orcestrator:D-163).
Отладка на ПК-target — адаптер DAP на самом ПК по SSH без PTY: Linux-ПК —
gdb и debugpy, Windows-ПК — debugpy (D-129, DP_AI_Orcestrator:D-164).

Этап 6 начат (D-132): предпросмотр Compose на телефоне — `PreviewActivity`

Этап 7 (D-133, DP_AI_Orcestrator:D-170): ИИ-дополнение по кнопке «ИИ:
дописать» у файла проекта; источник проекта — выключено, локальная модель
или облачная с согласием на отправку кода; уходит окно открытого файла.

версии из репозиториев Alpine. Полный анализ проекта, закреплённые версии,
управление Gradle/pip и удалённые среды остаются следующими шагами.

объяснения ошибок. Исходники во внешней памяти не требуют переноса.
