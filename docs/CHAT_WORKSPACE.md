# Единый экран ИИ-чатов

Состояние: 22 ноября 2026, `DPmetaApp:D-185`, `DP_AI_Orcestrator:D-219`.

Верхняя вкладка «Чаты» (прежний идентификатор `AiTab.MODELS` ради сохранения
навигации) показывает два прежних вида переписок в одном списке:

- API: `dpai.api-chats` v2, включая проектные разговоры, статусы, поток,
  прикрепления, Markdown, расход и «Полный доступ» в прежнем контуре.
- CLI: задачи с сессиями Claude Code, Codex CLI и Gemini CLI из журналов
  **всех** рабочих проектов; переход открывает штатный чат задачи и его
  лист, а не копию сообщений в новом хранилище.

«Исполнители и настройки» раскрывает существующие API-профили, проверку
ключей, администрирование, локальную модель и расход. CLI-исполнители
настраиваются через штатные target/слоты; отсутствие слота не считается
успешным входом.

## Проекты и target внутри API-чата

Кнопка «Подключить проект / target» открывает существующие targets,
затем рабочие проекты **на выбранном target**. Если подходящего нет, здесь
же доступны прежние мастера «Новый target» с подтверждением ключа хоста и
«Новый проект» с выбором места и каталога Git. Выбор меняет только явную
привязку разговора к проекту; root и конфигурация target берутся из общего
каталога. Подмена target через текст модели отсутствует.

Пустой проектный API-чат сохраняется после перезапуска. При смене проекта
или API-профиля старый грант «Полный доступ» отзывается; состояние брокера
одобрений и PIN/биометрия не переносятся. Действующий ход сначала нужно
остановить. Следующий запрос получает инструменты нового проекта только
после выбора человеком.

## Смена исполнителя с контекстом

| Откуда → куда | Действие человека | Что сохраняется |
|---|---|---|
| API → другой API | «Исполнитель / контекст» | Тот же чат и история с пометками моделей; нового гранта нет |
| API → Claude/Codex/Gemini CLI | Там же, после привязки проекта | Новая задача на проекте, до 32 завершённых реплик/12 000 знаков в цели; старый чат остаётся |
| CLI → другой CLI | «Сменить ИИ» в чате задачи | Штатный `SetExecutor` и handoff задачи, все прежние сессии в журнале |
| CLI → API | Там же, выбор профиля | Новый API-чат с последними 32 репликами (в сумме до 12 000 знаков), без событий и рассуждений |

Не копируются: ключи провайдеров, пароли CLI, `known_hosts`, бинарные
вложения, системные подсказки и подтверждения. Неудачные и отменённые
ответы API в контекст CLI не входят. Перенос — отдельное действие
человека: содержание уйдёт другому API-провайдеру **только после его
следующего сообщения**, не при выборе в окне. Начало новой CLI-задачи
является явной постановкой задачи; она может запустить платную работу.

## Приёмка Android

1. Три API-провайдера, несколько профилей, обычный и проектный чаты;
   вход в «Чаты» после рестарта сохраняет список.
2. Несколько одновременно работающих проектов на разных targets,
   Claude/Codex/Gemini; открыть чужой проект из списка и вернуться.
3. Из API-чата подключить существующий Termux SSH-target и проект, затем
   создать target/проект штатными мастерами, сверив fingerprint.
4. API → API → CLI и CLI → CLI → API: целостность истории/ролей, отсутствие
   передачи секретов, потерянных действий и повторного платного вызова.
5. Передача во время ответа/хода: запрет или ясное предупреждение;
   смена проекта/профиля отзывает полный доступ и не ослабляет approvals.
6. Удаление исходного чата/профиля не стирает другую CLI-задачу;
   удаление target не оставляет ложную работоспособность.
