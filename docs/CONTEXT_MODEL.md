# Модель контекста и handoff

Контекст — структурированный набор, а не длинный промпт (ТЗ, §23).
Код — модуль `contexts` (этап 8).

## 1. ContextBundle

| Часть | Источник |
|---|---|
| objective, exact next action | задача, прошлый handoff |
| project, repository, branch, worktree | реестр проектов, `git` |
| relevant docs, decisions, contracts, TODO | файлы проекта; DPmeta — если подключён (ТЗ, §5.3) |
| recent commits, current diff, tests | `git`, `verification` |
| risks, current failure | диагностика прошлых сессий |
| previous handoff | `contexts` |

Каждая версия — `contextId`, `version`, хеш (D-10), источники, время
создания (ТЗ, §24). Изменился любой источник — новая версия; старая не
меняется.

## 2. Отбор

Уровни: глобальный → проект → репозиторий → задача → нужные документы →
текущий код и diff → прошлый handoff → итог проверки (ТЗ, §25). Вся
экосистема не передаётся каждый раз. Отбор детерминирован (D-22):
одинаковые источники и задача дают одинаковый набор и хеш. Под
давлением бюджета порядок отбора — свой: правила, задача, handoff и итог
проверки раньше документов и кода, а не вошедшее названо в версии и в
prompt (D-40, `docs/EFFICIENCY.md`, §3).

## 3. Границы

- Уровни секретности источника: `PUBLIC`, `INTERNAL`, `SENSITIVE`,
  `SECRET` (ТЗ, §65). `SECRET` исключён по умолчанию; включение — явное
  разрешение с записью.
- Граница проекта (ТЗ, §67): задача проекта A не получает секретов и
  контекста проекта B, даже если они лежат на том же target.
- Содержимое репозитория — недоверенный вход (ТЗ, §64): оно передаётся
  Claude как данные с пометкой происхождения, а не как инструкция
  оркестратора.

## 4. Сжатие

```
сырая история → структурная сводка → решения → проверенные факты →
открытые проблемы → следующее действие
```

Исходная история хранится отдельно; сводка не заменяет источник (ТЗ,
§26). Каждый факт сводки — со ссылкой на событие или файл, откуда он
взят (ТЗ, §5.6).

## 5. Handoff

Создаётся при: близком пределе сессии, ручном продолжении, отказе
target, исчерпании аккаунта, остановке приложения, паузе задачи (ТЗ,
§27). Минимум полей: цель, состояние, сделано, проверено, не удалось,
предупреждения, изменённые файлы, состояние Git, ветка, id сессии, id
контекста, точное следующее действие. Handoff неизменяем и хешируется;
повтор создания с тем же ключом не дублирует его (ТЗ, §5.4).

## 6. Классификация источников

Файловый контекст не перемещает и не удаляет исходники (ТЗ, §5.8):
пробный прогон, копия, уверенность и объяснение классификации, откат.

## 7. Код

Модуль `contexts` (этап 8); уровни секретности и происхождение —
`security` (`Sensitivity`, `Origin`).

- `ContextAssembler.assemble` — версия `dpai.context` v2: источники по
  уровню, затем по ключу; источник другого проекта не включается никогда
  (`CONTEXT_PROJECT_BOUNDARY`); `SECRET` — только по разрешению политики
  и с предупреждением (`CONTEXT_SECRET_EXCLUDED`,
  `CONTEXT_SECRET_INCLUDED`); не вошедшее по объёму названо
  (`CONTEXT_TRUNCATED`); тот же контекст — та же версия, иной — версия
  + 1 со ссылкой на хеш прежней.
- `PromptRenderer` — prompt хода: указания только от оркестратора, прочие
  источники — блоки данных с ключом, уровнем, происхождением и хешем;
  маркер блока внутри данных обезвреживается (T3). Корпус уловок —
  `tests/data/context-injection/`.
- `Handoff` (`dpai.handoff` v1) и `Handoffs` — неизменяемый, хешируемый,
  идемпотентный по ключу; `asSource()` — источник уровня `HANDOFF` для
  следующей сессии с происхождением `MODEL` (заявления, D-23).
- `Compaction` — сводка без модели: одинаковые записи — один факт со
  всеми ссылками, решённые проблемы уходят из открытых, заметки остаются
  только в исходной истории.
