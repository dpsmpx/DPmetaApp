# Визуальная система

Визуальный язык автора (Д9). Токены — `assets/brand/tokens.json`
(источник истины для цвета, шрифтов и пределов; проверки берут значения
оттуда). Изменение системы — изменение основ (`docs/PROCESS.md`).

## 1. Принцип

Автор — над проектами. Визуальный язык связывает **автора + Galdhold +
DPlang + будущие проекты**, не смешивая бренды: у автора — графит,
типографика и семантические цвета; проекты входят «в рамке» своим
изображением. Никакой случайной «ИИ-эстетики».

Образ, который передаёт система: **инженерная мастерская** — спокойная,
точная, с настоящими результатами на виду. Не неон, не киберпанк, не
«магия».

## 2. Цвет

| Токен | HEX | Роль |
|---|---|---|
| `ink` | `#111214` | фон |
| `graphite` | `#1A1B1E` | панели |
| `line` | `#2E3036` | линии, рамки, сетка |
| `mist` | `#A3A6AD` | вторичный текст |
| `paper` | `#EEEEEC` | основной текст |
| `human` | `#FF7A59` | **человек**: замысел, архитектура, решения; главный акцент |
| `ai` | `#5CC8D7` | **ИИ**: реализация, анализ, автоматизация |
| `verified` | `#7FD68E` | **проверено**: проверки, приёмка |

Цвет — смысл, а не украшение: где человек решает — коралловый, где
работает ИИ — бирюзовый, где проверено — зелёный. Так одна схема
показывает метод без подписей «тут ИИ». Палитра намеренно отличается от
интерфейса Galdhold (сине-сланцевый `#0E1219` и янтарный `#F2B33D`),
чтобы автор не выглядел «темой игры».

Контраст: текст на `ink` — не ниже 4,5 (обычный) и 3 (крупный);
проверяется автоматически.

## 3. Типографика

- **IBM Plex Sans** — имя, роль, заголовки (Medium/SemiBold), текст
  (Regular). Кириллица и латиница одного рисунка.
- **IBM Plex Mono** — метки схемы, технические теги, числа с датой.
- Не больше трёх размеров текста в композиции (NN/g, «visual hierarchy»).
  Доли от высоты: display 8,5 %, title 3,6 %, label 2,4 %.
- Минимум — 16 px при высоте 720 px.
- Шрифты — SIL OFL 1.1 (`assets/brand/fonts/OFL-IBM-Plex.txt`).

## 4. Композиция

- Иерархия личной работы: **1 — человек, 2 — профессиональная
  идентичность (имя, роль), 3 — инженерный контекст, 4 — сотрудничество
  с ИИ, 5 — доказательство/проект, 6 — декор.** Не наоборот.
- Человек — самый крупный объект; лицо — в безопасной зоне каждого
  формата.
- Сетка 12 колонок; поля — не меньше 5 % короткой стороны.
- Не больше четырёх смысловых групп текста (имя, роль, схема,
  доказательство). «Панель с 50 надписями» — брак.
- Пустое пространство — часть композиции, а не место для ещё одной
  надписи.

## 5. Свет и фон

- Фон — `ink` с едва заметной инженерной сеткой (`line`, 6–10 %
  непрозрачности) или чистый.
- Свет на портрете — тёплый, сбоку; окружение уходит в `ink`
  (виньетка), чтобы интерьер не читался (Д18).

## 6. Стиль схем и интерфейса

- Схема — цепочка узлов слева направо: **Замысел → Архитектура →
  Реализация с ИИ → Проверка → Git → Продукт** (EN: Intent →
  Architecture → AI implementation → Verification → Git → Product).
- Узел — скруглённый прямоугольник, контур 2 px цветом смысла, подпись
  Plex Mono; стрелки — `line`/`mist`.
- «CI» в схеме не пишется: проверки идут в сессии, без Actions
  (ME-NO-CI) — узел называется «Проверка».

## 7. Данные и код

- Графики — по правилам `dataviz` (одна мысль на график, подписи у
  данных, без 3D); цвета — семантические токены.
- **Код закрытых проектов не показывается** (Д17). Если нужен «код как
  фактура» — синтетические строки без смысла или код этого репозитория.

## 8. Портрет

- Только фотография автора с пометкой `REFERENCE_IMAGE` (Д10, Д18).
- Разрешено: кадрирование, тон (экспозиция, контраст, насыщенность),
  виньетка, маска краёв, монохром/дуотон.
- Запрещено: изменение черт, формы лица и тела, «улучшение» ИИ,
  дорисовка, замена фона генерацией без отдельного решения.
- Проверка сходства: экспорт сравнивается с референсом глазами при
  утверждении (гейт Brand); геометрия не меняется — только масштаб.

## 9. Знак автора

Словесный знак — `dpsmpx` в IBM Plex Sans SemiBold, строчными, цветом
`paper`, с коралловой точкой-курсором (`human`) — «человек ставит
точку». Рукописный «dpsmpx code» (аватар Telegram) — допустимый
личный вариант, не основной знак (IC-08).

## 10. Проекты «в рамке»

- **Galdhold** — настоящий рендер игры или его стилизованный знак в
  тонкой рамке `line`; цвета игры не перекрашиваются.
- **DPlang** — только типографика (имя Plex Mono) до появления своего
  знака.
- Логотипы площадок (YouTube, Telegram и др.) — только по правилам их
  брендбуков (`docs/legal/RIGHTS_MATRIX.md`); в личных работах — не
  нужны.

## 11. Чего не делать

Неоновый мозг, робот-идол, голограммы без смысла, светящиеся «нейроны»,
матрица из цифр, чужие игры и логотипы, стоковые «программисты в
капюшоне», мелкий нечитаемый HUD.
