# Экономия контекста и токенов

Слой D-40: больше полезной работы на единицу расхода подписки — без
обхода пределов провайдера (D-04, D-30) и без потери того, что нужно для
правильного решения. Аудит, с которого он начат, —
`docs/audits/2026-10-08-token-efficiency.md`.

Главная мера — не «меньше токенов», а **сделанные и проверенные задачи
на единицу расхода**: ход, сэкономивший токены и не прошедший проверку,
— потеря, а не экономия.

## 1. Где тратится

Оркестратор не вызывает API модели сам: ход — процесс Claude Code
(D-32), и внутри хода инструменты, историю и кеш prompt ведёт Claude
Code. Оркестратор решает, **что и как часто** уходит в ход: prompt
(контекст задачи), продолжение или новая сессия, модель и усилие, повтор
после отказа. Поэтому рычаги слоя — на этих решениях, а измерение — по
итогу хода, который сообщает провайдер.

## 2. Учёт

Два источника, которые никогда не смешиваются (D-13):

| Что | Источник | Мера | Событие |
|---|---|---|---|
| Prompt хода: знаки, токены, источники, не вошедшее, не посланное повторно, режим, маршрут | оркестратор | оценка (`ESTIMATED`) | `SESSION_PROMPT_PREPARED` |
| Ход: токены входа, выхода, чтения и записи кеша, размышления, контекст в конце хода, вызовы API, субагенты, длительность, модели и их окна, стоимость, было ли сжатие истории | провайдер (`result`, `docs/research/CLAUDE_CODE_CLI.md`, §11) | наблюдаемое; стоимость при подписке — оценка по прейскуранту | `SESSION_TURN_USAGE` |

Оценка токенов — UTF-8 байты / 3 с округлением вверх: с запасом и для
латиницы (~4 байта на токен), и для кириллицы (~5–6 байт на токен);
точный счёт знает только провайдер, и отчёт сравнивает оценку с ним.
Ход без итога (оборвался) — расход неизвестен, а не нулевой: суммы
сессии тогда — нижняя граница (`UsageTotals.unknownTurns`).

Сессия копит расход (`SessionRecord.usage`, снимок `dpai.sessions-state`
v2): из него строятся отчёт (§9) и решение о продолжении (§4).

## 3. Бюджет контекста

Источники контекста (`ContextSource`) — слои по уровню; prompt
(`PromptRenderer`) выводит их от устойчивого к меняющемуся:

| Слой | Уровень | Раздел prompt | Под давлением бюджета |
|---|---|---|---|
| L0 правила | — (оркестратор) | «Правила оркестратора» | всегда |
| L1 правила и решения | `GLOBAL`, `PROJECT` | сразу после правил | критично |
| — устройство репозитория | `REPOSITORY` | сразу после правил | выпадает с указателем |
| L2 задача | цель, следующее действие, `TASK` | «Задача» | критично |
| L3 состояние | `HANDOFF` | после задачи | критично |
| L4 знания | `DOCUMENT`, `CODE` | после задачи | выпадают первыми, с указателем |
| L5 вывод инструментов | `TOOL` (итог проверки, §5) | после задачи | критично |
| L6 история | — (ведёт Claude Code) | — | §4 |

Бюджет (`ContextPolicy.budgeted`) — в оценочных токенах (§2) и вдобавок
к пределу знаков. Отбор — по `ContextPolicy.PRIORITY`: правила, задача,
handoff, итог проверки, затем репозиторий, документы, код. Не влезший
источник некритичного уровня — `CONTEXT_TRUNCATED` и строка в разделе
«Не вошло в контекст» с ключом и размером: исполнитель знает, чего не
видел, и найдёт сам. Критичный — отказ сборки `CONTEXT_BUDGET_EXCEEDED`:
правила и требования задачи не режутся молча. Тот же текст под вторым
ключом — один раз (`CONTEXT_DEDUPLICATED`, `sameAs`).

Размер бюджета задаёт оркестратор от окна модели (§10): окно минус
ответ, минус системный prompt и инструменты Claude Code, с запасом — и
лишь доля этого: остальное нужно ходу на собственную работу
(чтение файлов, вывод команд). Заполнять всё окно контекстом задачи —
лишить ход места для работы.

## 5. Итог проверки

`OutputDigest` (`verification`) сжимает вывод непрошедшего шага: строки
ошибок (первые и последние до предела, повторы — один раз), итоговые
счётчики тестов и сборки, первые кадры стека после ошибки,
предупреждения, края вывода; середина — пометкой «пропущено строк: N».
ANSI-цвета убираются, длинные строки обрезаются с пометкой. Каждая
строка выжимки — строка вывода: ничего не пересказано и не выдумано.
`VerificationReport.failureDigest` собирает её для непрошедших
обязательных шагов с командой и кодом выхода — это источник `TOOL`
следующей попытки (§4). Прежние 20 последних строк (`tail`) остаются в
доказательстве шага: у Gradle это «BUILD FAILED … --stacktrace», а не
ошибка.
