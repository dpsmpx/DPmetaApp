# Происхождение материалов

Откуда каждый материал и на каком праве. Машиночитаемо — реестр
входов `data/provenance/assets.yaml` (схема `schemas/assets.schema.json`)
и записи выходов каждого объекта `content/items/<id>/provenance.yaml`
(схема `schemas/item_provenance.schema.json`). Права по видам
материалов — `docs/legal/RIGHTS_MATRIX.md`. Проверка —
`tools/check.sh` (`provenance`, гейт Provenance).

## 1. Правила

- **Каждый файл в `assets/`** (кроме README) записан в реестре: id
  `A-NNN`, вид, путь, sha256, источник, автор, дата, лицензия,
  основание прав, разрешённое и запрещённое использование. Без записи
  материал не используется; хэш не совпал — проверка красная.
- **Каждый выход** (рендер, экспорт) записан в `provenance.yaml`
  объекта: файл и sha256, вариант, формат, язык, метод, входы (id
  ассетов), спецификация и её sha256, промпт и версия, инструмент и
  sha256 его кода, изменения, раскладка, дата. Записи пишет `tools/cs/render.py`;
  руками не правятся.
- **Спецификация изменилась после рендера** — выход устарел: проверка
  требует перерендерить (sha256 спецификации в записи). Изменился код
  рендера — предупреждение: перерендерить, если менялся макет.
- **Вход выхода** должен быть заявлен в `inputs` объекта.
- **Сгенерированный материал** (`kind: generated`) — только с
  провайдером, моделью, промптом и версией промпта (Д11). Генерация
  людей и лица автора — нет (Д10).
- В записи — только то, что нужно для прослеживаемости: без адресов
  с подписями, токенов, локальных путей машины автора (`docs/SECURITY.md`).

## 2. REFERENCE_IMAGE — фотографии автора

`REFERENCE_IMAGE` — настоящая фотография автора, присланная им для
образа (Д10, Д18). Лежит в `assets/reference/author/`
(`assets/reference/README.md`).

- Разрешено: кадрирование, масштаб, тон (экспозиция, контраст,
  насыщенность), монохром/дуотон, виньетка и маска краёв.
- Запрещено: изменение черт, формы лица и тела, генеративное
  «улучшение», дорисовка, генерация нового образа «по мотивам»,
  передача фото в сторонние сервисы генерации.
- Метаданные: в репозитории фото — без EXIF/XMP и геометок (проверка
  `provenance`, гейт Safety).
- Интерьер на фото — личное (Д2, Д18): в работах затемняется до
  нечитаемости.
- Каждая работа с портретом утверждается автором (гейт Brand).

## 4. Как добавить материал

1. Положить файл в `assets/<вид>/` с говорящим именем и датой.
2. Удалить метаданные (EXIF/XMP, комментарии), если это фото.
3. Добавить запись в `data/provenance/assets.yaml`: следующий `A-NNN`,
   `sha256sum` файла, источник (откуда и когда), автор, лицензия,
   основание прав, разрешённое и запрещённое использование.
4. Описать строкой в таблице §3 этого файла.
5. Если права неясны — запись в `docs/legal/RIGHTS_MATRIX.md` и вопрос
   автору; до ответа материал не используется в публичном.
6. `tools/check.sh provenance secrets`.

## 5. Происхождение продуктов

Каждый продукт ведёт свой `PROVENANCE.md` рядом с документами
(`docs/content/products/<product>/`): какие входы, какой метод и версия
промпта, где записи выходов. Первый продукт —
`docs/content/products/personal_presentation/PROVENANCE.md`.
