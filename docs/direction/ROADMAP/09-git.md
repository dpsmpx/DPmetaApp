# Этап 9 — Git и worktree

Состояние: —.

## Цель

Оркестратор всегда знает, где рабочее дерево и кто в него пишет (ТЗ,
§29–§31, §70, §132).

## Объём

- Регистрация репозиториев, ветки, worktree, владелец каждого дерева.
- Статус, diff, коммиты, fetch, push, PR, состояние слияния, конфликты.
- Оценка затронутых файлов и политика `ALLOW` / `WARN` / `SERIALIZE` /
  `REJECT` (ТЗ, §31).
- Без неявных `reset --hard`, `push --force`, `rm -rf` (ТЗ, §70).

## Критерии выхода

- [ ] Параллельные синтетические сессии не портят рабочие деревья друг
      друга (ТЗ, §139, Phase 9).
- [ ] Два изолированных сеанса не владеют одним изменяемым деревом
      (инвариант ТЗ, §118).
- [ ] Разрушительная операция Git невозможна без одобрения.
