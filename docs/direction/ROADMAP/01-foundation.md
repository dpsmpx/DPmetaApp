# Этап 1 — Основание

Состояние: **выполнен** (4 октября 2026).

## Цель

Подготовить DPpass к серьёзной разработке: понять предметную область,
принять архитектурные решения, собрать ядро, которое проверяется без
устройства, и проверки, которые не дают от решений отступить.

## Что сделано

| Направление | Результат |
|---|---|
| Исследование | `docs/research/` — аудит Happ, модель ограничений L0–L10, транспорты, стратегия ядра, архитектура клиентов, сетевая модель Android |
| Решения | `docs/direction/DECISIONS.md` — D-01…D-22 и список отложенных |
| Ядро | модули `diagnostics` … `connection` на Kotlin/JVM (`docs/ARCHITECTURE.md`) |
| Формат | собственный документ `dppass.config` v1 и IR (`docs/CONFIG_FORMAT.md`) |
| Ядро прокси | граница `ProxyEngine`/`BackendCompiler`, фиктивное ядро `mock` и `mock-limited` |
| Оболочки | `cli` (JVM) и `app/` (Android: `VpnService`, Keystore, оболочка разработки) |
| Тесты | модульные, межмодульные, корпус регрессий `tests/data/`, fuzz (`docs/TESTING.md`) |
| Проверки | `tools/hostcheck/run.sh`, проверки безопасности и происхождения, CI (`docs/PROCESS.md`) |
| Лицензии | `docs/legal/THIRD_PARTY_MATRIX.md`, `docs/PROVENANCE.md` |
| Аудит | `docs/audits/INITIAL_ARCHITECTURE_AUDIT.md` |

## Критерии выхода

- [x] Ядро собирается без Android SDK, предупреждения компилятора — ошибки.
- [x] Весь конвейер (разбор → активация → план → подключение на модели
      сети → откат) проходит в межмодульных тестах и через `cli`.
- [x] Неподдержанное ядром отвергается с путём (второй бэкенд `mock-limited`).
- [x] Корпус регрессий и fuzz идут в каждом прогоне hostcheck.
- [x] Секреты не попадают в журнал, отчёт, диагностику и на «диск» (тест).
- [x] Android-модуль собирается, Lint без предупреждений, API ядра ≤ minSdk.
- [x] Каждая ссылка на решение, документ, раздел и этап ведёт на
      существующее (`check_docs.py`).
- [x] Каждая зависимость — в матрице лицензий и PROVENANCE с той же версией.

## Что не делалось

Реальное ядро, сетевые операции, интерфейс продукта, выпуск — этапы 2–5.
