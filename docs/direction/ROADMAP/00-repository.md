# Этап 0 — Инициализация репозитория

Состояние: **в работе**.

## Цель

Подготовить репозиторий к долгой разработке: правила работы, решения,
план, архитектура документов и модулей, проверки, которые не дают от
решений отступить (ТЗ, §139, Phase 0).

## Объём

| Направление | Результат |
|---|---|
| Точки входа | `README.md`, `CLAUDE.md`, `TODO.md`, `LICENSE` |
| Направление | `docs/direction/` — ТЗ, решения, план, объём V1, матрица готовности |
| Устройство | `docs/` — документы ТЗ, §138: архитектура и модели, безопасность, тесты, производительность, восстановление, процесс, происхождение, журнал изменений |
| Скелет | модули Gradle по `docs/ARCHITECTURE.md`, §2; wrapper со сверкой сумм; convention-плагины |
| Проверки | `tools/verify/run.sh` — `static`, `affected`, `full`, `plan`, `report` |
| Процесс | хук начала сессии, шаблон PR |

## Критерии выхода

- [x] В корне — только точки входа и файлы сборки; ТЗ — в
      `docs/direction/` (D-19).
- [x] Решения этапа записаны с проверками (`docs/direction/DECISIONS.md`).
- [x] План покрывает все фазы ТЗ, §139; у каждого этапа — проверяемые
      критерии выхода.
- [x] Документы ТЗ, §138 есть и не дублируют ТЗ, а описывают устройство.
- [x] Скелет собирается `./gradlew build` без Android SDK;
      направления зависимостей сверяет `check_modules.py`.
- [x] `tools/verify/run.sh static` ловит каждое нарушение, ради которого
      написана проверка (внесённое нарушение — красный, чистое дерево —
      зелёный, `docs/PROCESS.md`, «Проверки»).
- [x] Проект запускается: `dpai version` из собранного `cli`.
- [ ] Полный прогон `tools/verify/run.sh full` зелёный на `main` после
      влития.
