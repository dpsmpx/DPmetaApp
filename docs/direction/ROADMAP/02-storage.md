# Этап 2 — Сохранённое состояние

Состояние: **выполнен (6 октября 2026)**.

## Цель

Состояние оркестратора переживает сбой процесса, прерванную запись,
миграцию и восстановление из копии (ТЗ, §139, Phase 2; ТЗ, §57–§62, §71).

## Объём

- Решение о хранилище — D-24 (файлы журнала и документов; индексы —
  производные), о копии — D-25 (без секретов).
- Атомарная запись (временный файл, fsync, переименование), обнаружение
  повреждений по хешу (D-10), last known good.
- Журнал событий только на дописывание (D-12), снимки, восстановление
  «снимок + события после него».
- Версии схем и явные миграции: проверить → мигрировать → проверить →
  атомарно заменить; при ошибке — откат (ТЗ, §62).
- Резервная копия с манифестом (версия, время, хеш, размер, версия
  схемы); секреты — отдельно и зашифрованно либо по явному согласию
  (ТЗ, §59, §60). Восстановление: годная, старая схема, частичная,
  повреждённая, после прерванного восстановления (ТЗ, §61).
- Структурный журнал приложения с редактированием секретов (D-14).

## Критерии выхода

- [x] Прерванная в любой точке запись оставляет прежнее или новое
      состояние, но не смесь; подтверждённая запись переживает сбой
      (`DocumentStoreTest`, `EventJournalTest`: сбой перед каждой
      операцией по модели, отказ ввода-вывода на каждом шаге).
- [x] Повреждённый файл обнаруживается и не применяется; сохраняется
      last known good (`DocumentStoreTest`); испорченная середина журнала
      открывается только после явного карантина (`EventJournalTest`).
- [x] Восстановление «снимок + хвост журнала» даёт то же состояние, что
      полный пересчёт (property-тест `SnapshotRecoveryTest`).
- [x] Миграция цепочкой версий с откатом при ошибке (`MigratorTest`).
- [x] Набор восстановления копий ТЗ, §61 зелёный; невалидная копия не
      применяется молча (`BackupTest`).
- [x] Секрет не попадает в диагностику хранилища и в копию сверх файлов
      данных (`StorageLeakTest`); секретов в хранилище нет по устройству
      (D-25, правило `storage-secret`). Редактирование вывода Claude до
      записи события — критерий этапа 4.

## Итог

`storage`: `Vfs` и `NioVfs`; `DocumentStore` (атомарная замена, last
known good, миграция при чтении); `EventJournal` (цепочка хешей,
подтверждение после fsync, обрезка оборванного хвоста в карантин,
явный карантин испорченной середины, закрытие после отказа записи);
снимки и `StateRecovery`; `Migrator`; `BackupService` (манифест,
проверка, возобновляемое восстановление). Тесты — по модели сбоев
`SimulatedVfs`; мутации «без fsync каталога» и «без fsync журнала»
ловятся. Транзакция — одна запись журнала: производное состояние
пересчитывается (D-12, D-24).
