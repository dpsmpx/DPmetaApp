# Этап 2 — Сохранённое состояние

Состояние: —.

## Цель

Состояние оркестратора переживает сбой процесса, прерванную запись,
миграцию и восстановление из копии (ТЗ, §139, Phase 2; ТЗ, §57–§62, §71).

## Объём

- Решение «Отложено»: SQLite или собственный журнал файлов — в начале
  этапа (`docs/direction/DECISIONS.md`).
- Атомарная запись (временный файл, fsync, переименование), обнаружение
  повреждений по хешу (D-10), last known good.
- Журнал событий только на дописывание (D-12), снимки, восстановление
  «снимок + события после него».
- Версии схем и явные миграции: проверить → мигрировать → проверить →
  атомарно заменить; при ошибке — откат (ТЗ, §62).
- Резервная копия с манифестом (версия, время, хеш, размер, версия
  схемы); секреты — отдельно и зашифрованно либо по явному согласию
  (ТЗ, §59, §60). Восстановление: годная, старая схема, частичная,
  повреждённая, после прерванного восстановления (ТЗ, §61).
- Структурный журнал приложения с редактированием секретов (D-14).

## Критерии выхода

- [ ] Прерванная в любой точке запись оставляет прежнее или новое
      состояние, но не смесь (тест с отказом записи на каждом шаге).
- [ ] Повреждённый файл обнаруживается и не применяется; сохраняется
      last known good.
- [ ] Восстановление «снимок + хвост журнала» даёт то же состояние, что
      полный пересчёт (property-тест).
- [ ] Миграция цепочкой версий с откатом при ошибке.
- [ ] Набор восстановления копий ТЗ, §61 зелёный; невалидная копия не
      применяется молча.
- [ ] Секрет не попадает в журнал, копию без шифрования и диагностику
      (тест утечки).
