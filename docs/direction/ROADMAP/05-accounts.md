# Этап 5 — Аккаунты

Состояние: —.

## Цель

Произвольное число слотов аккаунтов с изоляцией учётных данных,
возможностями, здоровьем и выбором (ТЗ, §9, §10, §50, §51, §66, §127).

## Объём

- Решение «Отложено»: изоляция учётных данных на target.
- Реестр `AIAccount` (ТЗ, §7); состояния `AVAILABLE` … `DISABLED` (ТЗ, §9).
- Ссылки на учётные данные (`credentialRef`), хранилище ОС; в базе —
  только ссылка (D-14).
- Возможности и требования задачи (ТЗ, §51); cooldown, rate limit,
  справедливое распределение нагрузки (ТЗ, §85).
- Журнал действий с аккаунтами.

## Критерии выхода

- [ ] 10+ синтетических аккаунтов одновременно проходят тесты
      жизненного цикла (ТЗ, §139, Phase 5).
- [ ] Перед запуском сессия сверяет `accountId`, `credentialRef`,
      `executionTargetId`; учётные данные B не попадают в сессию A
      (ТЗ, §66, §109).
- [ ] Аккаунт в `RATE_LIMITED` или `AUTH_REQUIRED` не выбирается; лимиты
      не обходятся (D-04).
