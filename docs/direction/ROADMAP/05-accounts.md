# Этап 5 — Аккаунты

Состояние: в работе.

Начат по слову автора раньше этапов 3–4 (D-30): логика аккаунтов не
зависит от транспорта. Сверка перед запуском сессии ждёт этапов 3, 4, 6.

## Цель

Произвольное число слотов аккаунтов с изоляцией учётных данных,
возможностями, здоровьем и выбором (ТЗ, §9, §10, §50, §51, §66, §127).
Основной режим — одна подписка с полным контролем; несколько подписок —
с защитами от пересечения (D-27, D-29, D-30).

## Объём

- Изоляция учётных данных на target — свой `CLAUDE_CONFIG_DIR` на слот,
  только вход формой Claude (D-27, D-29).
- Подписка и слот (`AIAccount`, ТЗ, §7); состояния `AVAILABLE` …
  `DISABLED` (ТЗ, §9) выводятся из фактов (`docs/ACCOUNT_MODEL.md`, §2).
- `credentialRef` — путь к каталогу настроек слота; учётные данные
  claude.ai оркестратор не читает и не хранит (D-14, D-27).
- Пределы подписки, cooldown, справедливое распределение нагрузки
  (ТЗ, §85); защиты от пересечения (`docs/ACCOUNT_MODEL.md`, §4).
- Возможности и требования задачи (ТЗ, §51) — с моделью задачи (этап 7).
- Журнал действий с аккаунтами.

## Критерии выхода

- [x] 10+ синтетических аккаунтов одновременно проходят тесты
      жизненного цикла (ТЗ, §139, Phase 5): `AccountsTest`,
      `twelveSlotsLiveThroughTheirLifecycleTogether`.
- [x] Аккаунт в `RATE_LIMITED` или `AUTH_REQUIRED` не выбирается; лимиты
      не обходятся (D-04): `AccountsPropertyTest`.
- [x] Каждая защита от пересечения (`docs/ACCOUNT_MODEL.md`, §4)
      проверена тестом: `AccountsTest`, `SlotEnvironmentTest`.
- [x] Режим одной подписки получает весь набор уведомлений
      (`docs/ACCOUNT_MODEL.md`, §7): `AccountNotificationsTest`.
- [x] Состояние аккаунтов восстанавливается из журнала и снимка:
      `AccountsJournalTest`.
- [ ] Перед запуском сессия сверяет `accountId`, `credentialRef`,
      `executionTargetId`; учётные данные B не попадают в сессию A
      (ТЗ, §66, §109) — с запуском процессов (этапы 3, 4, 6).
- [ ] Два `CLAUDE_CONFIG_DIR` с разными подписками на одном target
      работают независимо при параллельных сессиях — замер
      (`docs/research/CLAUDE_CODE_CLI.md`, §7).
- [ ] Возможности и требования задачи учитываются при выборе слота
      (ТЗ, §51) — с моделью задачи (этап 7).
