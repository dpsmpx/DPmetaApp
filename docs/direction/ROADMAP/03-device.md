# Этап 3 — Устройство

Состояние: —

## Цель

Всё, что на этапе 1 проверено на хосте моделью, — сделать и проверить
на устройстве: хранение, сеть, жизненный цикл, производительность.

## Работы

1. **Хранение и ключи** (D-19): `KeystoreKeyProvider` на реальных
   устройствах (Android 8 … 16), поведение после смены блокировки
   экрана, восстановления, переноса; путь восстановления, если ключ
   данных не расшифровывается (сейчас — исключение, `TODO.md`).
2. **Загрузка подписок по HTTPS**: `SubscriptionFetcher` с пределом
   размера во время чтения, таймаутом, без идентификаторов устройства
   (D-12), только `https://`; обновление по расписанию через
   `WorkManager` или эквивалент с учётом `UpdatePolicy`.
3. **Пробы сети на Android** (D-14): `Prober` поверх реальных сокетов
   (DNS, TCP, TLS, UDP, страница входа, крупная передача) с бюджетом;
   `NetworkCallback` → переоценка без залпов.
4. **Жизненный цикл сервиса**: смерть процесса и `START_STICKY`/always-on
   поднимают last-known-good, а не пустую конфигурацию; перезагрузка;
   lockdown; `onRevoke`.
5. **Бюджет производительности на устройстве**
   (`docs/PERFORMANCE_BUDGET.md`): пороги вместо ориентиров хоста.

## Критерии выхода

- [ ] Записи раздела «На устройстве» в `TODO.md` закрыты результатами
      проверки (устройство, версия Android, дата).
- [ ] Подписка обновляется по сети, неудача не трогает действующую
      конфигурацию (как в `SubscriptionActivationTest`, но на устройстве).
- [ ] Классификация сети на устройстве совпадает с моделью на тех же
      условиях (насколько их можно воспроизвести).
