# Снимки экранов на JVM

Настоящие экраны приложения `:shell` — пульт и окно «AI» — рисует
Robolectric с нативной графикой на синтетической экосистеме корпуса
(`tests/corpus/ecosystem`) и демо-системе подсистемы «AI». Телефон не нужен,
данных автора в снимках нет.

## Как снять

```sh
tools/screenshots.sh            # PNG — в docs/screenshots/
tools/screenshots.sh <каталог>  # PNG — в другой каталог (сверить, не трогая docs/)
```

Нужны JDK 21 и Android SDK — как для сборки APK. Robolectric и образ
«Android целиком» (213 МБ) Gradle берёт только по свойству
`dpmeta.screenshots`, со сверкой сумм в `gradle/verification-metadata.xml`;
в APK и в обычную сборку и проверки они не попадают. Происхождение —
`docs/PROVENANCE.md`. Старые PNG сценарий удаляет: снимок, которого тест
больше не делает, не остаётся молча.

## Что снимается

| Файл | Экран |
|---|---|
| `pult-summary.png` | Пульт, «Сводка» |
| `pult-projects.png` | Пульт, «Проекты» |
| `settings.png` | Документ настроек |
| `help.png` | Справка |
| `ai-summary.png` | Окно «AI», «Сводка» (демо) |
| `ai-tasks.png` | Окно «AI», «Задачи» (демо) |
| `workspace-simple.png` | Рабочий проект, простой вид, синтетическое локальное дерево |
| `workspace-full.png` | Тот же проект, полный вид |

Экран 360×800 dp, плотность xhdpi, SDK 36, светлая тема.

`AppearanceTest` дополнительно рисует восемь вариантов оформления
(четыре темы × простой/полный вид) с крупным текстом и плотным режимом,
проверяет совпадение цветов пульта, IDE и нативной палитры. Отдельно
проверяется сохранение фона, текста и курсора настоящего адаптера Sora
после повторного `applyDefault` (это происходит при attach редактора). Запуск:

```sh
./gradlew :shell:testDebugUnitTest -Pdpmeta.screenshots --tests '*AppearanceTest'
```

В APK workflow обе проверки обязательны, PNG — отдельный артефакт
`DPmetaApp-interface-<коммит>`. Ошибка интерфейса не заменяет и не отменяет
`full --strict`: у каждой проверки свой завершающий guard. Для состояния
проекта используется текущий синтетический `projects.json`, без прежнего
формата реестра ролей.

## Как устроен тест

`shell/src/screenshots/kotlin/…/ScreenshotsTest.kt` — один тест: все
экраны снимаются по очереди в одном окне, каждый — своя композиция
(`key`). В песочнице Robolectric диспетчер Compose запоминает
Choreographer первого теста, и в следующих тестах эффекты (переход пульта,
вкладка «AI», загрузка данных) не идут — отдельные тесты давали один и тот
же снимок. Перед снимком главный цикл прокручивается шагами по 50 мс с
настоящим ожиданием между ними: данные «AI» грузятся в фоновых потоках по
настоящему времени.

## Пока не снимается

- IDE с открытым файлом: в песочнице список файлов демо не загружается, а
  крутилка загрузки — бесконечная анимация, на каждом её кадре Robolectric
  сдвигает часы, и прокрутка цикла идёт минутами.
- Тёмная тема и другие размеры экрана.

Тесты виджета на минимальном Android 11 запускаются отдельно:
`./gradlew :shell:testDebugUnitTest -Pdpmeta.screenshots=true -Pdpmeta.test.sdk=30 --tests '*StudioWidgetTest'`.
По умолчанию используется API 36; свойство выбирает один из двух
закреплённых образов со сверкой Gradle, загрузка самим Robolectric запрещена.
