# Производительность

Бюджеты критических путей (ТЗ, §114). «Работает быстро» — не критерий:
у каждого пути — число, у числа — замер. Оптимизация — только по
замеру (ТЗ, §17; этап 17).

## 1. Принцип

- Бюджет записывается раньше, чем путь оптимизируется.
- Замер — на хосте (JVM) для ядра и на целевом устройстве для
  интерфейса; условия замера записываются рядом с числом.
- Телеметрия приложения (задержки, память, кадры) не смешивается с
  учётом провайдера (токены, запросы, стоимость) (ТЗ, §48).

## 2. Пределы в коде

Пределы, которые защищают от исчерпания ресурсов (ТЗ, §113), — в коде с
тестом:

| Предел | Значение | Где | Тест |
|---|---|---|---|
| Размер документа JSON | 16 МиБ по умолчанию, задаётся вызывающим | `JsonParser.Limits` | `JsonTest` |
| Глубина JSON | 64 по умолчанию | `JsonParser.Limits` | `JsonTest` |

## 3. Бюджеты (цели, замер — этап 17)

| Путь | Бюджет | Условия |
|---|---|---|
| Холодный старт приложения до сводки | ≤ 1,5 с | целевое устройство, 1000 задач в базе |
| Отрисовка сводки | ≤ 16 мс на кадр | 20 активных сессий |
| Создание задачи | ≤ 50 мс | включая запись в журнал |
| Такт планировщика | ≤ 20 мс | 1000 задач, 100 аккаунтов, 50 targets |
| Приём события | ≤ 2 мс среднее, ≤ 20 мс p99 | поток 100 событий/с |
| Запись в хранилище | ≤ 10 мс p99 | атомарная запись с fsync |
| Запрос списка сессий | ≤ 30 мс | 1000 сессий в истории |
| Поиск | ≤ 200 мс | 100 тыс. событий |
| Сборка контекста | ≤ 500 мс | средний проект, без сети |
| Отправка уведомления | ≤ 50 мс | после дедупликации |

Числа — стартовые цели этапа 0; меняются только с замером и записью
причины.
