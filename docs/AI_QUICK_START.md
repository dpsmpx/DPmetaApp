# Быстрый старт разработки с API-моделью

D-182, DP_AI_Orcestrator:D-214. Первый путь — «AI → Модели → Быстрый
старт с ИИ». Он также доступен у профиля, из обычного чата, во вкладке
ИИ рабочего проекта и при пустом списке мест выполнения.

1. Выбрать существующий клон или уже настроенный рабочий проект.
2. Выбрать подключённый профиль либо провайдера и ввести его API-ключ.
   Адрес стандартного провайдера, имя профиля и служебные каталоги
   приложение задаёт само. Ключ хранится в прежнем Keystore.
3. Выбрать модель из полученного списка и нажать «Начать работу».
   Клон не скачивается повторно; привязка к рабочему месту создаётся
   автоматически и повторно не дублируется. При необходимости среда
   телефона распаковывается из APK. Вход в подписку CLI для API-чата не нужен.
4. Написать задачу. До сообщения код провайдеру не отправляется и платный
   ход не начинается. В проектном чате доступны чтение, поиск, создание,
   точная замена и удаление файлов, запуск профилей проверки/сборки.

Провайдеры: Anthropic Messages, официальный OpenAI Responses (в том числе
кодовые модели), OpenAI-совместимые Chat Completions, Gemini. Если провайдер
сообщает, что модель не поддерживает инструменты, мастер её не предлагает.
Embeddings и генераторы изображений не выбираются вместо кодового помощника.

Ключ API остаётся в приложении и HTTP-транспорте. Модель получает код
выбранного проекта; служебный Git, известные файлы ключей и другие
проекты файловыми инструментами не доступны. Символьные ссылки не
проходятся. Чтение больших файлов идёт частями с суммой исходника;
устаревшая сумма не позволяет заменить файл.

Запись использует общий замок проекта, проверяет занятость и черновики,
сохраняет зашифрованную копию. «Проект и изменения» открывает рабочий
экран с Git diff и отменой последней файловой правки. Незавершённая запись
оставляет проект на паузе до восстановления. API-ход после перезапуска
не повторяется сам; выполнявшийся профиль восстанавливается без нового start.

Проверки выполняются через прежний механизм ручных профилей, с реальным
итогом и выводом. Сначала используется профиль проекта; для распространённых
Gradle/Python/CMake/Make-проектов есть начальные варианты. Уникальные команды
проекта настраиваются в прежнем редакторе профилей. Установка SDK/тулчейна
и исправление окружения остаются в «Окружении»: наличие API-ключа само
по себе не устанавливает все библиотеки проекта и не означает успешную сборку.

Обычные чаты без доступа к проекту, свои адреса API, дополнительные
параметры профилей, CLI-подписки, SSH-targets и их ручные формы сохранены.
Мастер предлагает быстрый путь, расширенная настройка доступна рядом.

На устройстве требуется приёмка: первый запуск с единственным ключом,
существующий клон без targets, повторное открытие, замена неверного ключа,
работа в фоне, отмена и восстановление. Синтетические API-тесты не используют
чужие ключи и не выполняют платные запросы.
