# Модель аккаунтов

Слоты аккаунтов AI-провайдера, их учётные данные, возможности и выбор.
Код — модуль `accounts` (этап 5); автомат — `core`, `AccountLifecycle`
(этап 1).

## 1. Слоты и пределы

Число слотов в модели не ограничено (ТЗ, §9). Параллелизм ограничен:
лимитами провайдера, числом execution targets, CPU и памятью, сетью,
политикой пользователя, доступными учётными данными. Слот — аккаунт,
который пользователь законно контролирует; оркестратор не обходит
лимиты и не маскирует идентичность (D-04).

Разделение сущностей (ТЗ, §10):

| Сущность | Что | Где хранится |
|---|---|---|
| `AIAccount` | слот: провайдер, метка, возможности, политика, состояние | база оркестратора |
| `Authentication` | способ входа; в V1 — вход по подписке через сам Claude Code (D-27) | база — вид и ссылка |
| `Credential` | вход claude.ai | на target, в каталоге настроек слота (`CLAUDE_CONFIG_DIR`); оркестратор его не читает и не хранит (D-27); `credentialRef` — путь к каталогу |
| `ExecutionSession` | применение входа в одной сессии | процесс `claude` на target с `CLAUDE_CONFIG_DIR` слота; секретов в аргументах, журнале и событиях нет |

## 2. Автомат состояний

Начальное — `AUTH_REQUIRED` (учётные данные ещё не проверены).
`DISABLED` выходит только явной операцией: включение → `AUTH_REQUIRED`.

| Из | В (обычный переход) |
|---|---|
| `AUTH_REQUIRED` | `AVAILABLE`, `ERROR`, `DISABLED` |
| `AVAILABLE` | `BUSY`, `COOLDOWN`, `RATE_LIMITED`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `BUSY` | `AVAILABLE`, `COOLDOWN`, `RATE_LIMITED`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `COOLDOWN` | `AVAILABLE`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `RATE_LIMITED` | `COOLDOWN`, `AVAILABLE`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `ERROR` | `AVAILABLE`, `COOLDOWN`, `AUTH_REQUIRED`, `DISABLED` |
| `DISABLED` | — (явно: `AUTH_REQUIRED`) |

- `AVAILABLE` — может принять ещё одну сессию; `BUSY` — достигнут
  предел параллельных сессий по политике аккаунта;
- `COOLDOWN` — пауза после ошибок или по политике распределения;
- `RATE_LIMITED` — провайдер сообщил о пределе; выход — через
  `COOLDOWN` или по времени, указанному провайдером.

## 3. Возможности

Возможности слота (ТЗ, §51): модель, программирование, рассуждение,
длительная работа, инструменты, удалённое исполнение, структурированный
вывод. Задача объявляет `requiredCapabilities`; планировщик выбирает
только совместимые слоты (`docs/SCHEDULER.md`, §4).

## 4. Изоляция

Каждая сессия несёт `accountId`, `credentialRef`, `executionTargetId`;
перед запуском они сверяются (ТЗ, §66). Изоляция на target — свой
каталог настроек Claude Code на слот (D-27): процесс сессии слота A
запускается с `CLAUDE_CONFIG_DIR` слота A и не видит входа слота B, даже
на одном target. Вход пользователь выполняет сам, через поток
Anthropic; оркестратор только проверяет, что слот вошёл (`AUTH_REQUIRED`
— если нет).

## 5. Журнал

Каждое изменение состояния слота — событие (`ACCOUNT_STATE_CHANGED`,
`ACCOUNT_RATE_LIMITED`, `ACCOUNT_AUTH_REQUIRED`) без секретов (D-14).

## 6. Риски подписок

Наблюдения на 6 октября 2026 (`docs/research/CLAUDE_CODE_CLI.md`, §6);
решения по ним — за автором, оркестратор их не обходит:

| Риск | Что известно | Что делает оркестратор |
|---|---|---|
| Регион | Россия не входит в страны, где Anthropic предоставляет и Claude.ai, и API | ничего не скрывает и не маскирует; потеря доступа к слоту — обычный отказ `AUTH_REQUIRED` или `DISABLED`, состояние задач сохраняется (D-01) |
| Несколько подписок для продолжения после предела | пределы Pro и Max рассчитаны на «обычное индивидуальное использование»; правила запрещают вести несколько аккаунтов, чтобы обойти защитные механизмы | не создаёт аккаунты; слот на пределе ждёт сброса; переход к другому слоту — только если автор завёл его сам, и это его решение (`TODO.md`, «Открытые вопросы автору») |
| Изменение условий для `claude -p` | перевод `claude -p` и Agent SDK на отдельный кредит объявлен и приостановлен 15 июня 2026 | расход и пределы — `Measure` из ответов Claude Code; при изменении условий — новая запись в `docs/research/` и пересмотр политики слотов |
| Истечение входа | вход по подписке истекает; без входа запросы падают | слот → `AUTH_REQUIRED`, уведомление автору; задачи — к другому слоту или в ожидание |
