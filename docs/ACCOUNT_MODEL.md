# Модель аккаунтов

Подписки Claude, их слоты на targets, пределы, защиты от пересечения,
выбор слота и уведомления. Код — модуль `accounts` (этап 5, начат по
слову автора раньше этапов 3–4: логика не зависит от транспорта);
автомат слота — `core`, `AccountLifecycle`. Решения — D-27, D-29, D-30.

Основной режим — **одна подписка** (D-30): всё ниже работает в нём
полностью; несколько подписок добавляют только защиты от пересечения
(§4) и переход задачи между подписками (§5).

## 1. Подписка и слот

| Сущность | Что | Где живёт |
|---|---|---|
| Подписка (`SubscriptionId`, `sub_…`) | аккаунт Claude (Pro или Max) с общими пределами: окно пяти часов и недельный | состояние — события в журнале; отпечаток аккаунта — хеш `orgId` и email, сам email не хранится |
| Слот (`AccountId`, `acc_…`; `AIAccount` ТЗ, §7) | подписка, вошедшая в Claude Code на одном target в своём каталоге настроек | вход — на target в `CLAUDE_CONFIG_DIR` слота, создан формой Claude; оркестратор его не читает и не хранит (D-27); `credentialRef` — путь к каталогу |
| Аренда | сессия оркестратора ↔ слот | одна сессия — ровно один слот на всё время жизни |

Одна подписка может быть слотами на Termux, Linux и Windows: пределы у
них общие (§3). Вход — только формой Claude (D-29): Claude Code должен
сообщать `authMethod = "claude.ai"`; ключи API, `apiKeyHelper`, токены
`setup-token` и облачные провайдеры не поддерживаются.

Число слотов и подписок в модели не ограничено (ТЗ, §9); параллелизм
ограничен пределами подписки, политикой (`maxParallelSessions`
подписки), ресурсами targets. Оркестратор не создаёт аккаунты и не
скрывает, какой аккаунт работает (D-04).

## 2. Автомат слота

Начальное — `AUTH_REQUIRED` (вход ещё не проверен). `DISABLED` выходит
только явной операцией: включение → `AUTH_REQUIRED`.

| Из | В (обычный переход) |
|---|---|
| `AUTH_REQUIRED` | `AVAILABLE`, `ERROR`, `DISABLED` |
| `AVAILABLE` | `BUSY`, `COOLDOWN`, `RATE_LIMITED`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `BUSY` | `AVAILABLE`, `COOLDOWN`, `RATE_LIMITED`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `COOLDOWN` | `AVAILABLE`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `RATE_LIMITED` | `COOLDOWN`, `AVAILABLE`, `AUTH_REQUIRED`, `ERROR`, `DISABLED` |
| `ERROR` | `AVAILABLE`, `COOLDOWN`, `AUTH_REQUIRED`, `DISABLED` |
| `DISABLED` | — (явно: `AUTH_REQUIRED`) |

Состояние слота не задаётся напрямую, а выводится из фактов (D-30), по
первому подходящему правилу:

| Факт | Состояние |
|---|---|
| автор отключил слот | `DISABLED` |
| вход не проверен или требуется | `AUTH_REQUIRED` |
| запрещённый способ входа, вход другим аккаунтом, аккаунт уже другая подписка | `ERROR` |
| подписка упёрлась в предел, сброс не наступил | `RATE_LIMITED` |
| серия ошибок слота, пауза не истекла | `COOLDOWN` |
| у подписки занято `maxParallelSessions` сессий | `BUSY` |
| иначе | `AVAILABLE` |

Вход проверяет `SlotAuthProbe` (модуль `orchestrator`): `claude auth
status --json` под агентом target с окружением слота (`CLAUDE_CONFIG_DIR`
слота, без перекрывающих вход переменных); итог — `observeAuthStatus`.
Вход делается сразу в каталог слота: при входе без него у Claude Code
нет файла настроек в каталоге слота, и отпечаток аккаунта неизвестен
(`docs/research/CLAUDE_CODE_CLI.md`, §10).

Если прямого перехода нет (например, `RATE_LIMITED` → `BUSY`),
выбирается кратчайший путь по таблице; каждый шаг — событие
`ACCOUNT_STATE_CHANGED`. Так история состояний всегда допустима.

## 3. Пределы

Пределы — подписки, не слота: предел, замеченный любым слотом, действует
на все слоты этой подписки.

| Окно | Длина | Уровни |
|---|---|---|
| `SESSION` | пять часов, скользящее | `OK`, `NEAR`, `REACHED` |
| `WEEKLY` | неделя | `OK`, `NEAR`, `REACHED` |

- `REACHED` — все слоты подписки в `RATE_LIMITED` до сброса: время сброса
  известно — до него; неизвестно — до первого успешного запроса или до
  истечения длины окна от наблюдения. Неизвестное время сброса — не ноль
  (D-13): оркестратор не выдумывает его, а сообщает «неизвестно» и
  предлагает пробный запрос не чаще `unknownResetProbeInterval`.
- `NEAR` — новые задачи на эту подписку не начинаются (по умолчанию),
  работающие и продолжения задач, уже шедших на ней, продолжаются.
- Сброс по времени делает такт (`tick`); `nextWakeUp` говорит
  планировщику, когда такт нужен.
- Где брать сигналы: ответы Claude Code в сессии и `claude auth status`
  (этап 4); формат сообщений о пределе — `docs/research/CLAUDE_CODE_CLI.md`,
  §7 (ещё не проверено).

## 4. Защиты от пересечения

| Пересечение | Защита | Код |
|---|---|---|
| два слота с одним каталогом настроек на одном target (общий вход) | регистрация второго отвергается | `ACCOUNT_CONFIG_DIR_IN_USE` |
| в каталоге слота вход другим аккаунтом, чем у его подписки | слот → `ERROR`, событие пересечения, уведомление `SECURITY` | `ACCOUNT_IDENTITY_MISMATCH` |
| один аккаунт Claude зарегистрирован двумя подписками (двойной счёт пределов) | второй слот → `ERROR` | `ACCOUNT_DUPLICATE_SUBSCRIPTION` |
| вход не формой Claude (ключ, `apiKeyHelper`, токен) | слот → `ERROR` (D-29) | `ACCOUNT_AUTH_METHOD_FORBIDDEN` |
| чужие учётные данные в окружении процесса | окружение — разрешённым набором, перекрывающие переменные удаляются, `CLAUDE_CONFIG_DIR` слота задаётся | `ACCOUNT_ENVIRONMENT_SANITIZED` (предупреждение с именами, без значений) |
| сессия на двух слотах | аренда идемпотентна: повторная — тот же слот; другой — отказ | `ACCOUNT_LEASE_CONFLICT` |
| задача скачет между подписками | переход только к подписке с `rotationAllowed`, только между сессиями, не чаще `maxSwitchesPerTask` за `switchWindow` | `ACCOUNT_SWITCH_LOOP` |
| отпечаток аккаунта неизвестен (Claude Code не сообщил) | слот работает, но проверка пересечения по аккаунту недоступна — предупреждение, а не молчание | `ACCOUNT_IDENTITY_UNKNOWN` |

## 5. Выбор слота

Аренда для сессии задачи (`lease`) детерминирована (D-22):

1. Кандидаты — слоты в `AVAILABLE` (на нужном target, если указан); у
   подписки с `NEAR` — только для продолжения задачи, уже шедшей на ней.
2. Задача уже шла на подписке — сначала её слоты.
3. Её подписка недоступна — другая, только если у той `rotationAllowed`
   и петли переключений нет (§4); событие `ACCOUNT_SWITCHED`.
4. Порядок среди равных: меньше сессий у подписки, меньше у слота,
   затем идентификатор слота (ТЗ, §85).
5. Подходящего нет — отказ `ACCOUNT_NONE_AVAILABLE` (повторяемый) с
   причиной и временем ближайшего сброса, если оно известно. В режиме
   одной подписки это и есть «ждать сброса».

Серия из `errorsBeforeCooldown` ошибок слота подряд ставит его в
`COOLDOWN` на `errorCooldown`; успешный запрос серию сбрасывает.

## 6. Риски подписок

Наблюдения на 6 октября 2026 (`docs/research/CLAUDE_CODE_CLI.md`, §6);
решения по ним — за автором, оркестратор их не обходит:

| Риск | Что известно | Что делает оркестратор |
|---|---|---|
| Регион | Россия не входит в страны, где Anthropic предоставляет и Claude.ai, и API | ничего не скрывает и не маскирует; потеря доступа к слоту — обычный отказ `AUTH_REQUIRED` или `DISABLED`, состояние задач сохраняется (D-01) |
| Несколько подписок для продолжения после предела | пределы Pro и Max рассчитаны на «обычное индивидуальное использование»; правила запрещают вести несколько аккаунтов, чтобы обойти защитные механизмы | не создаёт аккаунты; основной режим — одна подписка; переход к другой подписке — только если автор сам её завёл и разрешил (`rotationAllowed`) — по его решению (D-30) |
| Изменение условий для `claude -p` | перевод `claude -p` и Agent SDK на отдельный кредит объявлен и приостановлен 15 июня 2026 | расход и пределы — из ответов Claude Code; при изменении условий — новая запись в `docs/research/` и пересмотр политики |
| Истечение входа | вход по подписке истекает; без входа запросы падают | слот → `AUTH_REQUIRED`, уведомление с инструкцией; задачи ждут или идут на другой слот той же подписки |

## 7. Уведомления

Одинаковы при одной и нескольких подписках; переход между подписками —
только при нескольких. Повторы одного ключа агрегируются, рост
серьёзности проходит сразу (модуль `notifications`, ТЗ, §36). Повторное
наблюдение предела без изменений (проба при неизвестном сбросе) пишется
в журнал, но уведомлением не становится; сброс, вход и снятая пауза
закрывают своё уведомление.

| Событие | Категория | Смысл уведомления |
|---|---|---|
| предел `NEAR` | `WARNING` | близко к пределу окна; новые задачи отложены, работающие продолжаются; когда сброс |
| предел `REACHED` | `BLOCKED` | предел достигнут; когда сброс или «неизвестно»; задачи ждут |
| сброс предела | `SUCCESS` | подписка снова доступна; задачи продолжаются |
| нужен вход | `BLOCKED` | на каком target и с каким каталогом выполнить `claude` и войти формой Claude |
| вход скоро истечёт | `WARNING` | когда; как обновить |
| запрещённый способ входа | `SECURITY` | какой способ сообщил Claude Code; слот остановлен (D-29) |
| пересечение аккаунтов | `SECURITY` | какой слот, что за пересечение; слот остановлен |
| cooldown слота | `WARNING` | серия ошибок; до какого времени пауза |
| задача перешла на другую подписку | `INFO` | с какой на какую, почему |

Каждое уведомление ведёт по ссылке `dpai://account/<id>` или
`dpai://subscription/<id>` прямо к сущности (ТЗ, §76).

## 8. Журнал

Каждое изменение — событие без секретов (D-14): регистрация подписки и
слота, вход, подтверждение аккаунта, пересечение, предел и сброс,
истечение входа, ошибки и их сброс, отключение и включение, аренда и
освобождение, переход задачи, смена состояния слота. Состояние
аккаунтов восстанавливается из журнала и снимков (D-24).
