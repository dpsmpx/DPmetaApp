# Стратегия бэкенда: сравнение A–D

Дата: **4 октября 2026**. Решение по результатам — `DECISIONS.md`, D-03
и D-04.

## 1. Варианты

- **A. Xray-first** — первое и единственное реальное ядро Xray-core.
- **B. sing-box-first** — первое ядро sing-box (libbox).
- **C. Xray + sing-box за абстракцией** — оба ядра сразу.
- **D. Собственное сетевое ядро.**

## 2. Сравнение

| Критерий | Xray-core (v26.9.30) | sing-box (1.14 / testing) | Собственное ядро |
|---|---|---|---|
| Лицензия | **MPL-2.0** (файловый копилефт: изменённые файлы ядра — открыть; код DPpass не затрагивается); обёртка `XTLS/libXray` — **MIT** | **GPL-3.0-or-later** + запрет использовать имя; в одном процессе с приложением — всё APK как производное под GPL | своя |
| Сопровождение | активное: релизы каждые 1–4 недели (26.7.11, 26.7.28, 26.9.8, 26.9.9, 26.9.30) | активное; основной разработчик один | всё на DPpass |
| Android-интеграция | gomobile/c-shared через libXray или своя обёртка; TUN inbound с fd (с 26.1.13) или внешний мост | развитая: libbox, своя TUN-платформа, SFA как эталон | с нуля |
| Память/размер | Go-рантайм: десятки МБ RSS, бинарник ~20–30 МБ на ABI (оценка, мерить — этап 2) | сопоставимо | неизвестно |
| Покрытие протоколов | VLESS, Vision, REALITY, **XHTTP (только Xray)**, WS, gRPC, HTTPUpgrade, Trojan, SS-2022, **Hysteria2 (с 26.1.13)**, WireGuard, SOCKS, HTTP, VMess, MASQUE | VLESS (+Reality, Vision), WS, gRPC, HTTPUpgrade, Trojan, SS, Hysteria2, **TUIC, AnyTLS, Naive, ShadowTLS**, WireGuard, OpenVPN, SSH, MASQUE; **нет XHTTP** | — |
| Частота изменений схемы | высокая, бывают ломающие (finalmask 26.7.28) | высокая, есть политика устаревания | — |
| История безопасности | открытые исправления в релизах (например, утечка UDP SS2022, январь 2026; проверка листового сертификата при пиннинге, январь 2026) | сопоставимо | неизвестна, дорого получить |
| Настраиваемость | очень высокая (JSON) | очень высокая (JSON) | — |
| Тестируемость | `xray -test` проверяет конфигурацию без запуска; запуск на хосте | `sing-box check` | — |
| Значение для РФ (на 10.2026) | основная экосистема серверов и панелей (3x-ui, Marzban, Remnawave и др.) отдаёт ссылки и JSON под Xray | меньше серверной экосистемы в РФ | — |

## 3. Оценка вариантов

- **A** покрывает все три класса транспортов (TCP/TLS, HTTP/CDN,
  UDP/QUIC) одним ядром с допустимой лицензией и совпадает с серверной
  экосистемой, которой пользуются российские поставщики. Риск:
  моноядро — при регрессии ядра нет запасного; смягчается
  закреплённой версией и корпусом регрессий (D-18).
- **B** даёт лучшую Android-интеграцию и TUIC/AnyTLS/ShadowTLS, но
  **GPL-3.0+ в одном процессе** с приложением делает весь APK
  производным под GPL. Это меняет модель распространения DPpass
  (сейчас — Apache-2.0, закрытый репозиторий) — решение уровня автора,
  не инженерное. Нет XHTTP.
- **C** сейчас — двойная стоимость интеграции, тестов, обновлений и
  лицензий без доказанной пользы: XHTTP и Hysteria2 уже есть в Xray;
  уникальное у sing-box (TUIC, AnyTLS, ShadowTLS, Naive) не входит в
  первый набор (`TRANSPORT_COMPARISON.md`, §5).
- **D** отклоняется: собственный TLS/транспорт/стек — ровно то, что
  запрещено «спекулятивным переусложнением»; «полный контроль» не
  оправдывает годы работы и риск безопасности.

## 4. Итог

**A сейчас, с архитектурой C**: одно реальное ядро (Xray) и
абстракция (`ProxyEngine`, `BackendCompiler`, матрица возможностей),
проверенная вторым — пока фиктивным — бэкендом `MockProxyEngine` с
другим набором возможностей. Второе реальное ядро — отдельным
решением, когда появится транспорт, нужный пользователям и
недоступный в Xray, и после решения о лицензии (D-20).

Что не делать: не тащить sing-box «на всякий случай»; не форкать ядро;
не обновлять ядро «потому что вышло» (D-18).

## 5. Xray 26.9.30: на что опирается компилятор

Дата: **4 октября 2026**. Источник — исходники upstream на теге
`v26.9.30` (коммит `b26a91de4f32`, D-24), прочитанные при выборе версии;
пути ниже — внутри модуля `github.com/xtls/xray-core` (и его
зависимости `github.com/apernet/quic-go`). Факты проверяются эталонами и
шагом hostcheck «Xray» лишь в той части, которую видит `xray run -test`
(сборка конфигурации без соединений); остальное держится на отказах
компилятора и при смене версии перечитывается заново (D-18).

| Свойство | Где | Что из этого следует для DPpass |
|---|---|---|
| DNS-over-TLS нет: адрес сервера — `localhost`, `https`/`h2c` (с `+local` — мимо маршрутизации), `quic+local`, `tcp`/`tcp+local`, `fakedns` или классический UDP; строка `tls://…` ушла бы в классический UDP | `app/dns/nameserver.go`, `NewServer` | `DNS_DOT` нет в матрице; DoT — отказ, а не открытый DNS |
| Сервер для имени: совпавшие по доменам — по порядку записи; `finalQuery` — дальше не спрашивать; `skipFallback` — не быть запасным для чужих имён | `app/dns/dns.go`, `sortClients` | правило DNS — отдельная запись сервера: имя видит только сервер первого сработавшего правила |
| `queryStrategy` `UseIPv4`/`UseIPv6`: запрос другого семейства — пустой ответ без ошибки | `app/dns/dns.go`, `LookupIP`; `proxy/dns/dns.go`, `handleIPQuery` | смысл `ipv4_only`/`ipv6_only` сохраняется и для перехваченных запросов приложений |
| `allowInsecure` удалён: ошибка сборки конфигурации с отсылкой к `pinnedPeerCertSha256` и `verifyPeerCertByName` | `infra/conf/transport_security.go` | компилятор не пишет ни его, ни замен (T5) |
| Пустой `fingerprint` у TLS — отпечаток Chrome | `transport/internet/tls/tls.go`, `GetFingerprint` | «без отпечатка» в IR — отпечаток ядра по умолчанию (`docs/CONFIG_FORMAT.md`) |
| Hysteria2 (`hysteria`) соединяется через HTTP/3-транспорт quic-go: uTLS не участвует, ALPN всегда `h3` | `transport/internet/hysteria/dialer.go`; `http3/transport.go` в `apernet/quic-go` | `fingerprint` и иной `alpn` у Hysteria2 — отказ, а не молчаливое игнорирование |
| Ключ Shadowsocks-2022 читается как base64 `StdEncoding`; не сумев — байты строки берутся как ключ, «:» делит строку на несколько ключей | `proxy/shadowsocks_2022/kdf.go`, `ParseKey` и `ParsePSKList` | ключ раскодируется и записывается заново со стандартным дополнением |

## 6. Xray 26.9.30 внутри процесса: на что опирается мост

Дата: **4 октября 2026**. Источник — те же исходники upstream
(`v26.9.30`, коммит `b26a91de4f32`) и модуль `gvisor.dev/gvisor` из
`tools/xray/go.sum`, прочитанные при выборе обёртки ядра (D-25). Пути —
внутри модуля `github.com/xtls/xray-core`, если не сказано иное.

| Свойство | Где | Что из этого следует для DPpass |
|---|---|---|
| Хуки сокетов (`RegisterDialerController`) вызываются для каждого сокета системного dialer: TCP — `net.Dialer.Control`, UDP — `ListenConfig.Control`, а также для системного резолвера ядра; хук один на процесс, снять его нельзя | `transport/internet/system_dialer.go`, `Dial` и `RegisterDialerController`; `features/dns/localdns/client.go`, `New` | `protect()` — один хук на процесс, который спрашивает защитника текущего сеанса |
| Ошибку хука Xray только журналирует: сокет идёт дальше, соединение устанавливается | там же: `errors.LogInfoInner(…, "failed to apply external controller")` | отказ `protect()` мост закрывает сам, на уровне сокета |
| Все исходящие транспорта клиента (`raw`, `ws`, `grpc`, `xhttp`, `httpupgrade`, `hysteria`) и DNS с `+local` соединяются через `internet.DialSystem` → системный dialer | `transport/internet/*/dialer.go`; `app/dns/nameserver_doh.go`, `nameserver_tcp.go` | хук видит все сокеты ядра к серверу и прямые соединения |
| `core.New` переназначает глобальные DNS-клиент и менеджер исходящих системного dialer (`InitSystemDialer`); по ним `DialSystem` резолвит имя, если у исходящего задан `sockopt.domainStrategy` (у `direct` компилятора — `ForceIPv4v6`) | `core/xray.go`, `initInstanceWithConfig`; `transport/internet/dialer.go`, `DialSystem` и `LookupForIP` | второй `core.New` при работающем ядре подменил бы ему резолвер — проверка на ходу без `core.New` |
| Вход TUN на Android берёт fd из переменной окружения `xray.tun.fd`; без неё — fd 0. Устройство открывается в `Handler.Start`, а не в `core.New` | `common/platform/platform.go`, `TunFdKey`; `proxy/tun/tun_android.go`, `NewTun`; `proxy/tun/handler.go`, `Start` | вход TUN ⇔ передан fd; `xray run -test` и проверка fd не трогают |
| Ядро fd TUN не закрывает (`AndroidTun.Close` пустой); остановка стека отсоединяет fd-канал gVisor, а `Attach(nil)` ждёт, пока циклы чтения fd завершатся | `proxy/tun/stack_gvisor.go`, `Close`; `gvisor.dev/gvisor`: `pkg/tcpip/link/fdbased/endpoint.go`, `Attach` | fd остаётся у платформы; закрывать — после остановки ядра |
