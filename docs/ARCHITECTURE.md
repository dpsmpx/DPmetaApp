# Устройство

Как устроен DPvisualisation 1.0. Что строится и зачем — ТЗ
(`docs/direction/TECHNICAL_TASK.md`), что решено — `docs/direction/DECISIONS.md`,
форматы — `docs/FORMATS.md`, как пользоваться — `docs/OPERATIONS.md`.

## 1. Части и поток данных

```
model/ecosystem.toml ──model build──► data/model.json ─────────────────┐
  (узлы, потоки, ссылки)               dpvis-model/1                     │
                                                                         ▼
клоны экосистемы ─┐                                              viewer/ (ES-модули)
DPmeta: реестр, ──┼──collect──► data/state/latest.json ─────────► просмотрщик
  контракты       │              dpvis-state/1                          ▲
                                                                         │
                                                                         │
serve: сбор по расписанию + сервер 127.0.0.1 (viewer/, data/) ──опрос────┘
build:         viewer + модель + срез ─► dist/dpvisualisation.html (один файл)
build --site:  публичная выжимка ─► dpvis.js, dpvis.css, dpvis-data.json, MANIFEST.json
               └─► SocialMediaImage: site ecosystem-import → /ecosystem/ на dpsmpx.com
```

Модель пишется руками и меняется редко; срез собирается из клонов и
меняется с каждым коммитом экосистемы. Оба файла лежат в репозитории
(D-02, D-13): просмотрщик и DPmetaApp показывают реальные данные сразу
после клонирования, без клонов всей экосистемы.

## 2. Пакет `tools/dpvis/` (Python ≥ 3.11, только стандартная библиотека)

| Модуль | Что делает |
|---|---|
| `__main__.py` | команды `model check|build`, `collect`, `validate`, `build`, `serve`; коды возврата 0–3 |
| `model.py` | каталоги видов, состояний, транспорта и сигналов (ТЗ §8); чтение TOML, проверка, детерминированная сборка `dpvis-model/1` |
| `gitlog.py` | чтение клона без рабочего дерева: основная ветка, коммиты, ветки с невлитой работой (`git cherry`), признак ИИ |
| `collect.py` | срез `dpvis-state/1`: наблюдения узлов, участники, сигналы потоков, диагностика |
| `registry.py` | сверка с DPmeta: реестр `ecosystem.toml` и заголовки `C-NN` (D-11) |
| `rules.py` | все пороги и окна, `RULES_VERSION` (D-04) |
| `formats.py` | проверка документов по `schemas/` своим кодом, связность среза с моделью |
| `public.py` | публичная выжимка для сайта: белый список полей, `FORBIDDEN` — отказ сборки (D-15) |
| `build.py` | склейка модулей просмотрщика: один HTML или комплект для сайта |
| `serve.py` | локальный живой просмотр: сервер `127.0.0.1` только для `viewer/` и `data/`, сбор по расписанию с атомарной заменой (D-12); образец опроса для DPmetaApp (D-18) |

Срез — функция модели, клонов, времени среза и правил (D-04): с одним
`--now` два сбора дают одинаковые байты. Ожидаемые отказы (нет клона,
неполная история) — записи `diagnostics`, а не
падение: остальное собирается дальше.

## 3. Просмотрщик `viewer/` (HTML, CSS, JS без библиотек)

| Модуль | Что делает |
|---|---|
| `src/data.js` | разбор модели, среза и публичной выжимки в один «вид»: узлы, потоки, дни окна, числа |
| `src/filters.js` | фильтры, поиск, фокус соседей, адрес вида `#…` |
| `src/layout.js` | раскладка от ширины контейнера (D-16): колонки слоёв или полосы сверху вниз; связи — прямые от края до края |
| `src/graph.js` | SVG: узлы, связи со стрелкой, толщина — события за неделю; масштаб кнопками; перестроение при смене ширины |
| `src/panel.js` | подробности узла и потока; график по дням и таблица значений |
| `src/tables.js` | вкладки «Таблицы» и «Сверка»; на узком месте строки — карточками |
| `src/main.js` | каркас экрана, загрузка данных, опрос среза, шкала времени, легенда, тема, клавиатура |
| `src/format.js`, `src/dom.js` | даты по `+03:00`, числа; создание элементов без `innerHTML` |

Данные просмотрщик берёт по порядку: `data-src` у корня (сайт) →
встроенный JSON (сборка одного файла) → `?model=&state=` того же
источника → `../data/` рядом со страницей (живой режим). Встраивающая
страница может передать данные `postMessage({type: "dpvis:data"})`.

Схема без анимаций (D-16): единица схемы — пиксель экрана, поэтому текст
не мельчает, а ширина схемы равна ширине контейнера — прокрутки вбок нет.
Колонки слоёв, если помещаются; иначе слои — полосами сверху вниз. При
смене ширины раскладка строится заново; при новом срезе той же ширины —
сохраняются масштаб, сдвиг, выбор и фильтры (F-45).

Под строгой CSP сайта (`script-src 'self'`, без встроенных скриптов и
стилей) просмотрщик работает как есть: стили задаются классами, а
единственные вычисляемые свойства (`left`, `top` подсказки, высота) —
через CSSOM, который CSP не запрещает.

## 4. Проверки `tools/check/`

`run.sh` вызывает `python3 -m tools.check`: правила `checks.py` (уровень
`static`) и `slow.py` (уровень `full`: тесты, сборка, дым в Chromium с
проверкой прокрутки вбок при 390 px). Самотесты правил —
`tests/test_check.py`. Подробно — `docs/PROCESS.md`, раздел 3.

## 5. Границы

- Клоны только читаются; `git fetch` — только с `--fetch` (D-03). К сайту
  и сервисам сборщик не обращается (D-19).
- Наружу (сайт) — только публичная выжимка через SocialMediaImage; здесь
  нет ни команд выгрузки, ни ключей (D-14, D-15).
- Своих серверов в сети нет: живой режим схемы — в DPmetaApp (D-18),
  `serve` — локальный процесс на устройстве автора (D-12).
- В модели — только текущая система (D-20): архив из реестра DPmeta
  исключён из сверки с причиной (`[registry] exclude`).
