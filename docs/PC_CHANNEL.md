# Канал к домашнему ПК: проверка дома

D-88: нужен доступ из города к домашнему Windows 11 Pro при постоянно
включённом VPN на телефоне, без раздачи с телефона, без своего
VPN-сервера и без второго Android VPN; внешний или платный relay не
выбран. Какой транспорт возможен, решают условия сети дома и у VPN —
их проверяют два скрипта ниже. Итог присылается в сессию, по нему
выбирается транспорт (ROADMAP, этап 7).

Скрипты только читают и соединяются; ничего не меняют. Итог печатается
без полных адресов — его можно прислать как есть.

## 1. На ПК (дома, Windows 11)

PowerShell от своего пользователя, из каталога клона DPmetaApp:

```powershell
powershell -ExecutionPolicy Bypass -File tools\pc\check_channel.ps1
```

Что проверяется: глобальный IPv6 и выход по нему; внешний IPv4 и признаки
двойного NAT провайдера (CGNAT); UPnP на роутере; служба OpenSSH Server,
порт 22, правило брандмауэра и профиль сети; время до сна. В конце —
полный постоянный IPv6 ПК: он нужен для шага 2, в чат его не присылать.

## 2. С телефона (вне дома, VPN включён как обычно)

В Termux или в терминале Linux приложения:

```sh
sh tools/pc/check_channel.sh <IPv6 ПК из шага 1>
```

Нет IPv6 у ПК — вместо него внешний IPv4 (тогда на роутере должен быть
проброс порта 22 на ПК). Проверяется выход телефона по IPv6 и IPv4 через
текущую сеть и VPN и TCP-соединение до ПК.

## Как читать итог

| ПК | Телефон | TCP до ПК | Транспорт |
|---|---|---|---|
| глобальный IPv6 | выход по IPv6 | да | **прямой IPv6 + SSH**: ключ приложения, без пароля; роутер пропускает входящие на порт 22 ПК |
| глобальный IPv6 | выход по IPv6 | нет | роутер или брандмауэр Windows режет входящие по IPv6 — разрешить порт 22 для ПК и повторить |
| глобальный IPv6 | нет IPv6 | — | VPN телефона не даёт IPv6 — настройки VPN (раздельное туннелирование для DPmetaApp) или IPv4 |
| нет IPv6, CGNAT «нет признаков», UPnP или ручной проброс | — | да по IPv4 | **проброс порта IPv4 + SSH**: нестандартный внешний порт, только ключ |
| нет IPv6, CGNAT «похоже, да» | — | нет | входящего пути нет: нужен relay или свой VPN-сервер — это меняет D-88, решает автор |

Время до сна не 0 — в сне ПК снаружи недоступен: нужен «никогда» от сети
или пробуждение по сети (решается после выбора транспорта).

## Безопасность

Открытый наружу SSH — только вход по ключу SSH приложения
(`PasswordAuthentication no` в `sshd_config` ПК).
Скрипты адреса никуда, кроме двух сервисов «мой внешний адрес», не шлют.
