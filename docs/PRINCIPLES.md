# Общие инженерные принципы

**Вид всего документа — наблюдение (M-03).** Здесь собрано то, что
репозитории уже решили каждый для себя и что совпадает по сути. Это не
новые правила: правило каждого репозитория — в его `CLAUDE.md` и журнале
решений, и меняется только там. Где различие оправдано назначением
репозитория, оно так и отмечено — одинаковость ради одинаковости не цель.

Обозначения матрицы: **✓** — записанное правило; **≈** — та же мысль
своими словами или частично; **—** — нет. Сверено 5 октября 2026 по
`CLAUDE.md`, журналам решений и проверкам репозиториев.

## E-01 — Журнал решений — источник истины

Что решено и почему — в `DECISIONS.md`; при расхождении прав он, другой
документ исправляется; решение меняется только записью в журнале с
историей. Galdhold, DPlang, DP-Verify, DPlearn, SocialMediaImage — с
порядком старшинства документов в `CLAUDE.md`; DPpass и DPprofile — в
правилах журнала. DP_game_market_analytic_system — журнал ADR
(`docs/DECISIONS.md`) без правил старшинства.

## E-02 — Запрос автора сверяется с решениями до работы

Расхождение с решением — назвать и спросить; неясная важная деталь —
спросить; мелочи — решить и назвать в отчёте; решённое не
переспрашивать. Почти дословно одинаково в Galdhold, DPlang, DP-Verify,
DPprofile, DPlearn, SocialMediaImage; в DPpass — «изменение, которое
противоречит решению, начинается с нового решения» (`DPpass:CLAUDE.md`).

## E-03 — Сначала проверить, нужна ли правка; готово — остановиться

Уже есть — ничего не менять; есть похожее — дополнить; условие выполнено —
не брать следующую задачу без поручения. DPpass: «работа заодно —
строка в `TODO.md`, а не правка»; DPprofile: «следующий этап без
поручения не начинать».

## E-04 — Сбой инструмента — не сбой кода; красное до правки — не своё

Упавшая команда сперва разбирается по коду возврата и окружению;
поломка, бывшая до правки, в своей задаче не чинится, а записывается.
Дословно — в Galdhold, DPlang, DP-Verify, DPlearn; в DPpass и DPprofile —
«падающий тест не отключается и не ослабляется».

## E-05 — `TODO.md` — только незаконченное

Не журнал и не копия документации; сделанное удаляется; долг — только с
подтверждением. Метки сложности `М`/`С`/`Т`/`К` — в DPlang, DP-Verify,
DPlearn. DPprofile — пункт с меткой этапа.

## E-06 — В корне — только точки входа

`README.md`, `CLAUDE.md`, `TODO.md`, `LICENSE`; остальное — по каталогам.
DPlang проверяет это `check_root`, DP-Verify — `repo.layout`. У DPpass в
корне — модули Gradle (это код, а не документы); у
DP_game_market_analytic_system — каталоги данных `market/`, `projects/`,
`analysis/`.

## E-07 — Без GitHub Actions; проверка — командой в сессии

`Galdhold:Р12`, `DP-Verify:V-05`, `DPpass:D-23`, `DPprofile:D-08`,
`SocialMediaImage:Д3`; DPlang и DPlearn — в `CLAUDE.md`. Итог полного
прогона — в описании PR. В Galdhold `.github/workflows/build.yml` оставлен
описанием без триггеров (`Galdhold:Р12`), но значок сборки в README ещё
ведёт на Actions прежнего адреса (SQ-02).

## E-08 — Работа не теряется между сессиями

Коммит и пуш после каждого законченного куска и не реже раза в полчаса;
незаконченное — `WIP:`; PR черновиком сразу после первого пуша с
«сделано / осталось»; в начале сессии — ветки с невлитой работой.
Хук начала сессии есть у Galdhold, DPlang, DPlearn, SocialMediaImage; у
DP-Verify, DPpass, DPprofile — нет (у DPpass он запланирован поставкой
DP-Verify, `DP-Verify:docs/direction/TECHNICAL_TASK.md`, §12.2, шаг 8).
DP_game_market_analytic_system — заметка `docs/HANDOFF.md` вместо правил.

**Следствие для мета-проходов.** Хук показывает сессии ветки с невлитой
работой, и сессия продолжает их как свои. Ветка `dpmeta/<цель>` в таком
репозитории будет видна его сессиям — поэтому в коммите и в
`docs/SYNC_QUEUE.md` прямо сказано, что её вливание — отдельный шаг
(`docs/PROCESS.md`).

## E-09 — Секретов в репозитории нет — это проверяется

`check_secrets.py` в Galdhold, DPlang, DPpass; `security.secrets` в
DP-Verify и DPlearn; `tools/check.sh` в SocialMediaImage. В DPprofile и
DP_game_market_analytic_system проверки секретов нет — у DPprofile
предмет — документы о проектах, у DP_game_market_analytic_system —
синтетические данные; риск низкий, но правило не записано.

## E-10 — Тексты по-русски, идентификаторы латиницей

`DP-Verify:V-11`, `DPlearn:D-15`, остальные — в `CLAUDE.md`. Исключение —
DP_game_market_analytic_system: документы и код по-английски, заметка
`HANDOFF.md` — по-русски. Решения об этом в нём нет.

## E-11 — Чужое — только с записью происхождения

`PROVENANCE.md` (Galdhold, DPpass, SocialMediaImage), `THIRD_PARTY.md`
(DPlang), I-09 (DP-Verify — для своей поставки); чужие ассеты, тексты и
код других продуктов не копируются даже при разрешающей лицензии
(`DPpass:D-20`, `Galdhold:docs/ORIGINALITY.md`). DPprofile — выжимки до
300 знаков со ссылкой (`DPprofile:D-05`).

## E-12 — Детерминизм прежде скорости

Galdhold — фиксированный такт, случайность по ключам (`Galdhold:CLAUDE.md`);
DPlang — свойство языка (`DPlang:Р12`); DP-Verify — без кэша и
параллельности (`DP-Verify:V-14`); DPpass — `Clock` и явное зерно
(`DPpass:D-21`); DPlearn — `derive` и ключ `--today`
(`DPlearn:docs/ARCHITECTURE.md`); SocialMediaImage — детерминированный
рендер изображений (`SocialMediaImage:Д11`); DP_game_market_analytic_system —
INV-01 (`DP_game_market_analytic_system:docs/ARCHITECTURE.md`).

## E-13 — `README.md` — не источник истины

Galdhold и DPlearn: README меняется только по запросу автора; Galdhold,
DPpass, DPprofile: блок состояния между метками пишет скрипт и сверяет
проверка.

## Различия

Наблюдения о том, где одинаковые по смыслу правила разошлись в деталях.
Ни одно не мешает работе; собраны, чтобы при следующем копировании
правил брать согласованный вариант — process-kit DP-Verify (этап 5),
когда он будет готов.

- **Номера решений** — четыре разных схемы (`docs/NAMING.md`, §3).
- **Поле «Проверка» у решения** — обязательно в DPpass, DPprofile,
  DPlearn, DP-Verify; в Galdhold, DPlang, SocialMediaImage его нет.
- **Команда проверок** — у каждого своя (`docs/ECOSYSTEM.md`, §1); общий
  вход `dpv run static|affected|full` — по плану DP-Verify.
- **Хук начала сессии** — у четырёх из восьми (E-08).
- **DP_game_market_analytic_system** вне общего процесса почти целиком —
  RISK-05.
