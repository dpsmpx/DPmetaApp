# Контекст проекта

Этап 3 ТЗ автоматизации, dev.50, D-197 / `DP_AI_Orcestrator:D-224`.
Роли моделей и маршрутизация этапа 4 сюда не входят.

## Настройка

Рабочий проект → «Автоматизации» → «Контекст проекта».
Настройки открываются по требованию, действуют на API-чат и подготовку
нативной задачи. Сохраняет их человек; инструмента изменения профиля у
модели нет. Перед сменой профиля работающий нативный ход нужно остановить:
общая защита записи проекта не даёт сохранить настройки поверх занятого
дерева. Профиль не меняет ручные сборки и редактор вне инструментов ИИ.

| Режим | Можно прочитать | Автоматическая выборка |
|---|---|---|
| MINIMAL | перечисленные точные файлы, применимые правила родителей | эти файлы и обязательные правила |
| SCOPED | перечисленные файлы/каталоги и потомки каталогов, правила родителей | закреплённое и кандидаты внутри области |
| PROJECT_WIDE | проект без секретных и служебных файлов | правила, закреплённое, кандидаты по задаче |
| FULL_ACCESS | та же граница проекта, контекст по запросу | весь репозиторий не отправляется автоматически |
| CUSTOM | заданные человеком корни, файлы, правила и бюджеты | закреплённое и кандидаты внутри области |

Точка в корнях — весь проект; MINIMAL/SCOPED её не допускают. Пути
относительные, уникальные, по одному на строку. Дополнительные обязательные
документы задаются отдельно. AGENTS.md/CLAUDE.md корня и родителей
выбранных файлов учитываются всегда. Отсутствие проверяется отдельно от
отказа чтения; непрочитанные обязательные правила останавливают подготовку.

FULL_ACCESS контекста **не включает** полный доступ API-чата, секреты,
другой проект, произвольную команду или права Android. Грант операций
остаётся прежним, отдельным и отзывным. Секретные/служебные пути и ссылки
фильтруются прежними FileTree/ApiProjectFiles. Настройки приватны и не
лежат в репозитории; связаны с конфигурацией проекта/target/корня и
сохраняются CAS. До первой явной настройки человека сохраняются ревизии
прежних сценариев; после настройки все адаптеры, включая gate занятой
нативной задачи, используют одну привязку политики. Порча, старая привязка и неизвестный формат не выбирают
более широкий режим. Явный сброс человеком возвращает PROJECT_WIDE.

## Что получает модель

Пакет `dpai.context-packet` v1 привязан к настоящему task/chat, проекту,
месту и ревизии профиля. API-чат не получает вымышленный TaskId. Пакет
содержит цель, критерии приёмки, ограничения, релевантные файлы, связанные
задачи и сводку прошлых проверок. Неуказанные критерии, связи, недоступные
доказательства и HEAD названы неизвестными; они не сочиняются.

Выборка использует ограниченный обзор и лексическое ранжирование путей
этапа 2. Это кандидаты, а не доказанный семантический граф. Корневые и
модульные правила обязательны; архитектурные документы можно закрепить
или запросить явно. Длинный файл входит целиком либо явно исключается
по бюджету; обязательные ограничения не обрезаются молча. Исходные логи
и артефакты остаются вне prompt: в нём сводка, ссылка и хеш.

У каждого источника есть уровень, происхождение и хеш. Репозиторий,
человеческий запрос и результат модели остаются данными, разделители
внутри текста/пути обезвреживаются; секреты в тексте редактируются.
Правила стоят перед меняющимися данными для повторного использования
устойчивого начала провайдером. Точный повтор включается один раз.
Повторный запрос контекста в том же tool-ходе получает ссылки на уже
отправленные хеши. Новый stateless-запрос снова получает нужный текст.

Бюджет включает сериализованный манифест. В API также проверяется
фактическое тело **каждого** сетевого раунда: схемы инструментов,
переписка, результаты и подписи рассуждений. Оценка токенов — UTF-8/3,
не счёт провайдера. После переполнения подписанные рассуждения или
обязательные данные не удаляются: следующий запрос получает явный отказ.
Нужен новый ход с меньшей выборкой или больший бюджет человека.
Отдельный ответ context-инструмента API ограничен 26000 символами для
общего канала: превышение возвращает отказ, не обрезанные правила.
Если меньший канал сценария/CLI не вмещает пакет, он получает явную
ссылку contextDelivery=UNAVAILABLE и хеш вместо части обязательных данных;
полный пакет доступен в выводе IDE.

## Инструменты

Все семь операций есть в общей группе «Исследование проекта», сценариях
и подписанном `dpai automation`. API даёт также прямые имена:

| API | Каталог | Источник и границы |
|---|---|---|
| get_task_context | context.task | цель, критерии, правила, кандидаты и ссылки |
| get_symbol_context | context.symbol | symbols действующей LSP, точный сохранённый SHA-256 |
| get_related_interfaces | context.interfaces | definition действующей LSP; не выдуманный граф всех интерфейсов |
| get_architecture_constraints | context.constraints | применимые обязательные правила, явно выбранные документы |
| get_change_history | context.history | настоящий ограниченный Git log, без внешних обработчиков |
| get_test_evidence | context.evidence | сохранённая история CHECK/BUILD; не свежая проверка |
| expand_context | context.expand | явные пути и причина, внутри утверждённой области |

`paths` в прямом API — массив строк; в параметрах общего каталога —
строка с JSON-массивом. Для символов обязательны path/sha256; line/column
начинаются с 1, column в UTF-16. Нет действующей службы/возможности или
файл изменён — явный отказ. Расширение не меняет корни и грант; запрет
расширения пакета не отменяет отдельное чтение разрешённого файла.

CLI сначала получает текущую ревизию через list/describe, затем вызывает
run с JSON через stdin; канал, исполнитель и подтверждения прежние:

```
dpai automation PROJECT_ID list
dpai automation PROJECT_ID describe --stdin
dpai automation PROJECT_ID run --stdin
```

В ограниченных профилях доступны только адаптеры, использующие
отфильтрованный FileTree. Команды, build/check-профили, сценарии,
Git/история общих команд и LSP, способная вернуть соседние файлы,
недоступны. Числовой READ сам по себе не доказывает изоляцию. Для
проверки можно явно прочитать разрешённый файл JUnit/SARIF/замеров;
обычный PROJECT_WIDE сохраняет прежние инструменты и отчёты из build.
Нативный CLI/proot не объявляется файловой песочницей: MINIMAL/SCOPED и
CUSTOM без точки блокируют запуск до обращения к модели и не создают
петлю повторов. В широком режиме сохраняются прежние права нативного
исполнителя; prompt их не ограничивает на уровне ОС.

## Актуальность, история и кэш

Манифест содержит SHA-256 **всех** прочитанных байтов, в том числе текста,
не вошедшего по бюджету, и проверенное отсутствие правил. До выдачи пакет
сверяется повторным чтением; HEAD, если доступен, читается до и после.
Снимок не атомарен, изменения могут произойти после проверки. Перед
записью по-прежнему обязателен актуальный SHA-256 и защита владельца дерева.

API-переписка v3 читает v1/v2. Ответы получают contextScope,
contextSources и contextCommit. Смена области, места, владельца, файла
или HEAD исключает старые ответы из следующего запроса, сохраняя их в
видимой истории. Старые ответы без проверяемого происхождения не
считаются свежими. В прежнем профиле без явной настройки сохраняется
возможность использовать старую человеческую цель. Схемы и исходная цель
не обрезаются ради промежуточной переписки: отправляются первая цель и
недавние реплики с явным числом исключённых. 0 отключает прошлые реплики.
Неполностью прослеживаемые результаты общих команд/анализаторов не
переиспользуются как доказанный свежий ответ.

Перед инструментом, очередным сетевым раундом и принятием ответа
проверяются ревизия профиля и актуальность наблюдённых входов. Уже отправленные данные нельзя отозвать с
сервера; смена профиля предотвращает последующие отправки старой сессии.
Файлы/HEAD сверяются также перед принятием ответа. Собственная успешная
файловая правка обновляет наблюдённый хеш; внешняя правка требует нового
контекста. Отмена и фазы подбор/чтение/сборка используют прежний worker.

Производный текст кэшируется в процессе: до 64 записей/1 млн символов,
раздельно по проекту, владельцу, месту, политике и полному хешу входа.
Хеш реальных байтов вычисляется перед обращением к кэшу; mtime не
доказывает свежесть. Приватное хранилище сохраняет последние пакеты
не более 20 владельцев, без повторной записи одинакового пакета. Это
снимки для сравнения, не разрешение и не основание пропустить чтение.
Отказ записи кэша отражается как cache_not_saved, не расширяет доступ.
Кэш Gradle/SDK/Alpine и скачанные компоненты этим механизмом не очищаются.

Пределы: 5000 файлов/1000 каталогов/24 уровня обзора, до 6 кандидатов
по задаче, 20 явно запрошенных путей, 256 КиБ на автоматически включаемый источник
(штатное постраничное чтение/редактор сохраняют предел 2 МиБ),
128 ссылок вместе с правилами. Больше обязательных правил — отказ с
предложением сократить выборку. Бюджеты профиля: 1000–1000000 символов,
500–250000 оценочных токенов, 0–100 прошлых реплик. Обход ограничен
60 секундами и отменой; отдельный SFTP-вызов имеет тайм-аут транспорта.

## Проверка и приёмка

Автоматически: корпус формата профиля, области/переходы/секреты,
отсутствующие и непрочитанные правила, одинаковый mtime при иных байтах,
дедупликация, Unicode и поддельные разделители, бюджеты, CAS/порча/смена
привязки, ограниченный кэш, v1/v2/v3 переписка, отзыв области/HEAD,
реальные циклы всех четырёх API-адаптеров и запрет нативного запуска.
Полный строгий прогон, UI и обе APK выполняются workflow проекта.

На устройстве остаются настройка и копирование пакета, большой проект,
реальные провайдеры/LSP, SSH, отзыв во время ответа/команды, отмена и
обновление приложения с прежней историей. Это отдельный пункт TODO;
автоматические проверки не заменяют физическую приёмку и выпуск.
