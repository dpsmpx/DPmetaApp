# Безопасность и личные данные

Решения Д2 (закрытый репозиторий, личного сверх опубликованного нет),
Д3 (проверки без Actions), Д12 (учётные данные — только у автора), Д25
(граница площадка × окружение). Правило
кратко — `CLAUDE.md`, «Секреты»; проверка — `tools/check.sh`
(`secrets`, `tools/cs/secrets.py`).

## 1. Чего в репозитории нет

- Токенов, ключей API, паролей, приватных ключей, cookies, ID сессий,
  файлов `.env` — ни в коде, ни в документах, ни в логах.
- Учётных данных площадок: в репозитории — только **имя** переменной
  окружения (`credential_ref` в `data/platforms/destinations.yaml`), значение —
  у автора; облачным сессиям ИИ рабочие токены не передаются (Д12,
  `docs/operations/CREDENTIALS.md`). Входа в аккаунты автора через браузер
  нет.
- Закрытых приглашений (Discord и др.) и закрытых данных аккаунтов.
- Адресов с подписями и параметрами сессии: подписанные ссылки CDN
  (`x-signature=`, `refresh_token=`), параметры отслеживания из ссылок
  «поделиться» (`_t`, `_r` у TikTok) — сохраняется только чистый адрес.
- Локальных путей машины автора и имён исходных файлов, раскрывающих
  личное (импорт метрик хранит только имя файла и его хэш).

Где секреты: только локально у автора, вне Git. `.gitignore` закрывает
`.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `cookies*.txt`,
`*.cookies`, `secrets/`, `local/` и локальные настройки Claude
(settings.local.json в `.claude/`).

## 2. Личные данные (Д2)

Исследование собирает сведения об авторе в одном месте — такая сводка
ценнее для злоумышленника, чем разрозненные посты. Поэтому:

- хранится только то, что автор сам опубликовал, и производные от
  этого;
- опубликованное, но личное (работа, доход, учёба, семья, место) —
  только как «есть такая публикация», без повторения деталей (ОР-8);
- имя автора — по Д20 («Борис Давыдов / dpsmpx»), на сайте — только
  `dpsmpx` (Д37); имя не открывает
  остального личного (ОР-8);
- фото автора — без метаданных; интерьер в работах затемняется (Д18);
- адреса почты в файлах — предупреждение проверки `secrets`.

## 3. Проверка `secrets`

Просматривает все отслеживаемые и новые файлы (без игнорируемых):

| Ошибка | Что ищется |
|---|---|
| файл секретов | `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa`…, `cookies*.txt` |
| ключи и токены | приватные ключи, токены GitHub, AWS, Google API, Anthropic/OpenAI, Slack, бота Telegram, Discord, JWT |
| cookies | строки формата Netscape |
| подписанный адрес | `signature=`, `refresh_token=`, `access_token=`, `sessionid=`, `_t=`, `_r=` в адресе |
| присваивание | `password = …`, `api_key: …` со значением, похожим на ключ |

Предупреждения — адреса почты и приглашения Discord.

Ограничение: проверка ищет известные формы; секрет в непривычном виде
она может пропустить. Главная защита — не копировать секреты в сессию.

## 4. Если секрет попал в Git

1. Считать секрет скомпрометированным: **автор** отзывает и
   перевыпускает его на стороне сервиса — это первое и обязательное.
2. Удалить из файлов и закоммитить; переписывание истории — только по
   решению автора (затрагивает все клоны).
3. Записать находку в `TODO.md` до подтверждения автором, что ключ
   отозван.

## 5. Логи и выгрузки

Выгрузки аналитики (Д15) и логи сессий кладутся в репозиторий только
нормализованными: без ID аккаунтов, адресов почты, токенов и
персональных данных зрителей. Сырые CSV остаются у автора.
