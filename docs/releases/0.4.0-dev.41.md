# 0.4.0-dev.41 — основной APK локальной студии

23 ноября 2026. Основной вариант APK DPmetaApp/DP_IDE теперь собирается
с `targetSdk 28` и `minSdk 30`, с прежним `applicationId=com.dpsmpx.dpai`.
Смена уровня платформенных ограничений не переименовывает приложение
и не меняет пользовательские данные или формат подписи.

## Изменения

- `./gradlew :shell:assembleRelease` и `tools/build-apk.sh release`
  теперь по умолчанию выбирают `targetSdk 28`.
- `DPAI_TARGET_SDK=36` для сборки через скрипт и
  `-Pdpmeta.targetSdk=36` для Gradle выбирают сравнимый вариант с
  современными ограничениями Android. Старое свойство
  `dpmeta.onDeviceBuild` принимается для совместимости.
- Workflow GitHub Actions сначала собирает `primary/DPmetaApp.apk`
  и проверяет пакет, `minSdk 30`, `targetSdk 28`; затем проверяет
  дополнительный `modern/DPmetaApp-modern-target.apk` с `targetSdk 36`.
  SHA-256 записаны для обоих.
- Фикстура `AppComponentsTest` использует закреплённую в программе
  версию cmdline-tools (`20.0`), чтобы не считать актуальный SDK
  устаревшим.

## Важно перед установкой

- Диагностические APK в артефактах Actions подписаны **отладочным**
  сертификатом. APK из GitHub Release, если прошёл задание `signed-release`,
  подписан ключом владельца, загруженным только через Secrets Actions.
  Проверьте SHA-256 сертификата перед установкой поверх имеющегося APK;
  не удаляйте установленную копию с данными ради смены подписи.
- `targetSdk 28` нужен самой IDE для запуска инструментов в приватном
  Linux-каталоге Android. У собираемых проектов собственный `targetSdk`.
- Такой APK не подходит для публикации в Google Play и меняет модель
  разрешений Android. Встроенный Linux и Gradle всё ещё необходимо
  проверить запуском `java`, `javac`, `aapt2` и фактической сборкой
  проекта с ресурсами на физическом телефоне. Для JNI нужен ARM64 NDK.

Подробный порядок: [BUILD_ON_DEVICE.md](../BUILD_ON_DEVICE.md).

## Исправления окружения после подготовки dev.41

- Добавлен отдельный Android/Bionic OpenJDK 21 с Termux-совместимым
  виртуальным префиксом внутри Linux DPmetaApp, без внешнего приложения Termux.
- Исправлен вызов Termux `apt-get` с реальным UID Android приложения, без
  эмуляции root PRoot, необходимой только Alpine `apk`.
- Для Android-задач Gradle в старых профилях автоматически подключаются
  `ANDROID_HOME`, `ANDROID_SDK_ROOT`, Bionic `JAVA_HOME` и инструменты ARM64.
- Контроль присутствия JDK, SDK, `aapt2`, `zipalign` дополнен тестами.

Исправления должны пройти строгую проверку в Actions. Успешный APK
**не заменяет приёмку локальной Gradle-сборки на Redmi Note 13**.
