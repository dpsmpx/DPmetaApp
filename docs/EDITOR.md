# Редактор файлов

Для C++ в полной панели службы доступен «Индекс C++…»
(DP_AI_Orcestrator:D-174). Он выключен по умолчанию и включается
отдельно для проекта с `compile_commands.json`. Разбор использует два
потока с низким приоритетом и кэш на диске; потребление RAM и батареи
на Redmi ещё предстоит измерить. Перед включением показывается
подтверждение и проверяется запас места. Это даёт службе сведения о
закрытых файлах после их разбора. В рабочем дереве проекта доступен
предпросмотр переименования между файлами (D-180). Отключение сохраняет кэш. Настройка
перезапускает службу проекта; другие его вкладки могут включить её
повторно. В режиме дзен дополнительные строки не появляются.

Первый шаг этапа 4 (D-97, DP_AI_Orcestrator:D-131): «AI» → «Файлы» →
копия папки или домашняя папка Linux → файл → нажать на код.
Работает и с текстом в подключённой папке SAF.

- «Поиск»: буквальный текст, переключатель регистра, «Назад»/«Далее»
  с переходом по кругу, замена текущего совпадения или всех совпадений.
  «Все» — один шаг отмены; замена не ищется повторно в своём результате.
- «Строка»: переход к номеру строки. Над полем виден текущий номер
  строки и столбца (позиции UTF-16).
- «Отменить»/«Повторить»: история текущего черновика. Соседний короткий
  ввод объединяется в шаг; поиск/переход и отдельные команды его разделяют.
- Нативное поле Sora (dev.30, D-102): номера строк, текущая строка,
  направляющие отступов, выделение и прокрутка, IME, pinch-to-zoom.
  «Вид / команды»: шрифт 10–32 sp, перенос строк, пробелы 2/4/8 или табуляция.
- Вкладки: до восьми файлов в корне, путь в доступном описании,
  звёздочка правок. Клик по вкладке открывает просмотр без удаления
  буфера; закрытие — в меню долгого нажатия.
- «Отступ»/«Убрать отступ», комментарий, дублирование/удаление/перемещение
  строк — один undo. Панель символов обрамляет выделение скобками/кавычками.
  Enter и парные скобки используют конфигурацию языка.
- Аппаратная клавиатура: Ctrl+S/Z/Y/F/H/G, Ctrl+/ (комментарий),
  Ctrl+D (дублировать), Ctrl+Shift+K (удалить строки), Alt+↑/↓,
  Tab/Shift+Tab, Ctrl+Tab/Shift+Tab, Ctrl+W, Ctrl+P (файлы).
- «Изменения»: просмотр заменённого диапазона относительно открытого
  снимка. Изменение только переводов строк помечается отдельно. Это
  ограниченный просмотр ручных правок, не Git patch.
- Подсветка по расширению: C/C++, Python, Kotlin, Java, JSON. Это
  локальная асинхронная TextMate-подсветка с многострочными строками и
  комментариями, включая вложенные комментарии Kotlin. Ошибок компиляции
  и семантического дополнения пока нет; словарные подсказки отключены.

## В ИИ из редактора

D-130, DP_AI_Orcestrator:D-165. «В ИИ» — над полем файла на рабочем экране
проекта («Файлы»).

- **Что уходит:** ваша просьба и блок «Контекст из редактора»: путь от
  корня репозитория, строки и выдержка выделения (без выделения — строка
  курсора; до 200 строк и 16 КиБ), замечания этих строк, символ вокруг
  (функция или класс), импорты и `#include` файла, места использования
  символа. Файл не сохранён — выдержка из черновика с пометкой: ИИ на
  target читает с диска сохранённый текст. Секреты в выдержке закрываются,
  как в журнале. «Что уйдёт» показывает блок до отправки.
- **Символ и использования** — от языковой службы файла, если она включена
  (C/C++, Python, Kotlin); без неё символ и импорты — по тексту, а
  использований нет.
- **Куда:** «В сессию задачи» — сообщением в сессию задачи, выбранной на
  странице «ИИ»; «Новой задачей» — задача с этим контекстом, файл — в её
  области; «В терминал ИИ» — вставка в открытую вкладку Claude Code, Codex
  или Gemini терминала, Enter нажимаете вы (только если программа во
  вкладке принимает вставку в скобках — иначе строки выполнились бы
  сразу). «Запомнить для проекта» делает выбор направлением проекта.
- **У предела** всех слотов исполнителя направления окно предлагает
  другой уже подключённый ИИ: «Передать задачу Codex», «Через Gemini».
  Задача, ждущая у предела, показывает «Передать …» и в своём листе.
  Автоматическая передача — переключатель «Передавать задачи у предела
  другому ИИ автоматически» в карточке «Контур»; по умолчанию выключен.

## Отладка

D-124, DP_AI_Orcestrator:D-159 — шаг 6 этапа 5: Linux приложения. ПК-target
— D-129, DP_AI_Orcestrator:D-164: программа «Запуска» отлаживается на самом
ПК (ниже, «Отладка на ПК»). Свои APK (Kotlin/Java) — «Отладка своего APK».

- **Точка останова** — касание номера строки у файла C, C++ или Python в
  Linux: номер становится красным; второе касание снимает. До 200 точек на
  файл; правка текста точки не сдвигает — они остаются на своих номерах.
- **Отладка файла** — «Отладка» в строке над полем. C и C++ собираются для
  отладки (`clang`/`clang++ -g -O0`, проверка тулчейна D-140) в
  `/tmp/dpai-debug` и идут под gdb; Python — под debugpy тем же
  интерпретатором, что запуск (окружение проекта, если оно есть).
  Сборка — только одного файла, без библиотек проекта: проект с
  несколькими файлами отлаживается со страницы «Запуск».
- **Отладка программы проекта** — рабочий экран, «Запуск», «Отладка»:
  команда — одна программа с аргументами (кавычки и `\` — можно;
  `&&`, `|`, `;`, `>`, `$`, обратные кавычки — нет, отказ словами);
  `python файл.py …` — debugpy, иначе — gdb. Программа собирается заранее
  с отладочными сведениями (`-g`).
- **Нет отладчика** — «Поставить gdb» (пакет Alpine) или «Поставить
  debugpy» (в окружение Python проекта); сами отладчики ничего не
  скачивают.
- **Отладка на ПК** — у дерева на ПК: рабочий экран, «Запуск», «Отладка».
  Отладчик запускается на самом ПК по SSH тем же входом, что команды и
  терминал; панель, точки и шаги — те же. ПК с Linux: C и C++ — gdb 14
  или новее с Python (программа собрана профилем «Сборка» с `-g`), Python
  — debugpy того интерпретатора, что в команде (`.venv/bin/python3 …` —
  отладчик из этого окружения). Windows-ПК — только Python (`py -3 …`,
  `python …`): отладчик программ MSVC протокол DAP не говорит. На ПК
  приложение ничего не ставит: нет отладчика или gdb старше 14 —
  сказано, что и какой командой поставить.
- **Остановка** — строка подсвечена жёлтым и открыта во вкладке; панель
  под полем: «Продолжить», «Шаг», «Войти», «Выйти», «Пауза»,
  «Остановить»; «Стек» (касание кадра — его переменные), «Переменные»,
  «Выражение» (выражение языка программы в выбранном кадре), «Вывод»
  программы, «Точки» — встала ли каждая (✓) и «Убрать».
- Один сеанс на приложение; новая «Отладка» останавливает прежний.

## ИИ-дополнение

D-133, DP_AI_Orcestrator:D-170 — этап 7 IDE. Опционально и выключено по

- **Источник** — «Вид / команды» → «ИИ-дополнение…» (или первое нажатие

  отметкой «Разрешаю отправлять код проекта … на <адрес>»; если адрес
  профиля потом сменился, отметку нужно поставить заново.
- **Запрос** — только по кнопке, без фоновых запросов. Уходит окно
  открытого файла вокруг курсора (до 6000 знаков до и 2000 после, по
  целым строкам), ключи и токены вырезаются. В строке под панелью —
  сколько знаков ушло, затем токены входа и ответа; «Отменить запрос»
  прерывает ответ.
- **Ответ** — полоса под панелью: «Вставить» вставляет в место курсора
  (если текст за это время не менялся), «Отклонить» — убирает. Повтор
  начала строки и закрывающих скобок, которые уже стоят после курсора,
  убирается; не длиннее 40 строк.
- В журнале — профиль, адрес и числа, без кода.

## Отладка своего APK

D-126, DP_AI_Orcestrator:D-161 — шаг 8 этапа 5. Своё Android-приложение
отлаживается на этом же телефоне: adb из «Logcat» перезапускает его с
ожиданием отладчика, DPmetaApp подключается к нему по JDWP.

- **Что нужно:** adb подключён («Logcat» → «Подключить»); приложение
  установлено и собрано отлаживаемым — сборка `debug` (у `release` adb
  откажет словами). Сам DPmetaApp отлаживать нельзя.
- **Начать** — «Сборка» → «Артефакты» → «Отладка» у установленного APK.
  Приложение останавливается, запускается заново и ждёт отладчика («Waiting
  for debugger» на экране — так и должно быть); DPmetaApp ставит точки и
  отпускает его. Дальше «Отладка» над файлом `.kt`/`.java` того же дерева
  начинает отладку того же APK снова.
- **Точки** — касанием номера строки в файлах `.kt` и `.java`, до или во
  время отладки. Класс файла ищется по пакету (строка `package`) и имени
  файла; ещё не загруженный класс — точка без ✓, встанет при загрузке.
- **На остановке** — строка подсвечена, внизу — стек (касание кадра — его
  переменные), переменные кадра и `this`: числа и строки — значениями,
  массивы — длиной, объекты — классом. «Шаг», «Войти», «Выйти» идут по
  строкам и пропускают системный код (`java`, `kotlin`, `android`,
  `androidx`…), «Пауза» останавливает приложение целиком.
- **Исключение**, брошенное кодом приложения и им не пойманное, —
  остановка с типом и текстом; пойманное своим кодом — мимо.
- **Выражение** — только имя переменной кадра: JDWP не вычисляет код.
- **«Остановить»** отключает отладчик: точки снимаются, приложение
  работает дальше. Вывод приложения — в «Logcat».

## Семантика C и C++

Первый шаг этапа 3 (D-105, DP_AI_Orcestrator:D-137). Работает для файлов
в Linux приложения: домашняя папка, копии папок, рабочее дерево проекта.

  написано под строкой службы. CMake пишет файл с

- Замечания подчёркнуты в тексте; число ошибок и предупреждений — кнопка
  со списком, касание строки списка ведёт к месту.

  строке; вне папки (системные заголовки) — путь и строка.

  видит этот файл и разобранные им заголовки, а не все файлы проекта —
  об этом написано над списком.
- «Переименовать» — новое имя (идентификатор: латиница, цифры, `_`) для
  символа под курсором. Только символ, объявленный и определённый в этом
  исходном файле, и не в заголовке: иначе служба без индекса не видит

  файл объявления. Это ограничение отдельного файла: в рабочем дереве

- В списке замечаний у строки — «Исправить»: варианты службы с готовой
  правкой текста, предпочтительный — со звёздочкой. Варианты-команды
  службы пока не применяются, их число показано.
- В отдельном файле правки службы (формат, переименование, исправление)
  идут одним шагом отмены; правка других файлов отклоняется целиком.

«Сохранить» оставляет поле и undo-историю открытыми, обновляя исходный
снимок; последующая отмена снова помечает файл изменённым.
Сохранение перечитывает исходные байты. Если файл уже изменён или не
читается, запись отменяется, черновик остаётся. Сравнение оптимистическое:
внешний процесс не блокируется между проверкой и записью. UTF-8 BOM
сохраняется; исходные переводы строк не преобразуются автоматически.
Нулевые символы, некорректный Unicode и результат больше 2 МиБ не пишутся.

С dev.29 (D-101, DP_AI_Orcestrator:D-135) текст, выделение и исходные
байты черновика восстанавливаются после перезапуска. Копии шифруются
отдельным ключом Android Keystore и хранятся в приватном noBackupFilesDir:
вне GitHub-копии, файлового менеджера и резервной копии ОС. Исходные
файлы меняются только по «Сохранить». Полная прежняя undo-история пока
остаётся в памяти; после перезапуска доступен восстановленный снимок.

Изменения объединяются с интервалом 500 мс, уход с экрана/в фон просит
немедленно записать копию. Индикатор показывает ожидание, записанную
копию или ошибку. При аварии до завершения записи последние изменения
могут не восстановиться. Пустой текст тоже сохраняется.

«Черновики» показывает восстановленные записи даже после удаления
исходного дерева, с просмотром и копированием. Восстановление само не
пишет в файл и не переносит текст в другое дерево. При внешней правке
сохранение по-прежнему отказывает. Сбой записи не выдаётся за успешную
фиксацию; сбой удаления оставляет черновик. Повреждённые/нерасшифрованные
копии не удаляются автоматически; их можно явно удалить с подтверждением
в списке черновиков, не затрагивая читаемые записи и исходники.
Уход из файла с правками предлагает сохранить, отказаться или остаться.

Пределы: восемь открытых буферов без вытеснения; сохранение не закрывает
буфер — при достижении предела закройте вкладку; история — до 40 шагов
и примерно 8 МиБ UTF-16 текста истории на файл. Поиск показывает до
10 тыс. совпадений; если их больше, «Все» отказывает целиком, не меняя
часть файла. Поле принимает до 2 млн позиций UTF-16; для записи остаётся
предел 2 МиБ UTF-8. Подсветка выполняется движком по строкам. Просмотр
правок — до 400 строк, длинные строки сокращаются. Полный текст остаётся
в редакторе.

Полная IDE развивается постепенно по `docs/MOBILE_IDE.md`: поле
редактора, анализ C++/Kotlin/JVM/Android/Compose/KMP, семантическое
дополнение, предпросмотр и конструктор. ИИ-дополнение опционально и
выключено по умолчанию. Полный этап 4 не завершён.

Состояние вида, вкладки и позиции прокрутки сохраняются отдельно от
текста в состоянии Android. Восстановление текста после остановки
процесса использует зашифрованные черновики dev.29; вся undo-история
остаётся в памяти. Копирование помечено sensitive, код не становится
меткой буфера обмена. Лицензии движка доступны через «Вид / команды».

## Полный интерфейс и дзен — dev.32

D-106 / DP_AI_Orcestrator:D-138. В строке вкладок справа четыре действия:
выход, сохранение, полный/дзен и ▶ запуск. Вкладки стоят вплотную;
долгое нажатие открывает полный путь, закрытие вкладки, переход к файлам
и настройку команды запуска. Отдельного крестика нет.

Одиночный клик по коду включает редактирование; по вкладке — просмотр.
Режим просмотра показывает и несохранённый буфер. Выход и системный Back
предлагают «Сохранить» / «Отменить изменения», если есть правки; закрытие
диалога оставляет работу открытой. Сохранённый файл выходит без вопроса.
Выход возвращает дерево и сохраняет список вкладок; закрытие вкладки
удаляет её из этого списка. Все записи исходников сохраняют прежние
проверки байтов/владельца. Если во время Save пришёл новый ввод, он
остаётся несохранённым и окно не закрывается.

Дзен скрывает системные/верхние/нижние панели приложения, сведения
о файле/черновике, подсказку остановленного контроллера, поиск/инструменты
и строку службы C++; остаётся одна строка вкладок/действий и код.
Выход из дзена/файла восстанавливает панели. Служба clangd и её замечания
продолжают работать; скрытие инструментов не выключает службу.

В полном виде «Вид / команды» содержит независимые переключатели
«Подсветка просмотра» и «Подсветка редактора». Выключается только тема
текста: отступы, скобки и семантика остаются. По умолчанию оба включены.
Режим дзен, флаги, пути/активная вкладка, последняя папка или рабочий
проект/задача и команда запуска сохраняются в приватном noBackupFilesDir.
Там нет текстов файлов: их восстановление по-прежнему делает шифрованное
хранилище черновиков. Ошибка метаданных не перезаписывает старую копию.

▶ (или F5) открывает **новую настоящую PTY-вкладку** Linux-терминала:
программа получает stdin, вывод виден там, после завершения показан код
выхода и остаётся оболочка. Команда не отправляется в чужой открытый PTY.
Для Python/.kts/.sh есть начальная команда; для C++/Kotlin-проекта
команда задаётся явно, без угадывания флагов. В команде переменная
DPAI_FILE содержит путь текущего файла; рабочая папка показана в настройке.
Команду можно изменить в меню долгого нажатия на активную вкладку.

Запуск требует Linux-пути и установленной Linux-среды; инструменты
должны быть установлены в ней. Перед запуском нужно сохранить/отменить
правки дерева; свежие права/owner и исходные байты проверяются повторно.
После восстановления Activity команда автоматически не повторяется.
Это ручной терминал; существующие CHECK/BUILD остаются профилями со своей
долговечной паузой контура и подтверждением завершения.

Приёмка новых касаний, Back/IME, восстановления вкладок и системных

## Переименование в проекте и зависимости

В рабочем экране проекта откройте «Файлы», выберите код и команду
«Переименовать» в панели языковой службы. До сохранения показываются все
затронутые файлы и изменения. Сначала сохраните или отмените черновики;
контур должен быть свободен. Версии и исходный текст сверяются повторно.
При прерывании доступно восстановление; последнюю запись можно отменить
со страницы файлов. Отдельный файл вне рабочего дерева не получает прав
на запись соседних файлов. Для C++ сначала включается индекс проекта.

В том же рабочем экране есть «Зависимости проекта» (D-181).
Выберите Gradle, Python/pip либо Conan 2 и Python на target. «Анализировать»
сохраняет граф/версии в .dp-ide/dependencies; отчёты открываются как файлы.
«Закрепить версии» показывает, какие файлы будут изменены:

- Gradle: gradle.lockfile в проектах, ./gradle/dp-ide-locking.gradle
  и его подключение из корневого build.gradle(.kts). Обычные сборки затем
  используют locking. Плагины и included builds закрепляются отдельно.
- Python: выберите Python venv проекта (например .venv/bin/python).
  pip inspect/check проверяет окружение; requirements.dp-ide.lock —
  снимок всех его версий для текущей платформы, без хешей архивов.
  Direct/VCS/editable-пакеты требуют ручного закрепления. «Установить по
  lock-файлу» работает только в venv; исходные manifests не заменяются.
- Conan 2: нужен установленный Conan 2 и conanfile проекта. Graph info
  показывает граф, lock create записывает стандартный conan.lock с
  ревизиями рецептов. Это не сборка недостающих бинарных пакетов.

У Android-проекта в Linux приложения отметьте подключение SDK приложения.
Операция держит общую паузу, вывод и историю; после pin/restore прежний
языковой индекс останавливается, служба запускается заново её кнопкой.
При возврате в «Файлы» чистые вкладки перечитываются, черновики не теряются.
При отказе Gradle часть native lock-файлов могла измениться — проверьте
Git diff; полный успех не объявляется. Анализ не является проверкой задачи.

Исправление, затрагивающее только текущий документ, меняет черновик одним
шагом отмены и не требует предварительного сохранения. Общий предпросмотр
и сверка чистого дерева нужны для правки соседних файлов. Дополнение
Kotlin с импортом (DP_AI_Orcestrator:D-211) также меняет только буфер;
файл не записывается командой языковой службы.

Перед проектным переименованием C++ IDE читает сохранённую настройку
индекса и ждёт подтверждённого завершения очереди clangd. Если очередь
возобновилась во время подготовки или предпросмотра, запрос надо повторить

файлы вне неё не объявляются проиндексированными. По умолчанию индекс
остаётся выключенным до приёмки и замеров на устройстве.

только явной командой удаления компонента.
