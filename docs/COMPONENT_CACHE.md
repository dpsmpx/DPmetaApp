# Сохранение скачанных компонентов

Linux, терминал, IDE, ИИ и пульт используют постоянные каталоги вне
рабочего дерева (D-193). Повторная сборка и переключение PR их не очищают.
Смена версии, отсутствие компонента или повреждение требуют загрузки;
проверка обновлений метаданных сама по себе не означает повторное скачивание.

## Каталоги и совместимость

- `GRADLE_USER_HOME` по умолчанию — `/root/.gradle`. Если уже существует
  `wrapper/dists` или `caches` прежнего Bionic home
  `/data/data/com.termux/files/home/.gradle`, используется этот каталог:
  скачанный на телефоне Gradle не переносится во время работы daemon.
- `XDG_CACHE_HOME` — `/root/.cache`, pip — его подкаталог `pip`, npm —
  `/root/.npm`. Явные переменные пользователя имеют приоритет, включая
  собственные `GRADLE_USER_HOME`, `PIP_CACHE_DIR` и `NPM_CONFIG_CACHE`.
- Архивы установщиков — `$XDG_CACHE_HOME/dpai/downloads`, либо явно
  заданный `DPAI_DOWNLOAD_CACHE`. Имя определяется алгоритмом и ожидаемой
  суммой. Это данные rootfs в хранилище приложения, не Android `cacheDir`.
- Alpine сохраняет пакеты в своём включённом кэше; снятие снимка больше
  не удаляет скачанные пакеты. Ручная очистка и отключение кэша остаются.
  Termux/Bionic APT сохраняет `.deb` в `/root/.cache/dpai/apt/archives`;
  настройка приложения не заменяет уже существующий пользовательский файл.

Установщики SDK, ARM64-инструментов, JDK, Kotlin и языковых служб сначала
проверяют установленную версию. Готовые ARM64 aapt2/zipalign/aidl/aapt/
split-select проверяются закреплёнными суммами, поэтому переход со старого
APK не требует скачивания их архива. При восстановлении используется
сохранённый архив. Проверка SHA-256 Gradle Wrapper, подписей APT/apk и
лицензий SDK сохраняется. Репозитории пакетов могут обращаться в сеть для
свежих индексов и зависимостей, которых ещё нет локально.

## Целостность и обрыв

Перед каждым использованием архива сверяется закреплённая сумма. SHA-1
остаётся только для платформы SDK из официального манифеста Google, как
прежде. HTTPS и проверка суммы не отключаются. Загрузка идёт в `.part`,
после успешной проверки архив переименовывается. Ошибка распаковки или
копирования назначения не удаляет проверенный архив.

Одновременные загрузки одной суммы согласуются через `flock` из Alpine.
После аварии процесса замок освобождает ядро; незавершённые файлы убирает
следующий владелец замка. Завершённые архивы автоматически не вытесняются.
Очистку каталогов загрузок нужно выполнять явно, когда установки завершены.
Переустановка Linux или удаление данных приложения удаляет и эти данные.

## Копии с ПК

Копия SFTP принадлежит target, корню проекта, полному относительному пути,
размеру и времени изменения источника. Одинаковые `shell-release.apk`
разных проектов не смешиваются. При совпадении метаданных и локального
размера байты повторно не переносятся. До и после нового переноса сверяются
метаданные и фактический размер; только полный файл переименовывается.
Неизвестное время изменения не даёт использовать старую копию.

Старые плоские копии сохраняются, но автоматически не сопоставляются с
другим проектом без сведений об источнике. Лимит автоматического удаления
трёх завершённых файлов снят. Подписанные копии хранятся отдельно и не
удаляются загрузчиком. Метаданные SFTP не являются криптографической
проверкой APK; перед установкой сохраняются отдельные проверки APK/подписи.

## Прогресс и сообщения

Установка показывает загрузку, проверку, распаковку, готовый кэш и ожидание
другой установки. Проценты curl/Gradle поступают до конца процесса; APK
показывает известный счётчик пакетов, SFTP — байты, профиль — выполненные
шаги, пульт — завершённые источники. Без известного общего объёма индикатор
неопределённый. Это факты процесса, не оценка оставшегося времени.

`NO-SOURCE`, `UP-TO-DATE`, `FROM-CACHE`, `SKIPPED` — нормальные статусы Gradle.
Наличие warning само по себе не означает провал: итог определяется кодом
возврата и проверками артефакта. Исходный вывод остаётся копируемым.
Предупреждения совместимости и оставшиеся ограничения —
[описание dev.46](releases/0.4.0-dev.46.md).
