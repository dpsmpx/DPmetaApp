## 2. Находки

### A-1 — HIGH: токен канала `dpai` доступен сессии Claude, а через канал — решающие действия (T10, T6, D-23)

Токен лежит в `~/.config/dpai/control.json` того же пользователя, под
которым идёт Claude (Termux, proot-distro — те же пути; ПК — при туннеле
D-47, п. 4). Сессия под prompt injection (T3, T4) читает токен и через
`127.0.0.1:47777` одобряет слияние своей ветки (`TASK_MERGE`, вариант
`ACCEPT` — без `confirmed`), записывает исключение (`task.waive` с
`confirmed: true`), пишет в чужие сессии. **Автор:** решающее, пришедшее
из `dpai`, подтверждается на телефоне — D-91.

### A-2 — HIGH: `dpai` отдаёт токен любому, кто слушает порт 47777

Порт фиксирован; пока служба контроллера не поднята (после перезагрузки,
«Остановить»), его может занять любое приложение с `INTERNET`, а `dpai`
шлёт ему `Authorization: Bearer <токен>`. Утверждение D-47 «до контура —
нет» не выполняется. **Автор:** токен в сеть не передавать — подпись
запроса и доказательство сервера, D-92.

### A-3 — MEDIUM: запись `resolv.conf` гостя следует символьной ссылке

`LinuxEnvironment.writeDns` пишет `rootfs/etc/resolv.conf` через
`FileChannel.open(CREATE, TRUNCATE_EXISTING)`, а это следует ссылке; proot
хранит цель ссылки гостя как есть. Код в госте (Claude, пакет npm) делает
`ln -sf ../../../control-token /etc/resolv.conf` — и приложение при каждом
открытии терминала и `apk` затирает свой файл строками `nameserver`.
Исправление: ссылку на месте файла — удалить, писать без следования
ссылкам, каталог `etc` гостя — не ссылка.

### A-4 — MEDIUM: гость видит весь `/dev` и `/sys` телефона под личностью приложения

proot — не песочница: гость D-75 работает под UID приложения, а `-b /dev`
даёт ему `/dev/binder` и остальное. В модели угроз такой угрозы нет.
**Автор:** сузить `/dev`, убрать `/sys` — D-93, угроза T13.

### A-5 — MEDIUM: восстановление настроек доверяет ключам хостов из копии

Копия (D-51) несёт `knownHosts` и targets; восстановление из «Загрузок» или
из `~/.dpai/app-settings.json` Termux (D-54) заменяет known_hosts целиком.
Копию в «Загрузках» может подложить любое приложение, в Termux — Claude.
**Автор:** оставить один шаг, как сейчас; риск — в модели угроз (T14).

## 3. Проверено и в порядке

- JNI (`dpai_native.c`): каналы и master — `O_CLOEXEC`; у потомка закрыты
  дескрипторы от 3; между `fork` и `exec` — только безопасные вызовы;
  маска и обработчики сигналов сброшены, `setsid`, управляющий терминал.
- Запуск proot: argv списком, без оболочки; окружение — гостя и `PROOT_*`;
  `apk` — имена по шаблону, не с `-`; DNS — только IP-литералы, не больше
  трёх, перевод строки не внедрить.
- Корневая система: SHA-256 закреплён при сборке, архив подписан вместе с
  APK; `..` и абсолютные пути отвергаются; setuid и setgid срезаются.
- Канал `dpai`: Host и Origin (A-21 отчёта удобства); сравнение токена за
  постоянное время; код — 6 цифр, 2 минуты, 5 попыток; пределы тела и
  заголовков; токен и код в журнал не пишутся; `Secret.reveal()` не
  вызывается.
- Манифест: наружу — только `MainActivity`; extras — через
  неэкспортируемый `InternalEntry`; `PendingIntent` неизменяемые, кроме
  `RemoteInput` с явным компонентом; схемы `dpai://` во внешних фильтрах
  нет.
- SSH и Git: `StrictHostKeyChecking=yes`, вход только ключом; `RemoteShell`
  кавычит для POSIX, для Windows отвергает `" % ^ !`; у Git — защитные
  `-c`, имена веток проверяются; PowerShell — через `-EncodedCommand`.
- Терминал: ответы программе не повторяют её текст; OSC 52 на чтение не
  отвечает; запись в буфер — через диалог с `FLAG_SECURE`.
