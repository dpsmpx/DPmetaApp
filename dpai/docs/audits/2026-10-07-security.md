## 2. Находки

### A-1 — MEDIUM, исправлено: ключ источника мог закрыть блок данных (T3)

`PromptRenderer` обезвреживал маркер блока в содержимом, но не в ключе
источника, а ключ приходит из данных (имя документа в манифесте
экосистемы). Ключ с `<<<DPAI-END>>>` закрыл бы блок, и следующий текст
читался бы как указание. Исправление: ключ обезвреживается так же, как
содержимое. Тест: `ContextTest`, `sourceKeyAndSecretsInDataAreNeutralized`.

### A-2 — HIGH, исправлено: настройки репозитория исполняли код при командах Git (T4)

Команды оркестратора (`git status`, `merge`) в дереве с враждебным
`.git/config` исполнили бы программу `core.fsmonitor`, а слияние — хуки
репозитория (`post-merge`, `post-checkout`); `--no-verify` закрывал только
хуки коммита. Исправление: каждая команда `GitCommands` идёт с
`-c core.fsmonitor=false -c core.hooksPath=.dpai-no-hooks`. Тест на
настоящем `git`: `GitServiceTest`, `repositoryHooksAndFsmonitorDoNotRun`.

Дополнение 8 октября 2026 (ревью перед проверкой на устройстве):
относительный `core.hooksPath` Git считает от корня рабочего дерева —
хук, закоммиченный в ветку в каталог `.dpai-no-hooks/`, исполнялся при
слиянии. Каталог хуков — `/dev/null`, вне любого дерева. Тест:
`hooksCommittedInTheTreeDoNotRun`.

### A-3 — MEDIUM, исправлено: секрет в документе уходил провайдеру (T1, T8)

Prompt строился без `Redactor`: ключ, случайно лежащий в документе уровня
`INTERNAL`, ушёл бы в Claude и в документ входа хода на target.
Исправление: данные prompt проходят `Redactor.STANDARD`. Тест:
`ContextTest`, `sourceKeyAndSecretsInDataAreNeutralized`.

### A-4 — MEDIUM, исправлено: каталог агента читали другие пользователи target (T8)

Каталог агента (`runs/…`: prompt, вывод Claude, журнал) создавался с
правами по умолчанию: на общем Linux-хосте при umask 022 — читаемый всеми.
Исправление: `AgentRuntime.restrictHome` — права `rwx------` на POSIX.
Тест: `AgentRuntimeTest`, `agentHomeIsOwnerOnly` (на POSIX; на Windows
каталог в профиле пользователя, тест пропускается).

### A-5 — LOW, исправлено: вход хода хранился на target бессрочно

Документ `input` запуска (prompt хода, уже отредактированный) остаётся в
каталоге агента после хода. Риск — только для владельца target
(`docs/SECURITY_MODEL.md`, §5), но срок хранения не задан. Предложение:
удалять вход после выхода хода; журнал запуска — по политике хранения.

Исправлено (7 октября 2026): агент удаляет вход сразу, как только отдал
его процессу (`DocumentStore.delete`; `AgentRuntimeTest`,
`turnInputIsDeliveredThenDeleted`). Журналы запусков: агент при каждом
`start` удаляет завершённые запуски старше 7 дней (`AgentRuntime.prune`;
`oldFinishedRunsArePrunedRunningAreKept`); идущие и потерянные не
трогаются.

### A-6 — LOW, исправлено: `Redactor` — эвристика

Ключ без цифр или путь из коротких сегментов не редактируется (известный
долг, `TODO.md`). Для уведомлений и отчётов, которыми делятся, — уровень
STRICT (этапы 12, 19).

Исправлено (7 октября 2026): `Redactor.STRICT` — длинная последовательность
от 24 знаков без требования цифры, путь с длинным сегментом; id
оркестратора, UUID и хеши не трогаются. Всё, что принимает
`NotificationEngine`, проходит STRICT (`RedactorTest`,
`NotificationEngineTest`). Обычный уровень для журнала остаётся прежним:
лишняя порча текста сессий хуже, чем для уведомлений.

### A-7 — INFO, выполнено: требования к модулю `android` (этап 11)

- Ссылки `dpai://approve|deny/…` принимаются только из `PendingIntent`
  своего уведомления: приёмник не экспортируется, иначе одобрение может
  прислать чужое приложение (T10). Хеш предложения в ссылке не даёт права
  сам по себе.
- Ключи SSH к targets — в Android Keystore (T1); в базе — ссылка.

Выполнено (7 октября 2026): `ApprovalReceiver` с `exported="false"`,
кнопки — `PendingIntent` своего уведомления (D-36); ключ входа — ECDSA
P-256 в Android Keystore, закрытая часть не покидает устройство (D-35).
