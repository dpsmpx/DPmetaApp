# Экосистема и глобальный режим

Как оркестратор видит экосистему проектов и работает по ней (ТЗ, §5.3,
§43–§46, §148; этапы 15, 16). Экосистема необязательна: без неё
оркестратор работает как обычно.

## 1. Источник экосистемы

`ecosystem.EcosystemProvider`: проекты, их состояние, документы для
контекста и предложения задач. Реализации:

- `EcosystemProvider.None` — экосистема не подключена (`ECOSYSTEM_DISABLED`,
  не ошибка);
- `ManifestEcosystem` — манифест `dpai.ecosystem` v1 (§2).

Код DPmeta сюда не переносится (D-16): DPmeta выгружает манифест, адаптер
читает только его. Недоступный или испорченный манифест —
`ECOSYSTEM_UNAVAILABLE`; задачи, созданные вручную, идут дальше.

## 2. Манифест `dpai.ecosystem` v1

```json
{"format": "dpai.ecosystem", "version": 1, "projects": [
  {"key": "dplang", "name": "DPlang", "repository": "/src/dplang",
   "state": {"branch": "main", "verification": "red"},
   "documents": ["CONTRACT.md"],
   "suggestions": [{"key": "fix-contract", "title": "…", "objective": "…",
                    "priority": "HIGH", "operation": "fix"}]}]}
```

Чтение строгое (D-09): неизвестное поле, версия новее, повтор ключа
проекта — отказ. `state` — свободные пары строк: какие поля, решает
источник. `priority` — уровень `Priority`; `operation` — вид работы, по
нему прогон решает, разрешена ли она.

## 3. GitHub

`connectors.GitHubCommands` — команды официального клиента `gh`: создать
PR, узнать состояние PR, разобрать ссылку. Вход — у `gh` пользователя,
токенов оркестратор не хранит (D-14). Исполнение — процессом в дереве
задачи (`execution`). В V1 — PR и состояние, не замена GitHub
(`docs/direction/V1_SCOPE.md`, §3).

DP-Verify — шаг профиля проверки проекта со своей командой
(`docs/SCHEDULER.md`, §8; D-16), отдельного адаптера не нужно.

## 4. Глобальный прогон

`orchestrator.ecosystem.EcosystemRun` (ТЗ, §45, §46): осмотр → выбор
следующей допустимой задачи → создание задачи в контуре проекта →
исполнение → проверка → запись итога → следующая.

Ограничители `RunPolicy`:

| Ограничитель | Что делает |
|---|---|
| `allowedProjects` | предложения других проектов пропускаются (`OPERATION_NOT_ALLOWED`) |
| `allowedOperations` | неразрешённый вид работы пропускается |
| `confirm` | задача из предложения создаётся только с подтверждения (V1) |
| `maxConcurrency` | не больше задач прогона одновременно |
| `maxTasks` | не больше задач за прогон (`RUN_BUDGET_EXHAUSTED`) |
| `maxTicks` | бюджет тактов (ресурсов) прогона |

Повторы и одобрения — политика задач и контура (`docs/SCHEDULER.md`, §5;
слияние — с одобрения). Порядок выбора: приоритет, затем проект и ключ
(D-22). Контекст задачи — документы проекта как данные с пометкой
происхождения и состояние экосистемы (`EcosystemSources`).

Итог — документ `dpai.ecosystem-results` v1: проект, предложение, задача,
состояние, вердикт и хеш отчёта проверки.

Проверка: `EcosystemTest`, `GitHubCommandsTest`.
