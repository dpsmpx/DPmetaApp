calc.py

Модуль без зависимостей, в нём четыре функции с двумя аргументами:

def add(a, b):
    return a + b

def sub(a, b):
    return a - b

def mul(a, b):
    return a * b

def div(a, b):
    if b == 0:
        raise ValueError("division by zero")
    return a / b

Как это работает:

• add, sub и mul просто применяют операторы +, -, *. Типы не проверяются, поэтому функции принимают всё, что поддерживает эти операторы: int, float, Decimal, Fraction.
• div сначала проверяет делитель. Если b == 0, она выбрасывает ValueError до того, как дойдёт до деления. Без этой проверки Python выбросил бы своё исключение ZeroDivisionError, а по условию задачи нужен именно ValueError. Проверка b == 0 срабатывает и для 0, и для 0.0.
• div использует оператор /, то есть обычное деление: результат всегда float, даже для целых чисел (div(6, 3) → 2.0).

Примеры:

>>> from calc import add, sub, mul, div
>>> add(2, 3)
5
>>> div(1, 0)
Traceback (most recent call last):
  ...
ValueError: division by zero

test_calc.py

Все тесты собраны в одном классе TestCalc(unittest.TestCase). Каждый метод с именем на test_ — отдельный тест, unittest находит их сам.

Тест     │ Что проверяет                   │ Как
─────────┼─────────────────────────────────┼───────────────────────────────
test_add │ add(2, 3) == 5, add(-1, 1) == 0 │ assertEqual
test_div │ div(6, 3) == 2, div(1, 3) ≈ 1/3 │ assertEqual, assertAlmostEqual

Некоторые детали:

• assertEqual(div(6, 3), 2) проходит, хотя функция возвращает 2.0: в Python 2.0 == 2 даёт True.
• Тест на исключение написан так:
  with self.assertRaises(ValueError):
      div(1, 0)
  Тест падает, если внутри блока with исключения не было или было исключение другого типа, например ZeroDivisionError. Поэтому тест ловит и случай, когда проверку b == 0 убрали.
• Блок if __name__ == "__main__": unittest.main() позволяет запустить файл напрямую.

Как запускать

python -m unittest -v              # найдёт test_*.py в текущем каталоге
python -m unittest test_calc -v    # только этот модуль

Если тест не проходит, вместо ok будет FAIL, а ниже — ожидаемое и фактическое значение, например AssertionError: 4 != 5.

Чего тесты не проверяют

• Деление на 0.0. Оно работает так же, как на 0, но отдельного теста нет.
• Аргументы не-числа. Например, add("a", "b") вернёт "ab": строки складываются, а типы функции не проверяют.
